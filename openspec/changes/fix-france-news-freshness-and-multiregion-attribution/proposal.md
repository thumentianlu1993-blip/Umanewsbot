## Why

法国新闻低产出并非单一来源缺稿，而是 TDN 关键词入口按相关度返回历史结果、France Galop 未保存可信发布时间、瞬时翻译失败没有自动恢复，以及全球来源法国稿仍按单一来源地区归入美国等问题叠加。现有多地区归属代码虽已部署但生产关闭，真实 dry-run 曾出现法国稿改归英国、日本稿改归中国香港和单篇扩散到三四个地区，因此必须先提高归属准确度并建立可量化验收门槛，再将法国采集与多地区展示一起灰度上线。

## What Changes

- 将 TDN 法国关键词入口改为按真实发布时间倒序且带时间下界的 posts 查询，保留 3 天新鲜度硬门禁，避免相关度搜索固定返回历史稿并漏掉最新文章。
- 为 France Galop 英文文章解析详情页官方发布时间，记录时间证据和可信度；禁止列表 fallback 时间在重复抓取时覆盖可信发布时间，并提供受控修复近期错误时间的工具。
- 对翻译供应商 `429 / 502 / 503 / 504 / timeout` 增加有限次数、指数退避和抖动的自动重试；永久错误、达到上限和仍失败文章必须有明确原因、告警与后台快速重试入口。
- 改进多地区归属证据模型和决策规则：区分赛事发生地、马匹/骑师/练马师/马主所属地、育马/拍卖/马场/机构上下文与普通地名提及；来源默认地区只在无可信内容证据时 fallback。
- 同一新闻涉及多个地区时只保留一条文章记录，选择可解释的主地区并保存全部可信相关地区；全球来源的法国赛事、法国从业者、法国育马与拍卖新闻可进入法国池，同时保留实际赛事或其他对象地区。
- 增加归属置信度、正反证据、冲突原因和 `needs_review` 状态；低置信度或多组冲突证据不得自动改变主地区，也不得无上限扩散到多个地区。
- 将归属运行方式统一为 `off|shadow|enforce`：shadow 只保存审计结果，enforce 才写主地区/相关地区；旧布尔开关仅作兼容映射。
- 建立五地区真实样本基准集、反例集和 dry-run 差异报告，以主地区准确率、相关地区精确率/召回率、过度扩散率和来源 fallback 率作为上线门槛；样本与阈值未达标时归属模式保持 `off`，相关地区查询开关保持关闭。
- 提供小批回填、来源日期修复、翻译重试和多地区归属灰度启用流程；所有 commit 均须绑定 dry-run manifest，人工锁定归属不可被覆盖，回填不得直接重复发布或重复 QQ 推送。
- 扩充地区生产与窗口观测，明确区分来源无新稿、搜索漏稿、旧文过滤、时间不可信、翻译重试中/耗尽、归属待复核、门禁阻断和已由相关地区可见等原因。
- 预期在当前英语来源边界内，使法国常态生产从偶发 0 篇提升到日常约 3–6 篇、重要赛事日前后约 6–10 篇；该估算必须在上线后以来源候选、去重、门禁和实际发布四层数据复核。

## Capabilities

### New Capabilities

- `translation-failure-recovery`: 定义瞬时翻译失败的自动退避重试、重试上限、终态告警、人工快速重试和幂等约束。

### Modified Capabilities

- `crawl-freshness-and-source-health`: 增加按日期获取最新稿、发布时间证据可信度、fallback 时间不可覆盖和历史错误时间受控修复要求。
- `international-racing-coverage`: 扩充法国英文来源的最新稿发现方式，并要求全球英文来源按内容实体产生法国及其他相关地区归属。
- `multiregion-news-attribution`: 增加证据分层、置信度与冲突处理、过度扩散保护、真实基准集和生产启用质量门槛。
- `multiregion-news-production`: 要求法国来源、翻译恢复和相关地区候选共同进入现有固定窗口，同时保持单文章、主地区配额和 QQ 去重语义。
- `production-window-observability`: 增加法国来源漏稿、时间可信度、翻译重试和归属待复核等窗口级原因与快速处理入口。

## Impact

- 主要影响 `server/stable/adapters/international.py`、`services/ingestion.py`、`services/news_attribution.py`、`services/multiregion.py`、`services/production_windows.py`、`tasks.py`、运营后台视图与相关测试。
- 需要新增 backward-compatible Django 迁移，为发布时间可信度、翻译到期重试、归属状态/置信度和持久归属运行账本提供结构化字段；历史行使用 nullable/default-safe 语义，迁移本身不联网、不批量回填。
- 生产仍使用现有 Django、Celery、PostgreSQL、Redis 和 Docker Compose，不引入新的外部服务；第三方请求继续遵守 15 分钟来源轮询和限流保护。
- 上线涉及近期文章受控回填、生产开关灰度、数据库备份、窗口/QQ 回归与运行手册更新；不改变旧文章 URL，不复制文章，不放宽 3 天新鲜度门禁。
