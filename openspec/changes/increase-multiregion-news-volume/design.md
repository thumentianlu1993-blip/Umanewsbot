## Context

当前生产已经具备五地区新闻源、地区 tab、通用 enabled 来源轮询、非日本自动发布 allowlist、地区生产概览和 QQ 群级地区配置。但线上行为仍偏保守：通用轮询为 30 分钟，每轮来源数有限，非日本自动发布受高价值阈值和小每日上限影响，最近窗口中英国/美国等地区抓到了候选但常停在待审核。用户希望直接把五地区升级为更丰富的日常新闻生产，并在重要赛事期间提高频率。

这个 change 同时触及 Django 模型、迁移、Celery Beat/Worker、自动发布、QQ 推送、后台运营页面和生产运维。核心风险不是“能不能多发”，而是高频抓取导致来源限流、并发 worker 导致重复发布/超配额、QQ 刷屏、以及运营无法解释 0 发布或 0 推送。

## Goals / Non-Goals

**Goals:**

- 将生产批准且可爬性通过的新闻源默认日常抓取窗口提升到 15 分钟。
- 以固定时钟窗口驱动抓取、发布选择和 QQ 推送，并持久化窗口结果。
- 支持每地区每窗口网页发布 1-5 篇的软目标，允许最近 3 小时候选池补量。
- 支持重要赛事期间对应地区 5 分钟升频。
- 支持地区、群、全站配额，防止网页发布和 QQ 推送超量。
- 支持来源自动降频、人工暂停、错误原因可见和恢复。
- 支持后台地区生产中心、窗口预览、窗口重跑、重要赛事维护、CSV 导入、生产摘要和异常通知。
- 生产上线可直接开启五地区，但部署阶段默认关闭新调度，并提供资格审计和快速回滚。

**Non-Goals:**

- 不自动启用历史不可用、高风险、强反爬或未通过可爬性验收的来源。
- 不把外部赛马数据库 importer 加入新闻常态调度。
- 不重做 AI 评分 prompt 或整体评分模型，只增加窗口选择、赛事加分、榜单加分和保底边界。
- 不做前台重要赛事提示、赛事专题页、用户赛事订阅、公开赛果页或马匹页。
- 不要求运营每次 dry-run；窗口预览仅用于解释和排障。

## Decisions

### 1. 用持久化窗口模型替代临时任务返回值

新增窗口记录，至少覆盖三类 `crawl / publish / qq_push`。窗口按固定时钟切片，日常 15 分钟，重要赛事 5 分钟。每条窗口记录必须有幂等唯一键：

- 抓取窗口：`kind + source + window_start`
- 发布窗口：`kind + region + window_start`
- QQ 窗口：`kind + region + target + window_start`

窗口包含 `status`、`claimed_at`、`lease_expires_at`、`attempt_count`、`last_error`、`scheduled_at`、`started_at`、`finished_at`、`mode`、`reason_summary`。任务执行必须先原子 claim 窗口，处理中 worker 崩溃后由 lease 过期释放，避免 Celery late ACK 或重复调度导致重复执行。

替代方案是继续依赖 `TaskExecutionLog` 和任务返回 JSON。拒绝该方案，因为它无法稳定支撑最近窗口验收、0 原因查询、补跑、重跑和并发幂等。

### 2. 发布和 QQ 配额必须有账本并在事务内占用

新增配额账本或等价模型，用于地区窗口、地区小时、群小时、全站小时的网页发布和 QQ 推送占用。发布窗口选择候选、锁候选文章、占用配额、修改文章公开状态、写入候选决策必须在同一数据库事务内完成。QQ 窗口同理，先写入目标群决策和配额占用，再创建或更新 `QQPushDelivery`。

旧的 `auto_publish_batch_task` 以 queryset slice 逐条发布，无法保证多个 worker 或补跑同时触发时不超额。本 change 应将新窗口发布作为主路径；旧任务可以保留为兼容入口，但必须委托到窗口选择服务或被新开关替代。

### 3. 决策原因单独持久化

新增候选决策和目标群决策记录：

- 候选决策记录每篇候选文章在某发布窗口的状态：`selected / blocked / not_ready / dedup_loser / quota_limited / below_score_floor / below_cutoff`。
- 目标群决策记录每篇已发布文章对某 QQ 目标的状态：`selected / skipped / failed`，并保存 `region_not_allowed / not_high_value / group_hourly_cap / site_hourly_cap / onebot_offline / already_sent / url_unavailable` 等原因。

这样后台可以解释“为什么 0 发布”和“为什么 0 推送”，也能让窗口预览与真实执行共享同一判断。

### 4. 来源配置拆成内置定义和运营运行态

当前内置来源同步会写回来源定义字段，容易覆盖人工调整。实现时应保护运营运行态字段，包括 `enabled`、`crawl_interval_minutes`、生产批准状态、人工暂停、暂停原因、当前有效间隔、backoff 截止时间、失败/成功连续次数、错误分类、是否允许重要赛事升频。

15 分钟默认只应用到“已启用、生产批准、可爬性通过”的来源。JRA 等官方重源或历史长间隔来源不会因为本 change 自动改为 15 分钟，除非明确批准。

### 5. 统一硬门禁服务

发布窗口、预览、重跑和人工解释必须调用同一个硬门禁服务。硬门禁返回结构化 blocker，至少覆盖无中文正文、翻译失败、正文过短、明显乱码、校验失败、非赛马内容、URL 不可访问、来源停用、重复组已有赢家、核心字段缺失。

保底发布只降低分数阈值到 45，不降低硬门禁。保底发布必须记录 `region_minimum_fill`，并标记不可自动 QQ。

### 6. 去重采用事件/内容分组

新增内容/事件分组或确定性内容指纹策略。地区内强去重，同一事件多来源只自动发布最高分文章；跨地区弱去重，高度重复时在全站上限紧张或 QQ 推送时优先只保留一篇。分组必须保存证据，例如标题相似度、摘要相似度、实体重叠、原文 URL/canonical、来源时间。

实现阶段可以先采用规则和文本相似度，不引入新的外部向量依赖。

### 7. 重要赛事表作为后台运营数据

新增重要赛事表，唯一键为 `赛事名 + 年份 + 地区 + 赛事等级` 的规范化组合，同时保存原始赛事名、规范化赛事名、可选外部 ID、别名、地区时区、本地比赛日期、本地开跑时间、UTC 升频窗口、是否启用。CSV 导入按该业务键 upsert，时间变化更新原记录，不新增。

有开跑时间时窗口为开跑前 3 小时到开跑后 1 小时；没有开跑时间时使用地区本地日期级窗口并在后台提示补全。同地区赛事窗口重叠只合并，不叠加频率和上限。

### 8. 运营通知独立于用户新闻推送

每日摘要和异常即时通知应使用独立 ops 通知服务或通道，不占用用户 QQ 新闻推送配额。优先发送内部运营 QQ 群，邮件兜底。通知必须有冷却、失败日志和关闭开关。若上线时 QQ ops 通知不可用，邮件通知可作为上线兜底，但后台必须显示 QQ ops 通知未启用。

### 9. 直接上线但默认关闭部署

用户选择当前用户量少，可直接上线五地区新规则。技术上仍采用两阶段开关：

1. 部署迁移和代码时新窗口调度默认关闭。
2. 执行只读资格审计，输出将被 15 分钟调度覆盖的来源、当前风险来源、将开启的地区和 QQ 目标。
3. 运营确认后开启五地区日常规则。

这不是长期单地区 canary，但避免迁移刚部署就自动高频触发外部请求。

## Risks / Trade-offs

- [高频抓取导致来源限流] → 只覆盖生产批准来源，保留来源级 backoff、人工暂停、错误分类和异常通知。
- [并发 worker 导致重复发布或超配额] → 窗口唯一键、原子 claim/lease、候选锁和配额账本同事务提交。
- [QQ 推送刷屏或限流] → 只推高价值、地区/群/全站上限、OneBot 离线保护、ops 通知与用户推送隔离。
- [保底发布降低内容质量] → 最低 45 分，硬门禁不放宽，保底不自动 QQ，并记录原因供抽检。
- [窗口补跑发布过期内容] → 自动补跑最大回看 3 小时，超时仅手动重跑；候选池同样最多回看 3 小时。
- [重要赛事时间录入错误] → 后台同时显示当地时间和北京时间，内部使用 UTC 判断；缺少开跑时间时醒目标记日期级窗口。
- [全站上限让某地区看起来没新闻] → 持久化 `site_hourly_cap_reached` 和地区公平决策，地区生产中心展示具体原因。

## Migration Plan

1. 新增模型和迁移：窗口、窗口候选决策、窗口目标决策、配额账本、重要赛事、来源运行态字段。
2. 新增 settings 与 `.env.example`，所有新窗口调度默认关闭。
3. 实现只读资格审计命令，先在本地和生产只读运行。
4. 实现窗口服务、硬门禁服务、去重服务、配额服务、来源 backoff 服务和 ops 通知服务。
5. 接入 Celery Beat，但受总开关控制；旧自动发布任务在新开关开启后委托到窗口服务或停用。
6. 完成后台地区生产中心、窗口详情/预览/重跑、重要赛事管理和 CSV 导入。
7. 完成本地测试、OpenSpec 校验、compose config、生产部署前备份。
8. 生产部署代码和迁移，保持新窗口调度关闭，验证 `/healthz/`、后台、资格审计。
9. 开启五地区新日常规则，观察最近 4 个窗口；必要时使用全局、地区、来源或 QQ 回滚开关。

## Open Questions

- 全站上限触发时的地区公平排序细节由实现阶段确定，但必须在窗口决策中可解释。
- 内容去重阈值由实现阶段结合现有字段和测试样本确定，不引入新的外部向量服务。
