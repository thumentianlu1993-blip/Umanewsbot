## Context

线上排查显示，文章 `3961` 的日文标题包含 `宝塚記念` 和 `キタサンブラック`，但翻译元数据 `terms` 为空，`unknown_horse_names` 中仍包含 `キタサンブラック`。生产库 `TermEntry` 当前为空，因此翻译纠偏和自动评分都没有正式术语信号。

当前代码中，`TermEntry.priority` 主要用于排序和覆盖顺序；`race_priority()` 会先通过 `resolve_terms()` 取得比赛术语，再依赖固定海外 P0 列表和 `G1`/`Ｇ１`/`Jpn1` 字符串判断赛事等级。该逻辑没有结构化比赛等级，也漏掉了 `GI`、`GⅠ`、`ＧⅠ` 等常见写法，更没有覆盖 G2、G3、L、OP、新马、未胜利等赛事类型。

术语候选池已经具备基础发现、证据和审核工作流，但本轮需要明确修复马名和比赛名未命中正式术语库时必须入池，并补齐候选项的可编辑基础内容字段：日文原词、中文译词、类型、日文别名、中文别名。

## Goals / Non-Goals

**Goals:**

- 恢复可版本化的正式术语导入能力，让历史 PRD 中已确认的核心术语能进入生产 `TermEntry`。
- 让比赛类正式术语可维护官方赛事等级或条件类型，并让等级参与自动评分。
- 保证翻译服务在标题、正文和原文中命中正式术语时，能把命中项写入元数据并应用中文译词。
- 修复马名和比赛名未命中正式术语库时的候选池入池链路。
- 让术语候选池的基础内容字段与术语库保持一致：日文原词、中文译词、类型、日文别名、中文别名；审核状态、证据、最近更新时间等仍属于运营/流程字段，不作为“术语内容字段”复制到正式术语。
- 扩展赛事等级识别，覆盖 JRA 官方层级中的 GⅠ/GⅡ/GⅢ、リステッド、オープン特別、3胜/2胜/1胜、新马/未胜利，并预留 Jpn、障害和地方赛事扩展。
- 增加本地回归测试，覆盖文章 `3961` 的关键特征，以及执行日 0:00 后候选新闻池文章的批量验收。
- 实施阶段严格 TDD：先写完整测试并看到失败，再写代码通过测试。

**Non-Goals:**

- 不做历史文章全量重翻译、全量重评分或全量候选回溯。
- 不让 AI 或发现器直接写入正式术语库。
- 不重构抓取、发布、AI 改写、QQ 推送或 Docker Compose 架构。
- 不在本轮补齐完整术语库业务数据；完整清单等待用户后续提供。

## Decisions

### 使用结构化 `race_grade` 表达比赛等级

为比赛类 `TermEntry` 新增可为空的 `race_grade` 字段，保存归一化赛事等级或条件类型，例如 `G1`、`G2`、`G3`、`JPN1`、`JPN2`、`JPN3`、`JG1`、`JG2`、`JG3`、`L`、`OP`、`3WIN`、`2WIN`、`1WIN`、`NEWCOMER`、`MAIDEN`、`LOCAL_GRADE`、`OTHER`。`priority` 继续负责匹配顺序和展示排序，不再承担赛事等级语义。

备选方案：

- 使用 `notes` 约定写 `race_grade=G1`：实现最轻，但不可校验，后台筛选和导入校验都弱。
- 复用 `priority >= 100` 表达高等级赛事：会混淆“替换优先级”和“赛事等级”，后续 G2/G3/OP 分层会失真。
- 只保留 `P0/P1/P2` 业务等级：能支撑评分，但不能满足 G2、G3、L、OP、新马、未胜利等细分识别。

### 从 `race_grade` 派生自动评分优先级

自动评分继续输出 `race_priority`，但来源改为“术语库等级优先，文本识别回退”。建议映射：

- `G1`、`JPN1`、重点海外一级赛等映射为 `P0`。
- `G2`、`JPN2`、`JG1`、重要 Listed 或系统配置的高关注赛事映射为 `P1`。
- `G3`、`JPN3`、`L`、`OP` 映射为 `P2`。
- `3WIN`、`2WIN`、`1WIN`、`NEWCOMER`、`MAIDEN` 等映射为 `P3` 或低价值层级，仅在有重点马、重点人物或其他强信号时提高自动化优先级。

具体分值仍在实现中贴合现有阈值，但决策原因必须写明命中的 `race_grade`、派生出的 `race_priority` 和来源。

### 候选池补齐术语内容字段

`TermCandidate` 保留审核状态、证据、出现次数、置信度、最近发现时间等运营字段，因为候选池需要这些字段完成流程管理；但候选详情、编辑和接受为正式术语时的“术语内容字段”必须与正式术语基础字段一致：`source_ja`、`target_zh`、`term_type`、`aliases_ja`、`aliases_zh`。马名和比赛名未命中正式术语时，必须进入候选池或合并到已有候选证据。

### 通过数据文件和管理命令导入正式术语

新增仓库内版本化术语数据文件，例如 `server/stable/data/terms_seed.csv`，并新增 `import_terms` 管理命令支持 `--dry-run`、`--mode create|upsert` 和指定文件路径。现有后台 CSV 导入逻辑应复用同一套解析、校验和提交服务，避免两套规则漂移。

### 翻译术语解析同时覆盖标题与正文

当前 `LLMTranslationProvider.translate_article()` 主要对正文调用 `resolve_terms()`，而问题文章的关键命中出现在标题。实现时应把标题、正文和规范化原文拼接为术语解析文本，写入 `metadata["terms"]`，并继续在最终译文上执行 `apply_term_mappings()`。

### 赛事等级识别使用可扩展归一化器

新增赛事等级归一化函数，把 `GI/GⅠ/ＧⅠ/G1/Ｇ１` 归一到 `G1`，把 `GII/GⅡ/ＧⅡ/G2/Ｇ２` 归一到 `G2`，把 `GIII/GⅢ/ＧⅢ/G3/Ｇ３` 归一到 `G3`，并覆盖 `Listed/リステッド/L`、`Open/オープン/OP`、`新馬`、`未勝利` 等写法。后续官方数据源补充时，只扩展归一化表和种子数据，不改评分主流程。

### 验收范围按执行日 0:00 后候选新闻池全量覆盖

本地和生产验收不只看文章 `3961`。验收执行时，应以系统运行时区的执行日 0:00 为起点，筛选所有进入候选新闻池的文章，逐篇检查：正式术语命中、未知马名/比赛名候选入池、赛事等级识别、自动评分决策原因。今天执行时，该边界为 `2026-06-09 00:00`。

## Risks / Trade-offs

- [术语数据不完整] → 第一版只恢复历史 PRD 确认项和本次修复所需赛事项；导入命令支持后续增量 `upsert`。
- [新增字段影响旧 CSV] → `race_grade` 设为空值默认，旧 CSV 缺少该列时继续可导入。
- [候选池字段扩展影响旧候选] → 新字段默认空列表或空字符串，旧候选继续可展示和审核。
- [赛事等级误配导致过度自动化] → 术语库等级优先、文本识别回退，并在决策原因中记录来源；低等级赛事不直接推高到自动发布区间。
- [生产已有人工录入术语被覆盖] → 生产导入前执行备份和 `--dry-run`；默认新增模式不覆盖，只有明确 `--mode upsert` 才更新。
- [标题和正文拼接增加匹配量] → 仍使用 `TRANSLATION_TERM_LIMIT` 和现有优先级排序，避免无界元数据膨胀。
