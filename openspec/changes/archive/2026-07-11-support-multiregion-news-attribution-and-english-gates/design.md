## Context

现有国际新闻链路已经支持 `NewsArticle.racing_region`、`NewsSource.racing_region`、地区 tab、地区发布窗口和群级 `PushTarget.allowed_regions`。这个模型适合“来源固定属于一个地区”的第一阶段，但新增英国高产源、香港多栏目和法国英文补源后，新闻会频繁跨地区：英国源可能报道法国赛事，香港马可能远征海外，法国马可能在英国或美国出赛。

同时，英文门禁已经经历两轮止血：`fix-english-term-gate-region-filter` 解决跨地区术语和高歧义词静态降级；`classify-english-term-gate-context` 进一步用上下文区分普通英文词与真实专名。它们减少了普通词误挡，但新增来源仍需要让门禁理解多地区归属和内容类别，否则真实法国赛事术语在英国主地区文章里可能被排除，或者 tips / result / official notice 走同一套自动发布与 QQ 规则。

## Goals / Non-Goals

**Goals:**

- 保留 `NewsArticle.racing_region` 作为主地区，新增相关地区能力，使一篇文章可出现在多个地区 tab。
- 自动计算主地区和相关地区：赛事发生地优先，核心对象地区其次，来源默认地区兜底。
- 支持后台人工调整地区最终值，但不强制保存额外操作日志或原因。
- 让发布窗口、地区配额、审计、前台地区 tab 和 QQ 推送统一使用主地区 + 相关地区集合。
- 让英文门禁结合主/相关地区和内容类别处理，继续保留真实专名 blocker，减少可接受翻译差异和跨地区误挡。
- 提供 dry-run 优先的重处理入口，用于上线前评估近期文章地区归属和门禁变化。

**Non-Goals:**

- 不在本 change 中新增具体新闻源适配器；新增英国、香港、法国来源由后续 `expand-international-news-source-pool` 承接。
- 不接入法语正文主链路；法国补量只使用英文可审核来源。
- 不复制文章正文为多个地区副本。
- 不重构现有 QQ 交付唯一约束；仍以文章 x 群为幂等粒度。
- 不把重处理命令变成直接公开发布入口。

## Decisions

1. **使用现有 `NewsArticle.racing_region` 表示主地区，新增相关地区结构。**

   现有发布窗口、首页、QQ、审计和后台大量依赖 `racing_region`。完全改成地区集合会扩大迁移和回归风险。保留主地区能让旧逻辑兼容，新逻辑在需要多地区时显式查询相关地区。

   备选方案是取消主地区，只保存集合。该方案理论更纯粹，但会让配额、排序、统计和人工筛选失去默认归属，且影响面过大。

2. **相关地区使用独立关联表，而不是 JSON 字段。**

   关联表可建立 `(region, article)` 索引，适合地区 tab、QQ 群匹配和审计查询；也能保存归属原因、来源规则、置信度和是否人工设置。JSON 字段实现快，但地区过滤和聚合会更难写高效且可测的查询。

   因本 change 会影响首页、窗口候选、QQ、审计和重处理，第一版不采用 JSON 过渡，避免后续再做一次数据结构迁移。

3. **地区归属服务作为独立领域服务。**

   新增 `stable.services.news_attribution` 或等价模块，集中完成实体抽取、赛事/马场/机构关键词规则、来源 fallback、人工锁定检查和审计 payload。抓取入库、自动化重评、重处理命令和后台保存都调用同一服务，避免各处重复判断。

4. **发布配额只按主地区消耗，相关地区只影响可见性和软目标判断。**

   一篇文章只发布一次，也只产生一个公开 URL。如果同时消耗多个地区配额，多地区新闻会挤占弱势地区产能。主地区配额消耗最符合“谁负责发布这篇文章”的账本语义；相关地区用于地区 tab、QQ 匹配和“这个地区已有可见内容”的解释。

5. **QQ 仍以文章 x 群去重，地区匹配扩展为主地区或相关地区命中。**

   这样符合群订阅预期：订阅法国的群能收到法国马在英国大赛的新闻；同一个群即使同时订阅英国和法国，也只收到一次。现有 `QQPushDelivery(article, target)` 唯一约束可继续作为重复发送保护。

6. **英文门禁使用“文章地区集合”而不是单主地区。**

   英文术语地区过滤必须看主地区 + 相关地区。若一篇文章主地区英国、相关地区法国，法国赛事术语应参与校验，而不是被 `term_region_excluded` 直接排除。不在地区集合中的术语仍按现有排除/降级逻辑处理。

7. **内容类别影响自动发布和 QQ 资格，但不绕过硬 blocker。**

   `result_brief` 和重大赛事 `preview` 可以进入自动发布和 QQ 高价值判断；普通 `tips`、投注营销、普通官方通知、普通育马/拍卖默认不进 QQ。所有类别仍必须通过正文、URL、重复、可信核心术语等硬门禁。

8. **重处理默认 dry-run，commit 只恢复候选。**

   重处理命令应输出地区归属变化、内容类别、门禁变化、预计可恢复候选和仍阻断专名。commit 只更新归属、门禁结果和候选唤醒时间，不直接把文章公开发布，降低批量修复风险。

9. **多地区查询必须集中封装并支持配置回退。**

   首页地区 tab、发布窗口、QQ 推送、审计和门禁不应各自手写 `racing_region OR related_regions` 查询。实现应提供统一的地区集合与 QuerySet helper；生产如发现多地区归属异常，可通过配置暂时只按 `NewsArticle.racing_region` 运行，相关地区数据保留但不参与展示、发布和 QQ 匹配。

## Risks / Trade-offs

- [迁移引入查询回归] -> 相关地区表增加索引；首页、QQ、审计查询通过服务函数封装；补充地区 tab、QQ 匹配和发布窗口测试。
- [自动地区归属误判] -> 保存归属原因；后台允许人工改最终值；重处理先 dry-run；自动规则无法判断时回退来源地区而不是猜测。
- [多地区文章刷屏] -> 综合流按文章 ID 去重；详情页只一篇；QQ 交付唯一约束继续防重复。
- [相关地区文章影响“至少 1 篇”口径] -> 发布窗口保存明确原因，区分“主地区发布 0 篇”与“相关地区已有可见内容”。
- [英文门禁被过度放宽] -> 真实专名仍 blocker；普通词和可接受保留形式只降级；新增测试覆盖 `Belmont Stakes`、`Princess Of Wales's Stakes`、普通 tips 和跨地区术语。
- [内容类别分类不稳定] -> 第一版使用规则分类和来源/栏目默认类别；不确定时用 `other` 或转人工，不把未知类别直接推 QQ。

## Migration Plan

1. 新增相关地区数据结构和索引，保留现有 `racing_region` 字段不变。
2. 为既有文章生成空相关地区或按 dry-run 结果小批补算；不在迁移中进行复杂历史推断。
3. 部署代码后先运行地区归属和门禁 dry-run，确认近期国际文章影响范围。
4. 按地区小批 commit 重处理，观察地区 tab、发布窗口、QQ 资格和审计输出。
5. 验证无误后，再进入后续新增新闻源 change。

回滚策略：若多地区展示或 QQ 匹配异常，可先关闭新来源和重处理；前台/QQ 查询回退只看 `racing_region`；保留相关地区数据但不参与展示和推送。若迁移结构异常，按生产备份回滚数据库并回退代码。
