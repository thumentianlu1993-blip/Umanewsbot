## Context

国际新闻详情解析目前由 `SimpleInternationalNewsAdapter.parse_detail_html()` 统一选择 `body_selector`；当选择器没有命中时会回退到整页 `soup.body`。2026-07-13 的生产样本证明这个兜底会把 Sporting Life 的导航、登录、推荐、投注推广、责任博彩提示和页脚全部写入 `body_ja_raw`，随后继续进入翻译、实体识别、审核和发布。TDN 虽然能命中 `span[itemprop='articleBody']`，但该节点仍混有 `Editor's Note`、跨页跳转 CTA 和 `Read Today's Paper` 等非正文内容。

本变更只修正文边界和博彩噪声。实体消歧、马名完整保护、日文普通词翻译和赛马固定格式分别由后续独立 change 处理，避免将不同失败机制混入同一轮上线。

## Goals / Non-Goals

**Goals:**

- 国际来源只在命中来源级可信正文节点后输出正文，不再把整页 `body` 当作可发布正文。
- 在 DOM 和段落两个层次清除导航、分享、推荐、编辑注、跳转 CTA、页脚和博彩推广。
- 博彩内容默认排除，同时保留赔率，以及赛事标题、马主等专有名词中的博彩公司名称。
- 为正文选择和清理结果提供元数据，使页面结构漂移能被测试和运营排查发现。
- 用文章 `8086`、`8267`、`8316`、`8318` 的精简生产样本覆盖回归，并在部署后受控重建、强制重译和原位更新这四篇已发布文章。

**Non-Goals:**

- 不在本变更中修改术语库命中、英文实体地区门禁、人物简称共指或未知马名保护。
- 不在本变更中解决日文普通词、产驹格式、调教时间或赛后访谈格式。
- 不改变来源启停、自动发布评分阈值、QQ 推送规则或公开 URL。
- 不以通用大模型重新判断正文边界；正文清理必须是可重复、可离线测试的确定性逻辑。

## Decisions

### 1. 可信正文选择器未命中时返回显式解析失败

`SimpleInternationalNewsAdapter` 只接受适配器声明的 `body_selector`。未命中时返回空正文，并在详情元数据写入 `body_parse_status=selector_not_found`、来源和选择器信息；不得回退到 `soup.body`。正文节点虽命中但清理后为空时写入 `body_parse_status=empty_after_cleaning`。现有入库和发布完整性门禁继续阻止两类空正文进入公开链路。

备选方案是保留整页兜底后依赖清理器识别正文。该方案在页面结构漂移时无法证明剩余文本确实属于新闻主体，并已在文章 `8086`、`8267` 上造成生产事故，因此不采用。

### 2. 来源级选择器负责缩小 DOM，公共清理器负责可复用噪声规则

Sporting Life 使用稳定的 `Article__ArticleBody` / `Article__ArticleMobileContentWrapper` 类名前缀选择正文容器；TDN 继续使用 `itemprop=articleBody`。选择节点后交给新的确定性正文清理服务：

- 先移除 `nav`、`footer`、`aside`、`form`、分享和推荐等结构化噪声节点。
- 再按段落处理来源已知的前导和尾部标记。
- 输出清理后的正文、命中的选择器、移除原因和计数，写入 `SourceArticleDetail.metadata`。

选择器由适配器声明，避免把某个站点的 CSS 细节塞入公共文本提取函数；公共规则集中维护，避免每个适配器复制相同的 CTA 和页脚清理。

### 3. 前导噪声逐段跳过，尾部模板从确定边界截断

`Editor's Note:` 和纯跳转说明属于前导非正文，只移除命中的完整段落，不扫描并改写真实正文句子。`Read Today's Paper`、`More from Sporting Life`、完整赛果/活动详情跳转等属于尾部边界；命中独立段落后截断该段及其后内容。

规则匹配使用大小写无关的规范化文本和来源 allowlist，并记录命中的规则名。未知来源不得套用可能误删正文的宽泛字符串规则。

### 4. 博彩噪声以段落语义信号过滤，并显式保护两个例外

清理器对 Sporting Life 等允许来源执行博彩段落过滤。明显的下注号召、优惠、免费投注、推荐组合、责任博彩和博彩公司导流段落默认删除。以下情况保留：

- 段落核心是赛事标题、马主或其他专有名词，博彩公司名称只是名称组成部分。
- 段落包含赔率表达，且不是优惠或下注号召；赔率作为新闻事实保留。

实现采用可审计的正则和标记组合，而不是只要出现博彩公司名就整段删除。被过滤段落及规则只记录摘要/计数，不把整页 HTML复制进翻译元数据。

### 5. 历史修复使用 dry-run 管理命令并复用翻译写回逻辑

新增受控管理命令，按显式文章 ID 读取数据库中已保存的 `original_content_html`，使用来源适配器离线重解析。命令默认 dry-run，输出文章 ID、来源、解析状态、正文前后哈希、长度和清理规则；只有显式 `--commit` 才在事务内写回原文正文与审计元数据，并写 `OperationLog`。命令不发起外网抓取、不调用翻译、不改变发布状态，也不触发 QQ。

在现有 `translate_news` 命令和翻译任务上增加默认关闭的 `--force` / `force` 参数。只有本次明确列出的已发布问题文章使用同步强制重译；强制模式复用 `NewsArticle.apply_translation_result(force=True)` 覆盖已确认需要替换的公开中文字段，但不重新执行发布状态转换，因此保持原文章 ID、原公开状态和 `published_to_web_at`，也不会创建新的 QQ delivery。翻译仍通过现有 provider、`TranslationRun`、状态与失败日志写回，不另写一套翻译实现。

不得直接用 SQL 拼接正文、清空人工字段或再次调用 `publish_article()`。每篇文章在替换公开稿前保存修复前正文摘要和状态，修复后逐篇检查公开详情。

## Risks / Trade-offs

- [上游 CSS 类变化导致空正文] -> 不回退整页；元数据显式标记选择器失败，测试与抓取摘要可见，宁可转人工也不发布页面框架。
- [尾部标记也出现在真实正文] -> 仅对独立段落、指定来源和边界位置应用；测试覆盖正文中普通提及不被截断。
- [博彩过滤误删赛事事实] -> 对赔率与专有名词例外先判断，记录删除原因，并用 8267 的真实段落做正反例。
- [历史文章重处理改变发布状态或重复推送] -> 修复命令只改原文正文，强制翻译只替换译文，不调用发布服务；测试断言公开状态、发布时间和 QQ delivery 数不变。
- [强制翻译被误用于其他人工稿] -> `--force` 默认关闭且必须配合显式文章 ID；命令帮助与运维文档注明只用于已批准的内容修复。
- [只修四篇而遗漏同模板文章] -> 生产回归除指定文章外随机抽取同来源近期新文章，检查正文首尾和博彩噪声。

## Migration Plan

1. 先加入四篇问题文章的精简 HTML fixture 和失败测试，证明现状会选中整页或保留模板噪声。
2. 实现正文选择、结构化节点移除、边界截断和博彩段落过滤；运行目标测试、国际适配器测试和 Django 检查。
3. 部署前核对生产 `HEAD`、容器和任务状态，备份 `.env` 与数据库并验证备份可读。
4. 部署代码，不涉及数据库 schema migration；运行 `manage.py check`、目标测试和 `/healthz/`。
5. 先 dry-run 再 commit 文章 `8086`、`8267`、`8316`、`8318` 的离线正文重解析；随后按显式 ID 同步强制重译并校验。既有文章继续保持公开，不再次调用发布动作，避免重复 QQ 推送。
6. 验收四篇公开详情，再随机抽取 Sporting Life、TDN 近期新文章检查正文首尾、博彩噪声和解析元数据。

回滚策略：

- 代码异常：回滚到部署前 commit 并重建服务。
- 正文误删：暂停问题来源抓取/自动发布，恢复数据库备份或逐篇恢复修复前正文，再修正规则。
- 选择器漂移：保持空正文和转人工状态，不启用整页兜底。

## Resolved Questions

- 博彩边界：默认屏蔽博彩导流和投注建议；仅保留专有名词中的博彩公司名称与赔率。
- 解析失败策略：可信正文节点未命中时显式失败，不回退整页。
- 历史修复范围：本 change 负责文章 `8086`、`8267`、`8316`、`8318`。
- 生产更新方式：通过受控正文修复命令和现有翻译写回逻辑更新同一文章；既有文章保持公开，不再次调用发布动作、不另建文章、不手工改译文。
