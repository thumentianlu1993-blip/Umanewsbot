## Context

`fix-crawl-freshness-and-jra-date-parse` 已把访问量榜和注目数榜提高到小时级抓取，并在后台来源列表 / 工作台展示来源健康摘要。审查发现两个边界没有收紧：

- 来源健康摘要从最近 `CrawlJob` 取计数，但从 `NewsSource.last_crawl_status` 取状态。若最新 job 正在运行，`success_count=0` 会和旧成功状态组合成“成功无新增”的误导展示。
- `crawl-netkeiba-latest-hourly` 和 `crawl-netkeiba-access` 都在每小时 `00` 分触发，同一个上游会同时跑新着顺和访问量榜，削弱错峰设计。

当前已有 `CrawlJob.status=started/success/failed`、`NewsSource.last_crawl_*` 和后台 badge 样式，不需要新增模型或迁移。

## Goals / Non-Goals

**Goals:**

- 后台来源健康摘要优先展示最新运行中 job，不把运行中 job 的默认计数误判为最近成功结果。
- 陈旧运行中 job 不得永久遮住停滞状态；超过 60 分钟未完成时展示疑似卡住。
- 启用来源长期没有任何完成记录或运行中记录时，也能展示为长时间未运行。
- 停用来源不参与长时间未运行告警，避免人工关闭来源造成误报。
- 最近成功 / 失败 / 成功无新增摘要只基于已完成的最近抓取记录。
- netkeiba 新着顺、周日高频新着顺、访问量榜、注目数榜在同一小时内错峰触发，避免同源集中请求。
- JRA 单篇详情页结构异常按条目跳过并记录，不拖垮同轮其他可解析新闻。
- 增加测试覆盖这两个 P2 缺陷，并更新运维文档中的验收口径。

**Non-Goals:**

- 不改变访问量榜和注目数榜小时级抓取目标。
- 不改变 `CrawlJob` 或 `NewsSource` 数据结构。
- 不引入新的调度配置环境变量。
- 不处理更复杂的任务超时恢复、worker 并发限流或上游动态退避。

## Decisions

### 来源健康使用“最新 job”和“最新已完成 job”两个概念

实现时将 `_source_health()` 中的 job 判定拆开：

- `latest_job`：按 `started_at` / `id` 倒序取最新 job，用来判断是否有任务正在运行。
- `latest_completed_job`：排除 `TaskStatus.STARTED` 后取最近已完成 job，用来生成成功、失败、无新增、重复数量和错误摘要。

判定顺序：

1. 如果 `latest_job.status == started` 且 `started_at` 距今不超过 60 分钟，展示“运行中”，摘要包含开始时间；如存在上一条已完成记录，可补充“上次结果”。
2. 如果 `latest_job.status == started` 且 `started_at` 距今超过 60 分钟，展示“运行超时”或等价疑似卡住状态，摘要提示运行中记录已超过 60 分钟未完成；上一条已完成记录只作为参考。
3. 否则使用 `latest_completed_job` 和 `NewsSource.last_crawl_*` 生成最近结果。
4. 长时间未运行只在来源仍启用、没有未超时运行中 job 且参考时间超过阈值时展示；参考时间优先使用最近完成抓取时间，其次使用 `NewsSource.created_at`，避免从未运行过的旧来源长期显示为普通“未运行”。
5. 如果没有任何完成记录，也没有运行中 job，展示“未运行”。

这样可以保留 `NewsSource.last_crawl_*` 的快捷缓存价值，同时避免把运行中记录与旧状态拼成错误结论。

备选方案是完全只信 `NewsSource.last_crawl_*`。该方案简单，但无法展示当前运行中的任务；也无法满足“后台看到真实最近执行状态”的目标。

### netkeiba 榜单固定错峰到 `16/26` 分

保留新着顺每小时 `00` 分，JRA 每 12 小时 `10` 分不变；将访问量榜调到每小时 `16` 分，注目数榜调到每小时 `26` 分。

这个选择有三个好处：

- 三个 netkeiba 常规任务互相错开。
- 避开周日重赏高频新着顺补抓分钟：`14:30/35/40/45/50/55` 与 `15:00/05/10/15/20/25/30`。
- 避开 JRA 的 `10` 分固定触发点。
- 生产验收时可以在同一小时内按 `00 -> 16 -> 26` 查询 `CrawlJob`，判断非常直观。

备选方案是访问量榜 `15` 分、注目数榜 `20` 分，但这会和周日 15 点的高频新着顺补抓冲突。访问量榜 `05` 分、注目数榜 `10` 分也不理想，因为 `10` 分会和 JRA 在 `00/12` 点重合。另一个方案是白天更高频、夜间低频，这超出本次 P2 修复范围。

### JRA 单篇详情结构异常按条目跳过

JRA 列表页和网络请求仍是任务级边界：列表页不可访问或整体结构不可解析时，JRA crawl 应失败并记录错误。详情页则是单篇边界：某一篇详情页缺少标题、日期节点或出现无法解析的日期时，只跳过该篇并把错误写入抓取摘要。

实现时在 `_crawl_jra_source()` 的单篇 `fetch_detail()` 调用处捕获 `ValueError`、`AttributeError`、`IndexError`、`TypeError` 这类详情解析异常。网络异常、列表抓取异常和数据库写入异常不进入跳过集合，仍按整体失败处理。成功但存在跳过项时，将跳过摘要同时写入本轮 `CrawlJob.error_message` 和 `NewsSource.last_crawl_message`，保持 job 级追溯；`CrawlJob.status` 仍为 `success`，因为整轮抓取没有失败。

备选方案是在 `JRAAdapter.fetch_detail()` 内吞掉结构异常并返回空 detail。该方案会让下游入库看到不完整文章，风险更高；在任务层跳过并留摘要更可审计。

### 测试覆盖 review 中的失败模式

新增或调整测试时不只断言文案存在，还要构造 review 指出的组合状态：

- `latest_job=started`，`NewsSource.last_crawl_status=success`，最近已完成 job 为成功无新增：页面必须显示“运行中”，不能显示成“成功无新增”作为当前状态。
- 一个从未完成过抓取的来源有运行中 job：页面必须显示“运行中”，不能显示“长时间未运行”。
- 一个超过 60 分钟仍为 `started` 的 job：页面必须显示疑似卡住状态，不能一直显示普通“运行中”。
- 一个创建已久且没有任何抓取记录的启用来源：页面必须显示“长时间未运行”，不能长期显示普通“未运行”。
- 一个创建已久且没有任何抓取记录的停用来源：页面不得显示“长时间未运行”。
- Celery Beat 断言 latest/access/attention 三个 netkeiba 常规任务分钟值两两不同，访问量榜 / 注目数榜避开周日高频新着顺分钟，并且仍为小时级。
- JRA 单篇详情结构异常测试：第一篇详情缺关键节点、第二篇详情正常时，应跳过第一篇并继续入库第二篇，且本轮 `CrawlJob` 与来源最近摘要都保留跳过摘要。

## Risks / Trade-offs

- [Risk] “运行中”摘要会让后台多一个状态，运营人员需要理解它不是失败。  
  Mitigation: 文档中说明“运行中”表示任务已开始但尚未写入最终结果；最近完成结果仍可作为参考。

- [Risk] 固定错峰只能减少同一小时内集中触发，不能解决任务执行时间过长造成的实际重叠。  
  Mitigation: 本次只修复调度层 P2；如果生产仍有重叠，再单独设计 Celery 队列隔离、任务锁或动态退避。

- [Risk] 固定 60 分钟超时可能把极慢但仍在执行的抓取标记为疑似卡住。  
  Mitigation: 当前内置抓取任务正常应在分钟级完成；超时状态只用于后台诊断，不自动中断任务或改写数据库状态。

- [Risk] `_source_health()` 查询最新 job 和最新已完成 job 会增加少量查询。  
  Mitigation: 当前来源数量很少，后台页面访问量低；本次保持 view 层轻量实现，不提前引入复杂预取。

## Migration Plan

1. 本地调整 `_source_health()` 和 Celery Beat 分钟配置。
2. 更新配置断言、后台来源健康测试和文档。
3. 运行 `DB_ENGINE=sqlite python manage.py check`、相关 `stable` 测试和 OpenSpec 严格校验。
4. 生产部署时重启 `beat / worker / web`，确认 Celery Beat 加载新分钟配置。
5. 生产验收在连续一个小时内确认 netkeiba 新着顺、访问量榜、注目数榜分别在 `00/16/26` 分附近生成 `CrawlJob`；如有运行中任务，后台显示“运行中”；构造或观察超时运行中任务时，后台显示疑似卡住。
6. 回滚时恢复上一版本代码并重启 `beat / worker / web`；本 change 不包含迁移。
