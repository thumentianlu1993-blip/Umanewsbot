## Context

当前 `extract_unknown_horse_names()` 使用片假名正则、普通词名单和上下文打分识别疑似未知马名。这个方案轻量，但不能真正判断没见过的片假名词是否为普通词：只要文本出现在标题或带有类似马名的上下文，就可能进入未知马名列表。翻译阶段会把这些名称保护为占位符，自动发布校验也会检查它们是否被保留，因此误识别会直接增加人工审核噪声。

外部赛马数据导入已经建立 `ExternalHorseAlias` 本地索引。该索引包含日文马名、标准化马名、外部 horse_id、来源、置信度和最近出现时间，适合作为“确认这是马名”的本地数据源。但它不包含中文译名，因此不能等同于正式术语库 `TermEntry`。

## Goals / Non-Goals

**Goals:**

- 使用本地 `ExternalHorseAlias` 辅助识别文章中的真实马名，减少普通片假名词误报和真实马名漏报。
- 保持 `TermEntry` 与 `ExternalHorseAlias` 的职责分离：前者表示有中文译名或固定译法的正式术语，后者表示外部确认的日文马名索引。
- 在翻译阶段保护外部已知但无中文译名的马名，要求模型原样保留。
- 在发布校验和术语候选发现中记录识别来源，让后台排查能区分正式术语、外部马名和启发式猜测。
- 不引入新闻处理链路中的外部网络请求。

**Non-Goals:**

- 不把 `ExternalHorseAlias` 批量导入 `TermEntry`。
- 不为外部马名自动生成中文译名。
- 不改变外部赛马数据导入节奏、限速、断点续跑或数据模型。
- 不改变自动评分阈值、重复内容判断、批量自动发布策略或前台展示规则。

## Decisions

### 1. 新增结构化马名识别结果，而不是继续只返回字符串列表

新增服务层结构，例如 `RecognizedHorseName` / `HorseNameRecognitionResult`，至少包含：

- `name_ja`
- `source`：`formal_term`、`external_alias`、`heuristic`
- `external_horse_ids`
- `matched_text`
- `confidence`
- `needs_preserve`
- `has_translation`

原因：

- 翻译保护、校验和候选池需要知道“为什么它被当作马名”。
- 外部索引命中和启发式猜测的可信度不同，不能在后台继续混成同一种 `unknown_horse_names`。
- 可以兼容旧调用：短期仍提供返回字符串列表的封装，减少一次性改动面。

备选方案：直接在 `extract_unknown_horse_names()` 内把外部索引命中追加到旧 list。该方案实现快，但后续无法解释 `unknown_horse_not_preserved` 来自外部索引还是启发式误报，也不利于候选池分流。

### 2. 先提取候选 token，再批量查询 `ExternalHorseAlias`

识别流程建议：

1. 从标题和正文中提取片假名候选 token，并保留出现位置。
2. 对候选 token 使用与导入一致的 NFKC 标准化。
3. 批量查询 `ExternalHorseAlias.objects.filter(normalized_name__in=...)`。
4. 对命中的外部马名按文章出现顺序和长词优先去重。
5. 剩余 token 再进入普通词过滤和启发式打分。

原因：

- 避免对每篇文章扫描全部外部马名索引。
- `ExternalHorseAlias` 现有 `source + normalized_name` 索引可复用。
- 先用数据库确认真实马名，再让启发式处理剩余 token，可以降低 `タイトル` 这类普通词因标题加分被误判的概率。

备选方案：把所有外部马名加载到内存 trie 后扫描全文。该方案长远可能更快，但首版数据量不大，且需要缓存失效与多进程一致性设计；当前先用数据库批量查询更保守。

### 3. 正式术语优先于外部马名索引

如果同一日文文本已命中启用的 `TermEntry(term_type=horse)`，系统应按正式术语处理：

- 进入翻译术语表。
- 译后可映射到中文译名。
- 不再作为外部未知马名要求保留日文。

如果只命中 `ExternalHorseAlias` 而没有正式中文术语，系统应：

- 翻译前替换为占位符。
- 要求模型在译文中保留占位符。
- 译后还原为原始日文马名。
- 不执行中文替换。

原因：

- `TermEntry` 是人工确认的中文术语，优先级最高。
- 外部索引只证明它是马名，不证明中文译名是什么。

### 4. 候选池记录所有新闻中出现的外部已知但无中文译名马名

术语候选发现继续只创建待审核 `TermCandidate`，不得直接创建 `TermEntry`。外部马名命中但未命中正式马名术语时，应进入候选池，detector 标记为 `external_horse_alias`，reason 标记为“本地外部马名索引命中且缺少中文译名”，置信度高于纯启发式。首版不按标题、首段、出现次数或自动评分信号限制外部马名入池；只要该马名出现在新闻原文中，且本地索引确认是马名，就值得记录供后续补中文译名。

原因：

- 运营希望记录新闻中出现的 JRA 相关马名，后续逐步补齐中文译名。
- 不会把所有外部马名无条件塞入正式术语库。
- 能区分普通词误报与真实马名待翻译。

备选方案：外部马名命中后不进入候选池。该方案候选池更干净，但运营无法系统性补中文译名，后续仍需要人工在文章里发现并快速创建术语。

### 5. 普通词与外部马名同名时必须依赖强马名上下文

如果片假名文本同时存在于普通词过滤表和 `ExternalHorseAlias`，系统不得仅凭外部索引命中就判定为马名。只有命中强马名上下文时才作为外部已知马名处理，例如赛果/出走格式、括号内骑手结构、父母/产驹上下文、性龄上下文、或标题中明显作为新闻主语出现。否则应跳过或记录为普通词/马名冲突诊断，不进入马名候选池。

原因：

- 日本马名可能与普通片假名词同名；数据库存在同名马不代表文章当前语境一定在说马。
- 这可以避免把 `記事のタイトル` 里的 `タイトル` 因外部库存在同名马而误判为马名。

备选方案：外部索引永远优先于普通词过滤。该方案能最大化召回，但会重新引入普通词误报。

### 6. 同名马必须保留多个外部 horse ID

同一个 `normalized_name` 可能对应多个 `ExternalHorseAlias.external_horse_id`。结构化识别结果应保留 `external_horse_ids` 列表，并可选保存用于展示的主 horse ID，例如按置信度和最近出现时间排序后的第一个；不得在服务层只取 `.first()` 后丢弃同名歧义。

原因：

- 同名马、年代不同的同名马或多来源别名冲突都可能出现。
- 保留歧义可以让候选池和校验 payload 具备可追溯性。

### 7. 校验 issue 保持 warning 级别但提升可解释性

外部已知马名未保留应继续作为 warning，而不是 blocker。issue payload 应包含识别来源、外部 horse IDs、命中名称和置信度；后台展示仍可使用现有 gate issue 面板。

原因：

- 当前自动发布门禁已将这类低确定性内容质量问题从 blocker 降为 warning。
- 外部索引命中比启发式更可信，但“是否必须在摘要化发布稿中出现”仍可能依赖文章内容和发布稿长度。

## Risks / Trade-offs

- [外部索引覆盖不足] → 未导入或没命中的马名仍走启发式识别和候选池；实现时保留旧逻辑作为兜底。
- [外部索引存在脏数据] → 只作为保留日文和候选来源，不自动生成中文译名；后台可通过候选池人工拒绝或忽略。
- [候选池短期增加真实马名候选量] → 这是本轮接受的产品取向；detector 和 reason 明确标记 `external_horse_alias`，列表可后续按理由筛选；首版不做全量历史回填。
- [普通词与马名同名导致误报] → 冲突词必须命中强马名上下文才作为外部已知马名，否则跳过或只记录诊断。
- [同名马歧义] → 识别结果保留多个 `external_horse_ids`，不静默丢弃歧义。
- [查询性能退化] → 只对文章中提取到的候选 token 做 `normalized_name__in` 批量查询，不扫描全表。
- [旧 metadata 字段兼容] → 保留 `unknown_horse_names` 字符串列表，同时新增结构化来源字段，避免后台和历史记录突然断裂。

## Migration Plan

1. 新增识别服务与测试，不改数据库模型。
2. 将翻译阶段改为使用结构化识别结果生成占位符和 metadata。
3. 将发布校验阶段改为记录结构化外部马名保留 warning。
4. 将术语候选发现阶段改为消费同一识别服务，并区分 `external_horse_alias` 与 `unknown_horse` detector。
5. 本地运行 `manage.py check`、相关 stable 测试和 OpenSpec 校验。
6. 生产部署后抽检近期候选文章 metadata、gate issues 和术语候选池，确认 `タイトル` 不再误报，`マヤノライジン` 等外部索引命中马名可被保护。

回滚策略：

- 代码回退即可恢复旧启发式识别；本 change 不新增迁移，不改变外部数据表。
- 如上线后候选池噪声过高，先通过 detector / reason 筛选和候选池批量处理优化运营体验，不默认关闭外部索引候选发现。
