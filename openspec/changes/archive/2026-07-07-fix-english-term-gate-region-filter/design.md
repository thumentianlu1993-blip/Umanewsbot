## Context

当前非日本英文新闻已经进入常态抓取窗口，但生产观察发现：香港、英国、美国有文章入库，发布窗口却长期为 `no_ready_candidates`。根因之一是正式术语库中的英文词条会在发布校验中触发 `core_term_missing`，而部分词条是普通词、短词或跨地区高歧义词，例如 `CLASS`、`CONTENT`、`LINK`、`AGENT`、`Oaks`、`America`、`NUMBERS`。这些词在英文新闻中经常作为普通语义出现，不应默认作为硬门禁。

当前 `core_term_missing` 仍然有价值：真正重要的马名、赛事名、骑师名缺失时，自动发布应被阻断。因此本设计目标不是删除硬门禁，而是让硬门禁只作用在可信核心实体上。

## Goals / Non-Goals

**Goals:**

- 在不放松真正硬门禁的前提下，降低英文普通词和跨地区术语误挡。
- 让英文正式术语校验按文章地区、术语地区和全局通用范围过滤。
- 让高歧义词可以配置化降级为 warning 或忽略，并保留审计原因。
- 让最近被误挡的非日本文章可以在规则修复后受控重处理。
- 让生产审计能显示各地区高频 `core_term_missing` 词和降级情况。

**Non-Goals:**

- 不重建完整实体识别系统，不在本 change 中实现“主地区 + 涉及地区集合”的文章归属。
- 不扩展法国新闻源；法国扩源由 `expand-france-news-sources` 单独处理。
- 不绕过正文缺失、翻译失败、重复内容、可信核心术语缺失等真正硬门禁。
- 不直接修改 QQ 推送策略或限流。

## Decisions

### 1. 先用规则和配置止血，不新增复杂机器学习判定

实现上优先在服务层增加确定性规则：地区过滤、高歧义词表、长度和上下文条件。这样可解释、可测试、可快速回滚。

替代方案是引入模型判断某个词是否为马名或赛事名，但这会增加外部依赖和不可解释性，不适合当前生产止血。

### 2. 发布校验的术语范围必须先按地区收窄

英文文章校验正式术语时，默认只纳入：

- `TermEntry.racing_region == article.racing_region`
- `TermEntry.racing_region == ""` 的全局通用术语

第一版不引入 notes/source metadata 形式的“跨地区可检查”隐式约定。确实应当跨地区生效的术语，应先治理为 `racing_region == ""` 的全局通用术语；若后续做“涉及地区集合”，再把相关文章涉及地区纳入校验范围。

### 3. 高歧义英文词不得直接生成 blocker

第一版高歧义判断优先使用生产高频误挡词配置清单。短词、全大写词等派生规则只能在非核心命中时降级；一旦同地区或全局术语被判断为核心实体，除非它明确进入高歧义配置清单，否则仍然保留硬门禁。

命中高歧义规则时，系统应生成 warning 或 info，而不是 `core_term_missing` blocker。payload 必须记录被降级的术语、原本命中位置、降级原因和术语 ID。

### 4. 真正核心实体仍然可以硬阻断

以下情况仍可保留 blocker：

- 同地区或全局可信赛事名在标题或首段命中，且发布稿没有中文译名或可接受保留形式。
- 高优先级马名 / 赛事名具备低歧义文本或强上下文。
- 人工明确标记为可硬阻断的术语。

第一版不新增 `TermEntry` 字段，避免为止血引入迁移和后台维护成本。高歧义词先由 settings 配置清单承载；短词 / 全大写等自动派生规则只用于非核心命中，后续若运营需要在后台维护，再单独新增 `publish_gate_level` 或 `can_block_publish` 等可理解字段。

### 5. 重处理只处理近期误挡，不自动全库重跑

重处理入口应支持时间范围、地区、来源和 dry-run。默认只针对最近 3-7 天非日本 `manual_review_required` 且 blocker 主要来自术语缺失的文章。重处理不直接发布文章，只重新运行评分 / 发布校验；通过后进入 `publish_ready` 或设置新的复审时间，使发布窗口能再次看到。

## Risks / Trade-offs

- [Risk] 降级过多导致真实马名或赛事名被漏挡。  
  Mitigation: 只对高歧义词降级；保留同地区高可信实体 blocker；测试覆盖真实核心术语缺失仍阻断。

- [Risk] 地区过滤会漏掉跨地区新闻中的外地实体。  
  Mitigation: 第一版允许全局通用术语；确实跨地区通用的词条先治理为全局术语。后续用文章涉及地区识别扩展，而不是现在无差别全局检查。

- [Risk] 批量重处理可能一次释放过多文章。  
  Mitigation: 提供 dry-run、时间范围和地区限制；重处理后仍受发布窗口配额和 QQ 限流约束。

- [Risk] 术语库中的误挡词会继续增长。  
  Mitigation: 审计输出高频阻断词，形成定期治理入口；后续可把高歧义标记纳入术语后台维护。

## Migration Plan

1. 增加规则和配置，第一版不要求生产数据迁移；如后续需要字段，再另开变更补迁移和后台展示。
2. 本地补充校验、自动化、窗口候选和审计测试。
3. 部署后先运行生产只读审计，确认高频误挡词被降级。
4. 对最近非日本误挡文章执行 dry-run 重处理，抽检结果后再 commit。
5. 观察 24 小时内香港、英国、美国入库文章的 `publish_ready` 和公开数量。
