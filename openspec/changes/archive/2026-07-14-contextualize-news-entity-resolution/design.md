## Context

当前 `resolve_terms_for_language()`、`recognize_horse_names()`、`apply_term_mappings()`、`extract_horse_tags()`、发布校验和自动马匹关联分别按字符串命中。生产样本证明这些局部判断会互相矛盾：`Donnacha O'Brien` 已命中人物术语，但后续 `O'Brien` 没有继承同一人物；`Grace Hamilton has joined ... as ... Coordinator` 中的 `Hamilton` 被当成马；`more than enough time`、`the years roll on` 等普通短语命中马名术语并进入标签；`ノリヤンモーニン`、`マドモアゼルアスク`、`プティフォリー`、`ルアーヴル` 和含 `ユーロ` 的完整实体则被内部短术语拆开替换。

本变更跨越术语解析、翻译保护、标签、发布校验和自动马匹关联，但不需要新表。现有 `TermEntry`、`TermAlias`、`ExternalHorseAlias`、`TranslationRun`、`tags_json` 和 `ArticleHorseLink` 继续作为事实来源或输出；文章级解析结果只在进程内计算，并将必要摘要写入既有翻译/门禁元数据。

## Goals / Non-Goals

**Goals:**

- 为标题和正文生成唯一、确定性、可序列化的文章级实体解析结果，区分人物、马名、普通词和受保护的完整未知马名。
- 让完整跨度优先于内部短术语；日文未知完整马名整体进入占位符保护，不再局部翻译。
- 利用人物职业/任职/发言语境识别英文人名，并在同篇文章中把后续唯一姓氏回指到已确认人物。
- 让翻译术语表、译后替换、自动标签、发布校验和自动马匹关联消费同一批已接受实体，不再各自重新按字符串猜测。
- 提供显式文章 ID、默认 dry-run 的生产修复入口，重译并重算机器生成标签/自动关联，同时保护人工字段、人工关联、公开身份和 QQ 幂等状态。

**Non-Goals:**

- 不引入通用 NER 模型、外部 AI 分类调用或新的在线依赖。
- 不为缺少正式中文译名的马名自动创造中文译名。
- 不批量修改 `TermEntry` 的术语类型，也不删除可能在其他文章真实表示马匹的高歧义术语。
- 不在本 change 处理中日文普通词翻译、产驹格式、追切计时或赛后采访格式；这些属于后续日文翻译 change。
- 不覆盖 `tags_json` 人工锁定字段，不改变 `ArticleHorseLink` 的 `MANUAL` 或 `REMOVED` 决定。

## Decisions

### 1. 建立单一文章级解析器，而不是继续给各消费点追加例外

在 `stable.services.terms` 中新增文章级解析入口，输入原文语言、标题、正文以及可选的预加载术语/外部别名，输出带跨度的结构化实体列表。每项至少包含 `entity_type`、`matched_text`、规范原文、中文译名、起止位置、置信度、证据、冲突标记、是否需要原文保护及关联的术语/外部马 ID。

翻译、标签、校验和自动关联可在同一任务内复用该结果；`TranslationRun.terms_used`、翻译 metadata 和 prompt 必须引用同一批接受术语，不能由外层任务再调用旧解析器。批量 `ValidationBatchContext` 携带预计算实体与接受术语 ID，避免校验阶段重新分叉或逐篇扫描。`TermType.JOCKEY/TRAINER/OWNER` 的完整命中属于明确人物证据；其他 Title Case 姓名只能由人物语境升级。替代方案是在 `translation.py`、`models.py` 和 `validation.py` 分别补黑名单，但这会继续产生正文正确、标签错误的分叉，故不采用。

### 2. 使用跨度仲裁与最长优先，禁止在已接受完整实体内部替换短术语

候选先保留原文位置，再按“明确人物跨度、完整外部马名/正式完整马名、强上下文完整未知日文马名、其他上下文术语”仲裁；同类重叠按起点、长度、证据强度确定。接受一个完整跨度后，内部短 `TermEntry`、冠名或父马名只作为解释证据，不再独立进入翻译术语表、替换或标签。

日文连续片假名/马名字符 token 在强马名语境中即使只内部命中短术语，也作为完整未知马名保护。保护占位符在构建翻译 prompt 前应用；模型返回后先只按文章级接受实体执行确定性术语映射，最后才恢复完整马名占位符。不得在占位符恢复后再调用扫描全术语库的 `apply_term_mappings()`，否则内部短术语仍会二次拆分。替代方案是给已知问题马逐条加 stopword，这无法覆盖新马名且会不断增长，故不采用。

### 3. 英文人物使用保守规则与篇内唯一姓氏回指

英文大写姓名跨度只有在命中人物术语，或邻近 `joined/appointed/coordinator/trainer/jockey/said/according to` 等明确人物语境时才接受为人物。确认完整人物后提取姓氏；后续姓氏只在位于首次全名之后、篇内只对应一个人物且不处于强马名语境时回指同一人物。`Donnacha O'Brien → 岳品贤` 因正式人物术语可生成篇内 `O'Brien → 岳品贤` 映射；`Grace Hamilton has joined ... as ... Coordinator` 会把完整姓名标为人物并压制内部 `Hamilton` 马名命中。

不采用“所有两个首字母大写词都是人物”，因为英文马名同样常为 Title Case；不采用跨文章持久化姓氏 alias，因为同姓冲突会污染其他文章。

### 4. 英文普通词或短语马名必须有强马名证据

英文马名术语/外部别名若同时呈普通词形、全小写出现在句中或命中高歧义列表，只有在出马表/赛果结构、父母血统、性龄、赔率、明确参赛/胜负动词、标题核心主语等强马名上下文中才升级。`the years roll on`、`more than enough time` 和文章 8330 的普通词命中会被标为普通词而非马；真实马名 `多爵` 或强结构中的同形词仍可接受。

该判断复用现有普通词种子与英文门禁上下文工具，但输出统一实体类型；不直接删除术语库记录，因为同一字符串在其他上下文可能确为马名。

### 5. 机器标签使用既有 metadata 保存 provenance，只重建机器部分

`extract_horse_tags()` 只从已接受的 horse 实体生成中文译名或需保留的完整原文。新翻译在 `translation_metadata.machine_horse_tags` 记录本轮机器马标签；写回非人工 `tags_json` 时，只移除上轮 provenance 中的机器马标签，并加入新的确定性结果，同时显式保留 `source_config.default_tags` 和其他现有标签。旧文章没有 provenance 时，显式修复 dry-run 使用“当前 active 马名中文译名集合减去来源默认标签”列出 legacy 候选，只有目标文章 commit 才清除；不做无界全库猜删。若 `tags_json` 在 `manually_edited_fields` 中则完全不改，即使内容使用 `force` 重译也不覆盖。

自动 `ArticleHorseLink` 只依据同一解析结果创建/更新。显式文章 commit 会删除不再命中的旧 `AUTO/CANDIDATE` 关联，再写入当前自动结果；既有 `MANUAL` 与 `REMOVED` 始终保持不变。dry-run 必须分别列出待新增、待更新、待删除和受保护关联。

### 6. 自动马匹关联按已接受实体反查候选 Profile，不做笛卡尔扫描

文章级解析结果携带正式 `term_id`、外部 horse ID 和实际命中文本。关联服务先用这些稳定身份或规范化文本一次查询可能的已发布 `HorseProfile`，再对小候选集决定 `AUTO/CANDIDATE`；不得继续为显式文章遍历全部已发布马匹。批量文章解析按语言预加载相关术语/alias，英文 alias 也使用文章候选 key 过滤，测试以 20 篇批次的实体解析查询数不随文章数线性增长为门禁。

### 7. 历史修复显式、可审计且不自动发布

新增或扩展管理命令，只接受重复 `--article-id`，默认输出翻译术语、实体类型、机器标签 provenance、自动关联新增/更新/删除及前后差异；`--commit` 才写回机器元数据/标签/自动关联，重译必须另有显式同步强制参数。每篇 commit 使用独立事务：单篇失败回滚该篇并继续或明确报告其他篇结果，不得留下标签已改但关联未改的部分状态。公开文章保持 ID、`workflow_status`、`published_to_web_at` 和 QQ delivery 不变。人工锁定字段和人工/移除关联不得覆盖。

## Risks / Trade-offs

- [保守人物规则可能漏掉没有职业动词的新人名] → 未确认实体保持原文交给翻译模型，不把其升级为马名；后续可按真实样本扩充人物证据。
- [强马名上下文仍可能把同形普通词升级] → 输出证据和冲突标记，发布门禁可发现正文/标签不一致；用文章 8086、8318、8330 建立负样本。
- [日文完整 token 启发式可能保护普通片假名短语] → 只在强马名语境或内部存在马名/冠名证据时启用，并保留现有普通词过滤。
- [旧文章没有机器标签 provenance，重算可能误删同名业务标签] → 目标文章 dry-run 显式列出 legacy 候选并排除来源默认标签；新结果写入 provenance，人工锁定标签完全跳过，不执行无界全库清理。
- [自动关联清理误删人工决定] → 只删除目标文章中状态为 `AUTO/CANDIDATE` 且当前实体不再命中的关联，`MANUAL/REMOVED` 永不删除或改写。
- [文章级解析增加查询与 CPU] → 支持批量预加载，排序与跨度仲裁均为确定性内存操作；完整测试与生产小批 dry-run 检查查询规模。

## Migration Plan

1. 先以生产问题文本制作最小 fixture/模型样本，证明旧实现会误识别或拆分，并锁定查询数、人工保护和零发布/QQ 副作用门槛。
2. 实现统一解析器、跨度保护及消费点接入，运行目标测试、完整 `stable`、Django check、迁移漂移和多轮 review。
3. 部署前停止 beat、排空 worker、确认外部导入与历史写入窗口、备份 `.env` 和 PostgreSQL；从已 review 的精确提交构建可复现镜像。
4. 部署后先对指定文章执行实体/标签 dry-run，逐篇核对人物、马名、普通词和完整未知马名，再显式 commit、重译及重算自动关联。
5. 保持公开状态/发布时间与 QQ 幂等，逐篇检查后台和公开页；随机抽取新英文、日文文章回归。
6. 回滚先停 beat 并排空 worker，恢复旧镜像；本变更预计无迁移。仅确认数据写坏时恢复部署前数据库，或根据操作日志回写单篇旧字段。

## Open Questions
