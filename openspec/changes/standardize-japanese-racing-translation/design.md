## Context

当前翻译链路已先执行文章级实体解析，再为未知完整马名和人物术语创建占位符，调用模型后恢复占位符并保存 `TranslationRun` 元数据。这能保护马名，但不能稳定处理拍卖会产驹、追切时间、赛后采访署名和出马表骑手未定等结构化片段；模型也会忽略没有进入术语表的普通片假名词。

生产只读样本确认问题集中在 `8304/8299/8298/8291/8290/8288/8287/8283/8276/8219/8212`。现有术语库没有 `社台/Shadai`、`ノーザンホースパーク/Northern Horse Park`、`セレクトセール` 及本批普通片假名词条。改动必须复用 Django 单体、现有翻译提供方、文章级实体解析和同步重译命令。显式 `--force` 会按既有语义更新目标中文内容，但不得清除 `manually_edited_fields` 记录，也不得改变公开状态、发布时间或 QQ delivery。

## Goals / Non-Goals

**Goals:**

- 让常见日文赛马普通词进入术语提示并稳定翻译，同时明确它们不是马名。
- 在模型调用前保护结构化片段，在模型调用后确定性恢复为约定中文格式。
- 让产驹中的已知马名使用术语中文名，未知马名保留完整原文。
- 为新增日英中术语建立可审计、幂等、冲突即失败的数据迁移。
- 复用现有同步强制重译能力安全修复指定生产文章，并验证随机新文章。

**Non-Goals:**

- 不建立通用日语分词器，不试图穷举全部外来语。
- 不改变翻译模型、供应商、自动发布阈值、发布配额或 QQ 推送规则。
- 不为拍卖会 lot 建立新数据模型，也不把产驹名称自动写入正式马匹资料。
- 不全库重译历史文章，只处理显式 ID 和最终抽检样本。

## Decisions

### 1. 在现有翻译服务内引入纯函数式日文格式计划

新增独立服务模块，输入日文标题、正文和既有 `ArticleEntityResolution`，输出受保护文本、格式占位符到最终中文片段的映射，以及命中规则元数据。它只在 `source_language=ja` 时运行，不访问网络、不写数据库。

格式计划先于未知马名和人物术语占位执行，避免 `「プティフォリーの2025」` 被整体保护后无法去掉 `の`。计划同时记录被整段消费的源 span/实体；后续未知马名占位和缺失检查必须排除这些实体，由格式目标自身负责逐字保留未知母马或父马。模型返回后继续执行既有上下文术语映射，再恢复马名/人物占位符和格式占位符。替代方案是只扩充 prompt，但生产样本已证明模型自由输出不能稳定满足精确格式。

### 2. 结构规则使用窄上下文和整段占位符

- 拍卖 lot 只匹配日文引号内的 `<母马>の<四位年份>`；性别括号可位于引号内或引号后，父马字段可带或不带既有 `父` 前缀，恢复时不得生成重复的“父父”。`「コッパの2026(牡)」` 固定输出为 `「コッパ2026」（公马）`。格式计划使用字段内绝对 span 查找与母马/父马组件边界精确一致的文章级实体；只有该精确实体拥有已接受中文目标时才使用中文，否则逐字保留组件原文。禁止对组件再次调用全局术语替换，避免文章其他位置接受的父马、冠名或短词拆开完整未知马名。
- 追切只匹配 `<距离>ハロン<总秒数>―<末段秒数>` 的完整计时形态，输出 `<距离>F <总秒数>，末脚 <末段秒数>`。
- 赛后采访只匹配行首或段首的 `<骑手>騎手(<马名>＝<名次>着)`，输出 `<骑手>骑手(<名次>着 <马名>)`。
- 出马表只把“行末独立 `○○`”替换为“骑手未定”；说明句中的 `○○` 保持符号并正常翻译。

窄匹配优先于对译文做全局正则替换，可避免正文中的年份、秒数、等号或圆圈符号被误改。

### 3. 格式占位符属于必需输出并进入翻译审计

格式占位符采用独立命名空间 `__UMA_FORMAT_n__`。每个占位符记录来源字段；标题占位符必须出现在 `title_zh`，正文占位符必须出现在 `body_zh`，摘要不参与替代检查。prompt 要求原样复制；若模型漏掉任一必需占位符，沿用现有重试机制，最终仍缺失则抛出 `TranslationResponseError`，不得静默接受半格式译文。`TranslationRun.raw_response` 记录规则名、字段、源片段、目标片段和占位符，便于生产逐篇复核。

### 4. 普通词与机构概念通过数据迁移进入现有术语模型

新增无 schema 变化的 `RunPython` 数据迁移：

- 普通词以 `fixed_phrase` 保存并带 `non_horse_common_word` 标记，覆盖 `レコード=记录`、`セレクトセール=精选拍卖会`、`セール=拍卖会`、`セッション=场次`、`スピード=速度`、`タイプ=类型`、`コーナー=弯道`、`ペース=步速`、`オープン=公开级`、`スムーズ=顺畅`、`トップハンデ=最高负磅`、`ハイペース=快步速`、`スパイク=钉鞋`；同时在 prompt 明确“非占位符且非已接受专名的普通片假名必须翻译”，避免只靠有限词表。
- `社台` 与英文别名 `Shadai` 归入一个日本机构概念，中文为“社台”。
- `ノーザンホースパーク` 与英文别名 `Northern Horse Park` 归入一个日本机构概念，中文为“北方马公园”。

迁移按术语类型、语言和原文/`TermAlias` 大小写不敏感地幂等查找；若既有概念指向不同中文或别名已属于另一概念，迁移明确失败，禁止静默覆盖人工数据。反向迁移不删除已进入运营使用的术语数据；代码回滚保留这些无害词条。替代方案是生产 shell 或后台手工录入，但不可复现且容易漏掉跨语言别名。

### 5. 生产修复复用现有同步重译与副作用门禁

不新增批量重译命令。部署后先记录 11 篇文章的状态、发布时间、`manually_edited_fields` 标记和 QQ 次数，再用既有 `translate_news --sync --force --article-id ...` 小批重译，逐篇执行发布校验并比对身份快照。目标中文字段被更新是本操作的预期；人工编辑标记本身必须保持。随机抽取近期日文新文章验证普通词、格式和未知马名；不允许借本 change 扩大到全库重译。

## Risks / Trade-offs

- [结构正则误命中普通文本] → 仅在日文来源和窄结构上下文运行，并为相似非目标文本编写负例。
- [模型删除格式占位符] → 必需占位符检查、一次重试及最终显式失败；元数据保留失败详情。
- [术语迁移与生产人工词条冲突] → 迁移前 dry-run 查询，迁移冲突即失败，部署停止并由人工处理，不覆盖数据。
- [已发布文章重译产生重复发布或 QQ] → 复用同步重译路径并做前后身份快照；任何状态、时间或 delivery 变化均为阻断。
- [普通词译法在个别上下文不自然] → 词条只向模型提供强制术语提示，结构片段才做确定性输出；随机新文章用于检查自然度。

## Migration Plan

1. 在测试数据库验证数据迁移首次执行、重复语义、别名冲突和保留式回滚。
2. 完成完整回归和零问题 review 后，从精确提交构建 AMD64 候选镜像并验证迁移/check/目标测试。
3. 协调空闲生产写入窗口，暂停 beat、排空 worker，备份 `.env` 与 PostgreSQL 并验证恢复清单。
4. 部署 web，执行迁移并核对术语/别名；再依次恢复 worker、beat。
5. 对 11 篇显式文章执行小批同步重译与校验，确认公开状态、发布时间及 QQ 幂等不变。
6. 抽取近期新日文文章回归，记录 HTTP、队列、日志和容器镜像证据。
7. 回滚代码时保留新增术语数据；若翻译结果有问题，从备份恢复前先优先用旧镜像重新重译目标文章，只有确认数据库损坏才恢复数据库。

无。用户已明确目标格式、术语中文名、未知马名保留和上线验收范围。
