## Context

当前英文门禁通过 `TermEntry` 找到原文术语，再检查中文发布稿是否保留译名、原文或 alias。已有语义分类能够把配置中的高歧义词降为普通词，但分类优先相信 `term_type`：赛事、骑师、练马师直接视为专名，未进入普通词种子的 `horse` 也直接走 `horse_term_without_common_seed`。因此，合法存在于术语库中的单词型马名一旦在普通语法位置出现，仍会误触发 blocker。

生产近 7 天有 320 篇英文稿；101 篇命中已知高歧义词，36 篇的已存 blocker 全部来自这类词。这 36 篇均已翻译、评分不低于 75、没有重复标记。现有重处理命令会为每篇候选重复执行高成本术语扫描，生产 `--limit 5` 仍长时间占用单核，无法承担上线验收和历史恢复。

本变更同时影响术语匹配、门禁判定、管理命令和生产恢复，需要保证 PostgreSQL/SQLite 一致、dry-run/commit 一致、真实专名不被误放行，并保持当前 Django/Celery/Redis 架构。

## Goals / Non-Goals

**Goals:**

- 在不删除合法单词型马名的前提下，对每一次英文命中分别判断 `proper_noun / common_word / uncertain`。
- 同一词在同一篇文章中作为马名和普通词出现时，只保护真实马名用法。
- 高置信普通词不阻断；真实核心实体继续阻断；不确定命中按标题/导语与正文位置分层。
- 建立有界、可续跑、互斥且可观测的重处理流程，生产等价环境 100 篇 dry-run 在 60 秒内完成。
- 让历史候选恢复继续经过完整门禁、发布窗口、去重、配额和 QQ 资格。

**Non-Goals:**

- 不删除、停用或批量改写单词型正式马名和 alias。
- 不取消 `core_term_missing`，不放松正文、翻译、URL、重复内容和人工终态门禁。
- 不为每个术语命中调用外部大模型，也不新增常驻分类服务。
- 不改变新闻来源、抓取频率、评分阈值、地区发布上限、QQ 规则或多地区归属开关。
- 不在重处理命令中直接公开历史文章。

## Decisions

### 1. 分类单位采用“命中实例”，不是 `TermEntry`

新增不可变的命中实例结构，至少包含 term/alias ID、实际命中文本、字符跨度、所在字段、句子、前后 token、标题/导语/正文位置、地区和结构化实体证据。分类结果绑定命中实例，而不是写回 `TermEntry`。

原因：`Brilliant was brilliant at Sha Tin` 中两个 `brilliant` 必须得到不同结论。把术语永久标成普通词会破坏真实同名马，把整个术语永久标成专名则继续误挡。

备选方案是维护更大的普通词黑名单；该方案只能止血，不能处理同词双重用法，因此不作为最终判定。

### 2. 先检查可接受保留形式，再做高成本分类

若中文稿已包含正式译名、当前实际命中文本、同语言 alias 或规范化等价写法，该术语直接视为已保留，不再进入上下文分类。地区不匹配的术语继续先按现有地区规则排除。

原因：已经保留的词不可能造成 `core_term_missing`，提前返回同时降低误判和运行成本。

### 3. 使用可解释的分层信号，而不是仅信任 `term_type`

分类顺序：

1. 结构化强实体证据：参赛/赛果行、马匹国别后缀、已知参赛记录、骑师/练马师/档位/负磅/赔率关系。
2. 强赛马语法关系：候选词作为 `won / finished / runs / ridden by / trained by` 等谓词的实体参数，或出现在明确马匹名单结构中。
3. 强普通语法关系：冠词、助动词、介词、形容词/副词位置和仓库内可审核固定搭配，例如 `a brilliant winner`、`something around his head`、`yet to win`、`posed a threat`。
4. 弱信号：大小写、标题位置、出现次数和来源地区。英文标题首字母大写不得单独构成专名证据。
5. 仍冲突或证据不足时返回 `uncertain`，不得伪造高置信结论。

真实赛事、骑师、练马师类型仍是强先验，但不跳过实际匹配边界和保留形式；单词型 `horse` 只作为先验之一，不再直接等同 `proper_noun`。

### 4. 按命中位置和文章重要性处理 uncertain

- 标题、摘要或首段中的 uncertain 核心命中：保留 blocker 或转人工。
- 正文背景位置的 uncertain 命中：记录 warning，不单独阻断。
- 任一命中实例被高置信判为真实核心专名且译文未保留：继续生成 blocker。
- 同一术语同时有普通词与专名命中：只以专名命中生成保留校验；普通词实例写入审计 details。

这延续现有“核心术语与背景术语分层”原则，在减少误挡的同时保护标题主角。

### 5. 首版分类器完全本地、确定性且可批量复用

实现一个纯函数式上下文分类服务，输入命中实例和预构建证据，输出分类、置信度、原因码和证据摘要。首版不调用外部 AI；如果未来真实样本证明规则无法覆盖，再单独 change 评估小模型或批量模型调用。

固定搭配和信号规则放在可 review 的代码/配置中，测试必须覆盖正反例。审计 payload 不保存整篇正文，只保存有界句子片段和必要 token。

分类输入只使用标题和清洗后的可见正文。不得从 `original_content_html`、HTML 属性、脚本、样式、导航、推荐卡片或嵌入元数据中提取命中；`body_ja_normalized` 中残留的标签和样板文本也必须在匹配前清理。这样可避免 `title=` 等页面结构被误判为马名。

### 6. 术语匹配建立一次有界索引

为一次校验批次按语言和有效地区构建 `ValidationBatchContext`。它至少包含 `EnglishTermMatchIndex`、规范化术语/alias 快照、批量预取的结构化实体证据，以及一次加载的重复检测候选语料。术语 alias 按首 token/首字符分桶并预编译边界匹配；文章只检查可能命中的桶，不逐篇遍历全部术语，也不逐篇重新查询马匹 alias 或最多 80 篇重复候选。

自然新稿仍走同一个 `validate_rewrite()` 服务；单篇调用构建短生命周期上下文，重处理命令显式复用批次上下文。首版不做跨进程长期索引缓存，避免术语变更后的陈旧缓存。术语快照版本使用所有有效相关 `TermEntry` 与 `TermAlias` 关键字段的规范化排序 SHA-256，而不是仅使用最大更新时间。

不引入新的第三方搜索依赖；先用现有 Python/Django 能力实现并通过查询数、CPU 和内存基准验证。若仍无法达到 100 篇/60 秒，再单独评估 Aho-Corasick 等依赖。

### 7. 重处理采用两阶段有界读取

第一阶段只读取候选 ID、`gate_issues`、时间、地区、来源和终态字段，以 `(first_seen_at, id)` 稳定排序；应用地区、来源、固定绝对时间窗口、复合 continuation cursor、`--limit` 和当前 `core_term_missing` 条件。第二阶段仅批量加载选中的完整文章，并复用一次 `ValidationBatchContext`。首次运行固定 `window_start/window_end`，游标必须同时编码窗口、时间和 ID，不能使用与排序字段不一致的单独 `--after-id`，续跑也不得重新按当前时间计算 lookback。

命令增加：

- `--cursor`，编码首次固定的 `window_start/window_end` 及上一条的 `first_seen_at/id`，并校验格式和选择器一致性。
- `--max-seconds`，到期后安全停止并输出下一游标。
- 基于数据库单例锁行的全局租约；事务内 `select_for_update()` 认领，执行中续租，只有租约过期才能接管，完成/失败均保留运行记录。首版一次只允许一个重处理批次，避免不同地区批次同时争用生产 CPU。
- 扫描数、候选数、完成数、普通词降级数、专名 blocker 数、耗时、峰值批次大小、停止原因和下一游标。

默认不允许无 `--limit`、无时间范围的生产式全量运行。

### 8. 使用数据库运行账本连接 dry-run 与 commit

新增 `TermGateReprocessRun` 与单例 `TermGateReprocessLock`（名称可等价）及 migration。Run 保存模式、选择器、状态、复合游标、规则版本、规范化术语快照 SHA、候选 ID、每篇输入指纹、结果摘要、结果 manifest SHA、统计、错误和时间戳；Lock 使用固定唯一 key 保存当前 run、owner token、租约到期和心跳。它复用现有 `ExternalDataImportRun + ExternalDataImportLock` 与 `ProductionWindow` 的数据库租约思路，但作为独立运行域，不把重处理伪装成发布窗口。Django Admin 只读展示运行状态、失败原因、统计和续跑入口信息，并禁用新增、编辑、删除和直接发布动作。

dry-run 在数据库中持久保存完整的有界审核结果，可选择导出 JSON，但容器文件不是事实来源。文章输入指纹至少覆盖源文本、发布文本、工作流/自动化状态、门禁字段、发布时间和 `updated_at`；全局指纹绑定规则版本、相关设置和完整术语/alias 快照。commit 必须显式引用 dry-run run ID 与 manifest SHA。全局指纹漂移时整批拒绝；单篇文章漂移时跳过该篇并报告，不覆盖新状态。

commit 重新使用相同批次服务验证未漂移文章，并核对结果摘要。每个写入批次使用 `transaction.atomic()` 和 `select_for_update()` 锁定运行记录及文章；门禁结果、`AutomationLog`、状态和 `ranked_revived_at` 在同一事务中更新。异常时整批回滚并把运行记录标为失败。commit 不设置 `published_to_web_at`，不创建 QQ delivery，重复提交同一运行记录保持幂等。

### 9. 灰度只有一个互斥模式

新增 `ENGLISH_TERM_CONTEXT_MODE=off|shadow|enforce`（最终变量名可遵循现有前缀），默认 `off`。`off` 完全沿用旧判定；`shadow` 计算并记录新分类但旧门禁仍决定文章状态，且不得修改门禁/工作流状态；`enforce` 才让新分类决定门禁。部署后先 shadow 至少 24 小时，人工抽检通过后再切 enforce，避免多个布尔开关形成非法组合。

shadow 与 enforce 复用稳定 issue code：高置信普通词继续使用现有 `english_term_common_word_downgraded`，真实或核心 uncertain 缺失继续使用 `core_term_missing` 并在 payload 标注语义，背景 uncertain 使用现有 `background_term_missing` warning。shadow 差异写入有界 `AutomationLog` validation payload，不修改文章门禁和工作流字段。监控和历史统计不依赖自然语言 reason。

### 10. 产量预估按“可恢复候选”而非“必然发布”表达

生产样本中 36 篇候选构成历史上限，平均 5.1 篇/天；全部评分不低于 75 且无重复。由于未来文本分布、uncertain 保守策略、窗口去重和配额仍会生效，正式目标设为稳态每天新增公开 2-5 篇，中位 3-4 篇。上线验收同时报告“blocker 清除”“恢复为候选”“最终公开”三层数量，禁止把 dry-run 通过数直接宣称为发布增量。

## Risks / Trade-offs

- [普通词上下文规则误放真实马名] → 标题/导语 uncertain 保守阻断，真实参赛和关系证据优先，建立双重用法和单词型真实马名回归集。
- [规则过于保守，产量提升不足] → 分开统计 common/uncertain/proper，使用生产抽样逐步补规则，不通过删除术语追求数字。
- [上下文片段缺失，旧文章无法可靠分类] → 缺少句子或命中跨度时返回 uncertain；历史无上下文数据不得自动放行。
- [术语或文章在 dry-run 后变化] → 使用规范化术语快照、规则/设置版本和逐篇输入指纹；全局漂移拒绝 commit，单篇漂移跳过并报告。
- [进程崩溃导致锁永久占用或并发接管] → 数据库租约定期续租，过期后才允许事务化接管，owner token 防止旧进程释放新租约。
- [重处理再次拖高生产 CPU] → 强制 limit/时间边界、互斥、max-seconds、隔离环境基准和生产逐地区单批运行；未达 100 篇/60 秒不得上线 commit。
- [运行结果随容器重建丢失] → 数据库是 dry-run/commit 审核事实来源，JSON 只作可选导出，不依赖未挂载的 runtime 目录。
- [36 篇历史估算高于最终公开] → 文档和后台分开显示恢复候选与最终发布，接受窗口去重、配额和后续 blocker 带来的折损。

## Migration Plan

1. 新增运行账本模型、migration、只读 Admin、命中实例、分类器、批次上下文和回归测试；模式默认 `off`，不改变生产结果。
2. 在生产等价数据副本执行 100 篇性能基准，确认总耗时、查询数和峰值 RSS 有界；未达门槛不得开启 enforce 或历史 commit。
3. 部署并迁移数据库，确认生产 HEAD、容器环境中的 mode、迁移状态、健康检查和日志；保持 `off` 后切 `shadow`。
4. shadow 至少 24 小时，抽检普通词、真实单词型马名和 uncertain；通过后切 `enforce`，继续观察自然新稿。
5. 对香港、英国、法国、美国分别创建小批量 dry-run 运行记录，审核 run ID 与 manifest SHA 后再小批量 commit，使其重新进入发布窗口。
6. 若误放行升高，将模式切回 `off`；数据库运行记录和审计结果保留，历史文章不因代码回滚自动改变状态。代码回滚前必须确认 migration 兼容，默认采用向前修复而非删除账本表。
