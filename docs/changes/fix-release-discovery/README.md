# 发布版本标记与赛事发现诊断

## 范围

这是两项小型修复：准确报告发布版本，并解释现有赛事发现为什么未命中。
不增加第三方请求、原始响应存储、数据库迁移或自动化开关，不放宽赛事身份匹配。

## 实现

Docker 构建将已有 `UMANEWS_RELEASE_COMMIT` build arg 写入 `/app/.umanews-release-commit`。
Django 设置优先读取该文件，使旧 `.env` 无法影响应用的运行审计版本；源码运行且文件不存在时
保留原有环境变量回退。空值或无效镜像标记不回退为环境中的另一个版本，原有调用方的版本
校验仍会拒绝它；读取权限等错误直接暴露。共享 Compose 和各发布/重建入口不变，容器重新创建
仍读取自身镜像版本。Docker 原始环境变量与应用有效设置应区分，`.env` 字节保持不变。

赛事发现结果新增 `diagnostic_buckets`，沿用任务结果的现有序列化路径。每个成功解析的
地区/日期请求记录 provider、region、day、响应 SHA256、响应赛事数和 `match_reason_counts`。
只对未命中或多解记录 event ID、原因及逐级候选数；每次调用最多 50 条事件样本，
超出部分计入各桶 `omitted_event_count`，原因汇总仍完整。后续请求失败时保留已完成桶。
不记录响应正文、凭据、马匹信息或候选名称。

`match_counts` 是按既有过滤顺序累计的候选数：`response` → `valid_time` → `region`
→ `local_date` → `course` → `name`。首次归零的位置解释未匹配原因；多条最终候选仍为
`racecard_ambiguous`。桶中的 `matched` 仅表示候选唯一命中，后续身份冲突仍由原有流程拒绝，
不等于身份已成功创建。没有额外请求去补齐诊断；请求或解析失败仍使用原有失败原因。

## 验证与恢复

- 测试覆盖镜像版本优先级、环境缺失、源码回退、无效标记和读取错误；交付前以实际构建镜像核对文件、标签和 Django 设置一致性。
- 使用合成响应覆盖空列表、地区/日期/场地/名称不匹配、唯一命中、多解、样本上限及部分请求失败。
- 断言请求次数、身份创建行为、分区计数守恒和响应正文不外泄。
- 赛事测试使用隔离数据库，镜像构建验证和现有回归检查单独记录，不能以本地单元测试代替。
- 交付依根 `AGENTS.md`。迁移文件不变；恢复沿用同一候选、备份和发布意图，普通代码 rollback
  仍按既有 0078 合同处理。本修复不新增数据库修复或历史稿件处理动作。
