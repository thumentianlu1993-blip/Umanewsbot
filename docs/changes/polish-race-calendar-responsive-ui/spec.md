## 问题陈述

赛事日历日期轴和左侧时间线日期目前都只输出两位日号，例如 `24 / 28 / 01 / 04`。当窗口跨月
或跨年时，用户必须从顺序猜测月份和年份。

全局 `.grade-badge` 原本以 `flex: 0 0 42px` 提供 `42px` basis，但移动端日历规则把
`.cal-card .grade-badge` 改为 `flex: 0 0 auto`，同时徽标没有显式 `width/min-width`。因此日历
卡片中的 G1/G2/G3 宽度退化为文字固有宽度，空等级宽度退化为零；长标题占用剩余空间时问题更明显。

## 范围

### R1：每个有日期的导航项都明确显示月份

- 日期轴中的每个有日期项都显示真实 `local_date` 的“月 + 日”，不能只显示日号。
- 同一月份的连续日期也各自显示月份，用户不需要向前寻找分组标题。
- 星期信息继续显示，今天继续显示“今天”。
- 日期轴仍是横向可滚动的紧凑导航；增加月份后不能缩小点击区域或造成页面级横向溢出。
- 日期锚点、筛选、年份、搜索、过去/未来 cursor 和事件详情 URL 不变。

### R2：跨月与跨年没有歧义

- 例如 2026-07-28 与 2026-08-01 必须分别显示为 `7月28日` 与 `8月1日`。
- 当当前渲染结果包含多个自然年时，每个有日期项都同时显示自己的年份，例如
  `2026年 12月31日` 与 `2027年 1月1日`；不得只给跨年后的第一项加年份。
- 年份只由当前结果集中的 `local_date.year` 动态决定，不读取或写死服务器当前月份/年份。
- 无日期赛事继续显示“日期待定”，不伪造月、日或年份。

### R3：现有日期状态继续可辨认

- `today` 状态、今天下划线和时间线强调继续有效。
- 每个日期轴项的“有赛事”金色圆点继续存在。
- 本周重点 G1 继续由独立焦点条表达，不把普通日期误标为重点日期。
- 日期轴锚点仍指向对应 `agenda-day`；目标日期组应有可辨认的选中/定位反馈，且不改变 URL 查询参数。

### R4：移动端等级徽标保持稳定尺寸

- G1、G2、G3、JPN1/JPN2/JPN3、JG1/JG2/JG3 在移动端日历卡片中保持 `42px × 42px`。
- 徽标在同一列表和不同卡片中宽高一致，`flex-shrink` 为零，不能被标题或状态区挤压。
- 文字水平、垂直居中；JPN1 等四字符正式等级必须在固定框内清楚显示。
- 桌面端继续使用同一 `42px × 42px` 视觉尺寸。

### R5：长标题与未知等级回退

- 标题容器负责消费剩余宽度，中文、带空格英文和异常长连续文本可以换行；不得反向压缩徽标。
- `grade_badge_label` 现有最多四字符契约保持不变，不扩展赛事数据模型。
- 非 G1/G2/G3 系列的最多四字符标签使用中性徽标和受控的最多两行居中排版；四个全角字符
  也必须完整留在固定方框内，不能靠裁切或溢出伪装通过。
- 空等级仍渲染中性 `42px × 42px` 占位徽标，并以破折号表达缺失，不能塌为 `0px`。
- 不根据单个赛事名称、单个等级或当前月份写特例。

### R6：共用组件一致性

- `.grade-badge` 同时用于首页近期赛事、赛事日历、赛事详情和新闻详情赛事预告。
- 稳定尺寸与未知/空等级回退放在共用 `.grade-badge` 契约中；日历移动端不得再覆盖成内容宽度。
- 不重构整个 `public.css`，不改变各页面的赛事数据、等级归一化或状态逻辑。

## 非目标

- 年龄、距离、场地、马场等术语归一化；
- 赛事状态、出马表、赛果抓取或数据补采；
- 首页“今日赛事/近期赛事”产品文案；
- 数据库字段、迁移或生产数据写入；
- 新闻正文提取、英文马名识别、新闻来源展示、新闻地区 Tab；
- 马匹首页国家/地区 Tab；
- 整体赛事日历视觉重设计、前端框架或 JavaScript 状态系统。

## 验收标准

1. 同月、跨月和跨年样本均能直接识别年月日；星期正确。
2. 今天、有赛事、本周焦点和日期锚点状态不退化。
3. 390px 下 G1、G2、G3、JPN1 及中性回退徽标均为 `42px × 42px`。
4. 空等级不塌陷；未知四字符等级（包含四个全角字符）不溢出、不裁切。
5. 长赛事名称换行后徽标尺寸和多卡对齐保持不变。
6. 1440px、390px 以及必要的 375px/320px 页面无横向溢出。
7. 首页近期赛事、赛事日历、赛事详情和新闻赛事预告的共用徽标没有回归。
8. 日期 URL、筛选、搜索、cursor、详情链接和查询数量边界保持不变。
9. 无模型、迁移、赛事数据、新闻链路或马匹链路变更。
