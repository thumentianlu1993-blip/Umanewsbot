## G2 发布包内容

最终精确候选 commit / PR head 在交付消息绑定；以下动作只针对该候选，按根 AGENTS.md 交付。

- 无新增模型或迁移文件；同 schema 发布，核对实际 migration leaf 和空迁移计划。
- 在独立固定提交目录/镜像构建，不修改其他线程部署工作树。保留当前镜像 digest、完整 Compose 链、配置哈希与服务运行意图作为恢复面。
- 在现有完整 Compose 链之后追加本包覆盖：四应用统一候选镜像，新增 `race_control_worker`、`race_realtime_worker`。
  新服务从**最终解析后的** `race_sync_v2_worker` 继承环境、全部数据挂载、网络及浏览器接入，覆盖 command、CPU、memory 和 shares；不能只继承基础 yml 的默认值。
- 控制 worker 0.25 CPU / 384 MiB；临场 worker 0.5 CPU / 384 MiB，单并发、单预取，shares 2048。普通新闻和广域发现仍使用原 worker。
- 停 Beat、排空所有已运行 worker；不删除队列或撤销消息。按现行唯一发布协调器重建 Web、普通 worker、原赛事 worker，启动两个新 worker，确认消费者就绪后恢复 Beat；Nginx检查并重新加载上游。
- 配置行为变化：控制队列隔离、Redis 重试消息 priority 0 / 普通临场 priority 3；删除周日两条 rush；有效未确认赛果 claim 免内部每日请求/字节上限，继续记账并受第三方退避与磁盘保护；冠军证据推进完赛。
- 不扩大来源、赛事覆盖或权限；不启动旧 race-live，不改变 QQ/邮件/通知开关，不手动外发。无历史批量状态修复、无旧 pending revision 清理、无整库回填。自然调度按现有已纳管范围运行并写入观测、状态和正式结果。
- 备份：现行协调器生成并校验本次数据库备份/TOC，保存前后配置和镜像身份；生产数据写入只来自本包明确的自然赛事任务。

## 验证与回退

发布前先核对资源、在途发布/导入、当前镜像与完整配置链；不满足时停在切换前，交接发布协调者解决。
镜像/配置与获准版本漂移按根 AGENTS.md 处理。

验收须区分服务健康和业务完成：两个消费者的 active_queues/并发/版本正确；Beat 三条赛事控制任务进入独立队列，失败后 fresh claim 带优先级；原新闻计划继续、周日 rush 消失；检查点和观测推进；部分冠军只改状态，完整结果通过原发布校验；公网日历/详情状态一致。没有当期部分赛果时，以隔离回放证明该分支，不能把完整赛果现场验收冒充部分赛果现场验收。

失败时先停 Beat 并排空新 worker，保存故障证据和期间自然产生的数据。若未发生 schema 变化且当前基线仍与上述固定身份相同，使用发布包保存的完整旧 Compose 链及旧镜像恢复四应用，停止两个新 worker，再恢复原 Beat。新队列剩余消息保留，过期 claim 在重新部署后拒绝写入；不得清空 Redis。旧版会恢复旧时间状态规则，须明确报告该行为回退。

通用 `rollback.sh` 没有本包获准目标，不能借其绕过当前 schema/恢复合同。若实际 schema 或共享生产边界已变化，停止自动回退，保留现场并准备前向修复；不以整库恢复覆盖期间正确赛果。
