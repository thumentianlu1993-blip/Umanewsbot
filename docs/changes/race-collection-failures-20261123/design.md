# 设计与边界

复用现有 Django/Celery 及私有原件根目录。新增 `RaceEventLiveProviderCheckpoint.failure_diagnostic` JSON 字段，保留数据库级 `{}` 默认值以兼容回滚后旧镜像省略该列的 INSERT，赛前与发现诊断使用已有 `source_refs` 对应状态。
所有数据库状态更新仍在原 claim/lease/CAS 与行锁内；过期领取者不得覆盖新任务。只增加诊断和下一次到期时间，不改变来源准入或赛果 writer。

## 分类与重试

|类别|含义|基本等待|
|---|---|---|
|not_published|明确尚未发布/未找到|1 分钟|
|incomplete|完整性门禁未通过；不能据此断言源站只是更新慢|2 分钟|
|waiting|锁、预算或本地配额等待|1 分钟|
|network|超时、传输失败、429/5xx|5 分钟开始指数退避，上限 60 分钟|
|access|401/403/406、访问限制|60 分钟|
|identity|身份冲突或歧义|60 分钟|
|configuration|路由、配置、权限不可用|60 分钟|
|parser|未知状态、格式与其他无法解释的问题|15 分钟开始，上限 180 分钟|

实际重试取原有节奏、来源 Retry-After、现有每日配额等待和分类退避中的最晚时间，不增加网络压力。
相同内容的解析故障再次出现至少等待 60 分钟。仅前三类不累计 `consecutive_failures`；仍保留错误原因、观测次数和下一次尝试时间，且不更新 `last_success_at`。
发现任务按来源 route digest 分别保存 `retry_not_before`；健康来源的成功不清除其他来源的等待时间。所有来源都在退避时，事件等待最早可用来源且不早于原有节奏。
同一错误、解析器版本和内容摘要构成指纹。成功保留最近失败诊断并标记恢复时间，便于查阅恢复前现场。

## 原件

任务范围内的上下文捕获既有共享快照响应；每次领取/每条发现路由重置，任务结束自动清空。快照缓存命中同样捕获，后续快照替换不影响独立失败原件。
单次最多 12 份、16 MiB，超额保留缺失计数。`failures/` 下按 SHA 去重，目录 0700、文件 0600，使用不跟随符号链接的目录描述符和短时文件锁。
文件池最多 128 份/256 MiB；写入时清理超过 7 天的记录，再按最旧记录淘汰至容量内。没有新失败时不会主动扫描该目录。元数据引用可能指向已淘汰文件，检查原件必须重新校验存在性和 SHA。
新文件写入还遵守既有 `RACE_DATA_RAW_MIN_FREE_DISK_BYTES` 磁盘余量下限，余量不足时保留已有证据并记录 `disk_low`。
存储不可用时不掩盖原始采集失败，也不影响失败 claim 正常释放；诊断标记原件未留存。
