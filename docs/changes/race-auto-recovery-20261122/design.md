# 根因与自动恢复设计

## 已核现场

2026-11-22 只读诊断：生产应用仍为 da74e11d。福岛纪念 127 已超过赛时十小时，JRA官方有赛果，结果checkpoint连续失败为jra_roster_partial；英国21005缺少来源/登记；法国20902/20904因source_set_drift无next_poll_at。五地区28场范围中，另五场英国赛事已有正式结果，排除全局调度停摆。

JRA原件证明出马表的退赛马号为“取消”；代码先严格解析出马表才发现结果链接，退赛行导致未尝试真实结果页。英国已缓存付费响应存在唯一Haydock候选，原名含“Steeple Chase”，既有目标键为chase；赛场别名已兼容，并非Haydock Park别名缺失。英国跨午夜后无绑定赛事又不读取日期卡表，冷启动结果还缺独立卡原件。

法国登记主策略和来源字段为旧单源策略/TRA，而有效v2 source_set和binding仍指向Geny当前策略。现场source_set与owner代次已相同；真实旧rotate还可能使owner/enrollment比旧source_set多一代，因此两种状态均覆盖。防止再发生的措施是旧census排除v2，旧rotate在持锁后拒绝v2。

## 恢复路径

- JRA仅结果抓取时允许已明确取消/除外且有马名的缺马号卡继续发现真实同场结果链接。该卡不能作为完整名单证据；结果须与原已核名单/独立名单一致，不能丢退赛行。
- 英国只在赛事名称键两侧归一Steeple Chase/Chase，日期、赛场、唯一候选、race_id约束不变。沿现有前后7天发现窗口使用既有日期卡端点；结果冷启动先补已发现race_id的独立pro卡，再验证结果。
- 自然发现取得既有due/lease后，在单事务中恢复已证实的旧策略覆盖。当前两份策略均有效；旧策略摘要/路由、旧生命周期收据、当前owner、v2 manifest哈希/代次、身份键和binding必须一致。仅同代或一次相邻旧轮转可以恢复；相邻代次只重绑原来源集合到现有owner，保留parent哈希，不重新授owner、不新增来源。
- checkpoint已被同源旧轮转改写时，须与当前旧路由精确contract/registry相同才可恢复为原v2 binding路由。未知漂移继续阻断。人工锁、暂停、过期、在途claim均保留原校验。
- 恢复增加claim/lock代次，原claim失效；普通调度器取得新claim、worker正常取数/发布，公开覆盖对账在正式赛果可见后解除原incident。恢复本身不提前解除业务告警。
- 成功/拒绝都通过已有发现状态记录last_outcomes和next_poll_at，失败不占据永久队首；租约与现有20场/轮预算不变。

## 兼容性

无模型/迁移/队列改变；配置开关、现有地区/来源、额度不变。恢复只写登记、来源集合收据、跟踪、checkpoint、发现状态和审计；正常任务仍负责名单/时间/赛果，不手工补场。回滚旧代码会失去上述恢复能力，已正确采集/公开的数据保留。
