# P02 免费地区接入实施记录（2026-10-28）

## 交付边界

用户要求继续其他地区、免费且无需会员、不绕付费墙、测试先行和独立子 Agent 评审，先不合并或部署。本轮沿用已批准的核心设计及同一分支，不开启生产抓取、公开自动化或消息发送；人工确认只引用根 `AGENTS.md`。

本轮实现地区常驻 producer、公开页面解析、同场名单核验和隔离数据库回放。来源权限、真实容量、明确更正标记和自然赛日仍需真实证据，不能把离线通过改写为 R11 全部验收或 SLA 达标；原卡百分比不变。

## 实现约束

- 新纯解析代码在 `race_regional_sources.py`；统一 `fetch_bound_observation` 进入既有身份、claim、writer、epoch 和公开读取，无第二套调度器。
- 多页组合分别保留源 URL、原始字节 SHA 和字段来源；配对不一致、缺行、重复马号、未知名次、越界日期或未许可 URL 均拒绝。缺失名单不是退赛。
- AU/DE/NAR/HK 的配对请求通常为 2，ERA 结果为 3，JCSA 结果为 2；JCSA 同时刷新赛时和名单需要额外网页元数据。发现入口及重试另计，不将此表当生产预算授权。
- 德国页面仅在严格解码前移除 HTML 注释中的无效字节；正文仍严格解码，原始 SHA 仍按完整响应字节计算。不能用忽略错误的解码悄悄丢掉马匹信息。
- 本轮没有新增自动更正判断。官方结果发生变化仍由既有冲突/更正门控处理，不能把页面重复抓取或“Official”本身当修订声明。
- 无迁移、无配置或默认开关变化、无生产数据动作。

## 验证及评审

新增地区测试先取得缺解析器、缺成熟度、缺配对、实际绑定出马表不能转赛果、重复马号、日期冲突等 RED，再完成 GREEN。测试入口是仓库 `run_bounded_stable_tests.py`，只用本机专用 PostgreSQL 55493、隔离配置、离线 fetcher；不连接第三方或生产资源。

`test_race_regional_pipeline` 用九个地区/子区子用例验证 producer → 审核身份 → claim → writer → epoch reader；沙特另有专项全链和缺行拒绝用例。历史名单、权限和容量前置被明确标记为合成，不能当真实来源能力证明。新增解析器还覆盖过期路由、类别拒绝、并列、非完赛、错日期、未知状态及部分名单。

最终批次、准确测试数与审查状态见 [regional-validation.json](regional-validation.json) 和 [regional-review.md](regional-review.md)。先前核心实现的 491 项通过是历史基线，不冒充本轮重新运行。
