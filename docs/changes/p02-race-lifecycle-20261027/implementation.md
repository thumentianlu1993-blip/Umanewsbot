## 已实现的核心

- 新增持久 PublicState、不可变 EpochPublication/Receipt、独立 Delivery。业务内容与此次授权分离；A→B→A 复用内容 revision，创建新的授权 epoch；相同内容的成熟度变化能独立发布。
- 0083–0084 保存状态与 PostgreSQL 不可变证据触发器；0085 增加 observation.acquisition_key，使同内容的不同真实领取可保留当次观测，同时同次投递幂等。旧 writer 使用空 key 保留旧去重行为。
- 名单完整性/确定语义、待确认结果、跨来源冲突隐藏、明确更正恢复；人工字段锁后的公开值来自获准 revision 快照，不从未应用候选补名。首页、日历、详情及同系列历年冠军共用 epoch 结果；已建 epoch 的赛事关闭写开关后仍执行新读边界。
- 预想名单 T−30、待确认结果 T+60 请求时隐藏；改期重算未到期截止，旧的已到期失败保留。日期赛不造 00:00；已纳入事件不再由时钟自动判开赛/完赛。延期继续及时发现；取消仅保留每日赛程恢复，明确较新来源更正可恢复。
- multisource 及时发现按重点 60 秒、其他 120 秒；首次确认后的七天窗口不被更正重置，窗口后自动赛程/名单/赛果请求均停止。无轻量索引证明时采用完整请求，完整复查已被更高频的完整请求覆盖；容量报告仍按额外复查开销保守预留。未确认超期继续发现。
- SHA/有效期/全目标/host/provider/重点额度绑定的容量清单；领取时和网络执行前/末端写入校验均复验。无真实证明不领取高频请求。既有 host ledger 继续执行实际限速，不突破已有预算。
- outbox 120秒租约、过期抢回、CAS续约/完成、失败退避、提交后唤醒和30秒周期补偿；每次只领取一个再执行，避免批量任务排队导致租约提前耗尽。公开探针验证当前 epoch、模块可见性、行标记及实际单元格，不把数据库提交当公开成功。
- ORM→F01 输入快照；冻结 scope/缺源目标义务、期限违约、外部探针修复记录、严格 R01 报告及按 epoch 的延迟测量。未知来源时钟/独立审核保持 UNKNOWN；修复不抹除历史失败。新版本义务不能被旧版本探针完成。
- 历史兼容默认只读审计，回填限定明确 ID、游标、完整 manifest 内容 SHA 和当前授权；不制造历史确认时间。新增免费来源取样证据见[来源盘点](source-inventory.md)。

## 验证方法

专用 PostgreSQL 16，`127.0.0.1:55493`，数据库/用户 `bounded_ci`，不读取 dotenv，Redis/cache/broker 用隔离替身，测试期间网络只允许此本地 PostgreSQL。通过仓库 `scripts/run_bounded_stable_tests.py` 明确选择测试，每批不超过200项。

实际 RED/GREEN 原始 JSON 保存在本地 `/tmp/p02-lifecycle-20261027/`。仓库[validation.json](validation.json)保存最终所选用例、结果文件摘要及 SHA，不引用旧部署/CI充当本次通过。

首轮独立实现 review 提出 11 项纯技术问题：公开旁路、同事实误冲突、真实重复采集、名单冲突恢复、字段锁、延期节奏、取消恢复、义务版本、七天停止、赔率字段和可见单元格。全部逐项修复并补回归；最终复审仅覆盖这些 finding 及直接影响路径，不把第三方能力缺口说成代码测试成功。

第二轮复审进一步发现 5 个直接回归：旧纠错重放绕过开关/冲突时间、确定结果被临时结果降级、乱序观测隐藏较新结果、历史 revision 授权更新后缺姓名、未知输入义务无法由确定后继履约。修复统一了公开状态写入前的新鲜度/成熟度/纠错开关校验；历史姓名仅从原 revision 的不可变观测读取；缺资料与临时资料义务允许冻结后同实体同代际的确定后继，明确版本仍精确匹配。新增 PostgreSQL 回归先复现失败再通过；同一 reviewer 的最终聚焦复审已通过，详见 [实现评审](implementation-review.md)。
