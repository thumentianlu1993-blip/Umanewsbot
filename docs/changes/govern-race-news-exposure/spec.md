# spec：赛事新闻聚类与首页 / QQ 曝光治理

## 背景与根因

2026-07-26 英皇锦标结束后，生产只读检查发现首页头条及靠前列表被同一场赛事的多篇赛果稿占据。
现有逻辑只在单个发布窗口内按正文指纹去重：

- 只识别近似相同正文，无法识别“同一赛事、不同来源或不同角度”；
- 首页头条独立选择，未计入普通列表的赛事配额；
- QQ 只按地区窗口和群级额度控制，没有赛事级终身额度；
- 文章即使已通过发布门禁，也没有“公开可访问但不进入首页 / QQ”的分发状态。

因此这不是简单调低相似度阈值可以解决的问题，需要把“内容重复”和“同一赛事曝光过密”分开治理。

## 已确认产品规则

1. 同一赛事允许保留不同角度的稿件。
2. 首页同一赛事最多展示 2 篇，头条计入这 2 篇。
3. 第一篇可信综合赛果可立即进入首页和 QQ。
4. 第二席等待约 15 分钟，从不同角度稿件中择优。
5. 后续出现更优稿件时，只允许替换首页第二席；已经发送到 QQ 的稿件不撤回、不重复发送。
6. 同一 QQ 群对同一赛事最多发送 2 篇。
7. 超出两席的文章仍可公开访问，并可出现在对应赛事详情页；不进入首页、首页分页、热门榜或 QQ。

## 范围

- 为公开新闻解析一个可靠的主赛事身份，优先使用已确认的 `ArticleRaceLink`。
- 将“硬重复”与“同赛事不同角度”分开：
  - 硬重复不取得分发席位；
  - 不同角度参与赛事级两席选择。
- 建立首页和 QQ 共用、可审计、并发安全的赛事曝光决策。
- 让头条选择、首页信息流、热门榜和 QQ 都使用相同的赛事预算。
- 记录第一席、第二席、等待、替换、抑制和跳过原因。
- 对现有公开文章提供只读盘点和经审核的历史分发状态回填方案。

## 非目标

- 不删除文章，不改变来源原文，不因首页抑制而撤销公开详情页。
- 不把同一赛事的所有稿件都标记为 `duplicate_of`。
- 不让大模型直接决定赛事身份或生产分发状态。
- 不改变地区归属、自动发布质量门禁或现有站点 / 群级总额度。
- 不自动补齐赛事名称和马名；术语统一由
  `docs/changes/unify-public-racing-terms/` 负责。

## 术语

- **硬重复**：同一来源标题相同、规范化来源标题相同，或正文指纹达到经测试确认的重复条件。
- **赛事簇**：绑定到同一 `RaceEvent.id` 的文章集合。
- **角度**：`comprehensive_result / winner / connections / runner / analysis / market / other`。
- **第一席**：首篇可信综合赛果。
- **第二席**：第一席后至少 15 分钟择优产生的不同角度稿件。

## 用户可见行为

- 首页首屏和后续分页合计的当前候选集合中，同一赛事最多出现 2 篇；头条属于其中一篇。
- 手工头条选择若会形成第三篇，系统不得产生第三席：应以手工稿占用或替换第二席，并记录审计；
  第一席不得被无声替换。
- 赛事详情页继续展示该赛事的全部公开非硬撤稿文章，并标明其角度，不受首页两席限制。
- QQ 对每个目标群、每个赛事最多创建 2 次成功发送；失败重试沿用原 delivery，不消耗新席位。
- 已发送稿件后来失去首页第二席时，不新增替代稿 QQ delivery。

## 验收标准

### 身份与失败关闭

- 只有唯一 `manual` 关联，或唯一达到既有可靠阈值且无冲突的 `auto` 关联，才能形成赛事簇。
- 多赛事歧义、候选关联、跨年度同名或无赛事证据时，不猜测 `RaceEvent`；记录
  `race_identity_unresolved`，沿用普通新闻规则。
- 赛事别名变化不得把历史文章静默重绑到另一届赛事。

### 重复与角度

- 完全相同的规范化来源标题必须在相同赛事/合理时间范围内命中硬重复保护。
- 正文相似但角度不同的稿件不得仅因同赛事而写入 `duplicate_of`。
- 角度无法可靠分类时使用 `other`；第二席要求与第一席角度不同，`other` 不得自动证明差异。

### 首页

- 同一赛事任何时刻最多 2 个有效首页席位，头条、普通列表和热门榜共同计数。
- 第一席可立即生效；第二席在第一席生效满 15 分钟前保持等待。
- 第二席按质量、角度差异、发布时间和稳定 ID 确定性排序。
- 只有质量明显更高且角度有效的稿件可原子替换第二席；重跑不产生额外有效席位。

### QQ

- 同一 `PushTarget` 与同一赛事最多两个已发送/在途席位。
- 第一篇可立即排队；第二篇遵守 15 分钟及角度差异规则。
- 首页第二席替换不得重发 QQ；既有 `(article, target)` 唯一约束继续有效。

### 历史边界

- 历史盘点默认只读，至少输出赛事、文章、当前公开状态、头条、QQ delivery、建议角度和建议席位。
- 回填只写新的分发决策，不修改正文、公开时间、QQ 记录或 `duplicate_of`；任何身份歧义留待人工。
- 生产历史回填必须有冻结 manifest、dry-run 差异、独立审核和单独写入授权。

## 失败边界

- 无法证明赛事身份、角度差异或第二席质量优势：不授予或不替换席位。
- 并发窗口争抢同一席位：数据库唯一约束与事务锁保证最多一个成功。
- 新策略异常时，关闭策略开关后恢复现有公开列表和 QQ 选择；不得删除既有曝光审计。
- 任何方案实现不得把“公开详情可访问”误解为“必须出现在首页或 QQ”。
