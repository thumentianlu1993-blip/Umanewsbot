# 新闻与术语候选恢复基础修复规格

## 目的与本轮范围

让包含真实新闻、术语候选的数据库能够完整备份和恢复，同时保住既有内容、审核决定、历史证据与已发送事实。

先完成隔离诊断和独立方案审核，用户随后明确授权连续推进隔离试修、完整备份恢复、整栈及故障演练。当前实施范围限定为本机禁网副本；不包含生产数据修改、合并或部署。诊断见[诊断](diagnosis.md)，实施结果见[验证](validation.md)；门禁统一引用根[AGENTS.md](../../../AGENTS.md)。

## 期望结果

- 新闻恢复(source_site, source_article_id)唯一；术语候选恢复(term_type, source_language, normalized_key)唯一，保持原有约束语义。
- 公开新闻9783的ID、路径、正文、公开状态与已发QQ不变；忽略/拒绝的记录不因修复重新进入生产流程。
- 候选405保持人工拒绝；不猜测/生成中文译名，不修改正式TermEntry或术语别名身份。
- 每个删除的重复主表/关联行先完整留档，所有移交都有旧ID、新ID、字段来源、before/after SHA256与可验证回执；历史正文与决策能够追溯。
- 两个唯一约束、全部相关FK/索引/触发器有效，修复后的完整逻辑备份可在另一空库一次恢复成功。

## 范围外

不重新翻译、重新抓取、发布文章、发送QQ、开启P02；不修改来源身份规则、删除任意失败约束、伪造source_article_id/normalized_key以绕过唯一性。不借本次清理其他新闻/正式术语，不把9月26日清单直接用于今天生产。

## 完成标准

隔离试修、幂等/中断/恢复测试、内容与引用保护、独立review均通过，并形成固定候选的新dump→空库完整恢复证据，才称为隔离修复完成。生产修复和P02第4步完整Compose/RTO仍分开验收。
