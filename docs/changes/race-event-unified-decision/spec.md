# 第二阶段：统一赛事业务规则与下一步决策

状态：设计完成，未实施/未部署。第一批已上线，执行证据见[发布记录](../race-coverage-recovery-20261002/rollout.md)。本文不代表第二阶段代码已实现、迁移已执行或新来源已启用。

## 要解决的问题

第一批恢复了七场赛果，并使全部公开 canonical 赛事进入覆盖检查、缺口汇总邮件和管理后台。但“比赛事实是什么”“还有哪些资料缺失”“哪个执行器接下来做什么”仍由多条路径各自判断。第二阶段收敛这些规则，保留 Django/Celery/PostgreSQL 和现有身份、唯一写入者、租约、版本、公开证据。

本方案选择渐进重构赛事控制流程。没有证据支持全站重写；仅继续逐场补数据也不能解决时间推断、登记前失管、授权换代和任务积压造成的重复断链。

## 范围与优先级

| 顺序 | 交付切片 | 用户/运营得到的改变 |
|---|---|---|
| 2A | 11 场既有正式结果公开受阻的证据审计与兼容修复 | 有合法历史发布依据的结果恢复可见；证据不足的继续明确挂账 |
| 2B | 统一纯决策与全目标诊断，先影子比较 | 同一场的缺口、原因、下一步和实际执行情况一致；没有来源身份仍可跟踪 |
| 2C | 事实与时间提示分离、按能力登记、地区时区与策略换代 | 到点不冒充真实发车/完赛，缺马号不挡身份，策略更新不静默留下旧登记 |
| 2D | 小范围执行切换与控制任务容量保障 | 控制任务不再被新闻或慢抓取长期阻断；停摆可以被队列外的探针发现 |

2A 可独立交付；2B 是 2C/2D 的规则基础。2D 的运行健康合同在 2B 阶段先定义，不能等大范围启用以后补监控。具体实现任务见 tasks.md。

不包括购买数据、新地区实网授权、自动发布全年赛历、批量处理所有重复事件、消费/清空旧 race_live 队列、新闻/术语唯一约束修复，或直接实施本设计。赛历候选处理和 canonical 去重列为相邻后续工作。

## 业务合同

1. **收录与跟踪**：所有 published canonical 赛事始终属于覆盖分母；明确选入的 draft 可内部跟踪但不因此公开。缺来源 ID 不伪造 enrollment，也不使赛事从责任清单消失。撤回、合并和取消仍留可追溯的处理结果。
2. **身份**：一场实际比赛一个 canonical event；名称只帮助召回。强身份键或受审映射建立来源绑定；改期沿用既有赛事身份，歧义隔离后处理。
3. **能力**：身份、赛程、名单、马号/闸位、赛中信号、结果、更正分别描述可用性。已确认身份的部分名单不能越级当作完整赛卡，但也不能让身份能力被拒绝。规划能力不意味着该来源已获准提供该能力。
4. **事实**：可信证据才确认已发车、已结束、延期、取消；T、T+30 和当地次日零点只影响查询和提示。赛后接入有完整可信赛果可直接确认结束，不补造未观测到的赛中历史。
5. **结果**：结果成熟度与完整度分开。无结果、部分/暂定、完整参考结果、正式结果、更正结果不混称。完整 runner 映射及来源合同满足后才投影；跌倒/退赛/取消资格不是虚构名次，平手保留真实名次。
6. **权限**：当前抓取/写入准入与既有版本公开依据分别验证。当前授权到期停止新请求；明确撤销、身份无效或公开总开关关闭仍能立即阻止展示。没有历史证明不能补造一份证明绕过门禁。
7. **下一步**：每个未闭环目标要么有可执行动作及真实排程，要么有明确阻断、责任方和下次复核；“预计下次检查”不得冒充已经入队。完成与取消可以不再轮询，但保留更正或重新排期的合法入口。
8. **执行**：唯一 owner、generation、lease、预算和末端准入继续约束所有副作用。相同输入和 now 得到相同决策；迟到、重复、失效任务不能覆盖新赛程或已确认结果。

## 前台语义

| 证据/时间 | 主状态与补充信息 |
|---|---|
| 有未来精确赛时 | 未开始；北京时间日期/时间 |
| 只有当地赛日 | 时间待公布；明确标注当地日期，不放入北京时间“今天/明天”集合 |
| 已到预计赛时，无发车或结束证据 | 等待赛事更新；已到预计开赛时间 |
| 有有效发车信号 | 进行中；资料更新时间 |
| 有结束证据，无完整可公开结果 | 已结束，赛果待补全 |
| 有完整可公开参考结果 | 已完赛；参考结果（不标为官方） |
| 正式结果/有效更正 | 已完赛；正式结果/已更正及更新时间 |
| 延期/取消 | 已延期/已取消；有新赛程则同时展示 |

`RaceEvent.status` 在兼容期继续作为既有投影字段。统一读模型结合证据形成上述展示，不能把历史 time_t_plus_30 一律视作真实结束证据，也不能把已有完整历史结果全部降成未知。自动改写历史 status 不在默认迁移中。

## 验收原则

- 缺口数变化附相同时间口径和目标分母；不以“队列为空”“开关开启”证明闭环。
- 2A 每场列出旧/新公开判定、原版本/证明引用及撤销测试；不以“11 场全显示”作为可以放松权限的目标。
- 影子模式零额外来源请求、零业务投影、零外部通知；只保存有界比较结果。
- 执行切换后同时验证赛前、赛后、更正、取消/改期、任务迟到、当前权限到期与历史公开；按能力/地区分别给出真实与离线证据。
- 生产启用方式和人工确认边界统一引用仓库根 AGENTS.md；本次授权止于第二阶段设计。
