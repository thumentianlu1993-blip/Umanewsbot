# P01 测试与验收计划

本文件是待执行测试设计，所有业务结果初始为 NOT_RUN。产品要求见[spec](spec.md)，工程合同见[design](design.md)。自动测试隔离生产DB/Redis/队列/第三方，模型和来源均fixture/mock；真实模型评估与自然周观察单独记账。

## 1 样例与标注

F02固定至少100篇、每区20篇；按独立事件分组后75篇调试、25篇保留（每区5篇保留），同事件转载不能跨集合。包含成功稿、拒稿、失败稿、无中文名与同名实体、合法短文/表格/引语、模板漂移及数值语义错误。保留原始HTML、源时间证据、clean blocks、人工事实/实体/span、地区和选稿标签，文件带SHA和来源用途信息，不含凭据或个人数据。

标注者逐条对照原文，第二次检查争议项；无人可确认的项目标uncertain，不让生成模型自己给自己打分。固定保留集在调参前冻结。评测前先核既有缓存是否合法、完整可用；不足如实报告，不能用合成样例充真实gold。

## 4 运行层级与停止条件

- 纯函数：复用 `test_content_review_decisions.py`、`test_content_review_shadow.py`、`test_numeric_surface_audit.py`、实体与term测试；新增P01各service的目标测试。
- Django集成：真实五地区fixture跑完整新增链，逐阶段回执与最终effective字段一致；首页/详情/分页和既有后台必要入口回归。
- 隔离PostgreSQL：T10/T16–T19/T21–T23并发、锁、事务、迁移、恢复；固定Git树/无外网容器，先证明容器清理与隔离资格，不在真实生产资源运行。
- 影响面回归：使用仓库 `scripts/plan_affected_tests.py` 生成范围，针对新模块补test-impact规则；按根流程执行，不因方案阶段虚构测试通过、不机械升级全仓。
- 真实样例小评估：20篇、至多两候选模型，输入/次数/token/金额上界与结果留存；未执行前为NOT_RUN。
- 上线后168小时：固定来源/policy/预算版本，公开探针核网页与缓存，独立事件分母核漏报，五地区及重大事件拆报时效/质量/曝光/费用。参数变化注明不可比区间，相关指标重新起算完整窗口。

发现新增技术缺陷修复并跑受影响回归；无修改和失败后停止扩大测试。空样本、未知状态、环境错误不能算业务RED或通过。
