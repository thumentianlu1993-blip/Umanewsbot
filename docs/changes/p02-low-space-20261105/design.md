# P02 恢复指纹降低临时空间（2026-11-05）

用户要求不购买额外存储，通过清理临时产物或降低容量需求继续第4步。当前生产空间不足以容纳未经预算的多份恢复副本；本变更仅优化恢复一致性指纹，不改变业务数据、公开行为、迁移清单或恢复身份边界。人工门禁仅引用根AGENTS.md。

## 指纹协议

原实现把完整row_to_json文本交给PostgreSQL排序，大表宽行会产生大量磁盘临时文件。新实现先对每一完整行的UTF-8 JSON字节计算PostgreSQL原生SHA-256，再按固定32字节bytea排序，通过服务器游标逐批更新整表SHA-256。

保留所有原字段、每次重复出现和行数；不使用DISTINCT、集合、XOR或抽样。序列验证原样保留。该协议提供密码学一致性检测，不声称数学上不可能碰撞。排序对象由宽JSON缩为定长摘要，客户端批次也保持有界。

结果增加algorithm=`sorted-sha256-row-json-v2`，算法标记参与最终counts_sha256。已有未带版本的证明不能直接复用，真实发布准入会因源摘要不符而拒绝。新增代码不回写旧intent/receipt，不提供跳过选项。

## 测试与已知边界

- 真实RED：合成PG宽行表在work_mem=64kB、temp_file_limit=1MB下，旧算法报临时文件超限。
- 新算法在同限制通过；内容变更、重复行增加均改变摘要，行物理顺序变化不影响结果，NULL/空串/Unicode被覆盖。
- 未带版本的恢复证明通过真实admission路径在DDL前拒绝；原source mutation、序列、迁移故障及角色/权限恢复测试继续执行。
- 本机完整真实数据副本只读诊断覆盖129表、13,392,635行，在work_mem=4MB、temp_file_limit=1GiB、禁并行的独立连接下用时约84.98秒；行数与原基线一致。该诊断先于最终实现，不代替本候选完整CI或恢复验证。
- temp_file_limit约束单个PostgreSQL进程的临时文件，不约束整个实例、WAL、备份或并发总量。此代码不修改生产全局PG设置。实际演练需显式绑定连接参数、并发数量、磁盘余量与中止条件，并采样峰值。

## 恢复流程与交付边界

精确清理仅面向已核实的临时日志/未使用构建产物，必须保留当前和回滚镜像、业务卷、备份、登录资料及其他项目资源，按实测df增量报告空间。

简单的A修复→删除A→恢复B→对B创建intent不能满足独立恢复证明：恢复身份必须不同于升级目标。优先在实际清理所得空间内保持原有独立恢复实例；若仍不足，再设计并验证独立C证明的执行路径。不把重新填SHA、同库自证或放宽身份不等式当作低空间修复。

演练切点副本始终只用于演练；正式切换必须另取最终release cut并持续停写至校验/切换结束。当前仍没有生产发布授权，第4步整体完成取决于后续完整材料、生产形状/RTO及精确发布包。
