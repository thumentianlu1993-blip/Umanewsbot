# 首页人工头条与 AI 编辑推荐规格

## 1. 背景与现状

公开首页已经有算法化头条，但没有运营控制面。当前
`server/stable/views.py::_select_headline_article()` 从公开文章查询集中选择头条：

1. 优先 `published_to_web_at` 在近 72 小时内的文章；
2. 没有候选时扩大到近 7 天；
3. 仍没有候选时回退到全部已公开文章；
4. 每层只取按 `published_to_web_at desc, id desc` 排列的前 48 篇，再依次比较赛事优先级、
   `score_total`、是否有封面、发布时间和文章 ID。

公开文章查询条件为 `workflow_status=published` 且 `published_to_web_at` 非空。首页、详情页和
头条目前没有页面级或文章级缓存；配置的 Django cache 只被赛事日历/站点地图统计使用。

`simplify-public-navigation-and-attribution` 已通过 PR #16 合入当前 `origin/main`。首页已经统一为
跨地区信息流，头条、普通卡片、热门列表和详情页均不展示新闻来源、新闻地区、原文语言或原文链接。
本变更必须保持该公开展示边界。

## 2. 目标

1. 有明确权限的后台人员可以从合格文章中选择当前首页头条。
2. 同一时刻最多一篇人工头条生效；新选择在一个数据库事务中替换旧选择。
3. AI 编辑台可以生成并展示一篇头条候选及中文推荐理由。
4. AI 推荐和正式人工头条是两个独立持久状态；生成推荐不得改变首页。
5. 人工显式接受推荐后，推荐文章才可成为正式人工头条。
6. 有效人工头条优先于算法化头条；没有有效人工头条时保留现有三级时间窗口、48 篇候选和排序元组，
   但算法候选也必须经过同一头条资格校验。
7. 设置、替换、取消、接受推荐、推荐被替换/失效、人工头条失效回退均有审计记录。
8. 并发操作不能产生两个人工头条，也不能让陈旧页面静默覆盖较新的人工选择。

## 3. 名词和状态

- **人工头条**：后台人员通过受控业务入口明确设置、当前仍满足资格的文章。
- **AI 推荐**：推荐引擎保存的候选快照，包括文章、理由、信号证据和引擎版本；它不拥有首页写权限。
- **算法回退**：现有 `_select_headline_article()` 的 72 小时、7 天、全部文章三级选择逻辑。
- **有效人工头条**：选择记录指向的文章在读取时仍满足第 4 节资格。
- **当前推荐**：状态为 `active` 的最新推荐记录；历史推荐保留为 `accepted`、`superseded` 或
  `invalidated`。

## 4. 头条资格

人工选择和 AI 推荐使用同一资格函数，必须同时满足：

- `workflow_status=published`；
- `published_to_web_at` 非空且不晚于当前时间；
- `effective_title`、`effective_summary`、`effective_body` 去除首尾空白后均非空；
- 文章可通过当前数字 ID 公开详情入口访问。

补充规则：

- 不要求封面。现有人工发布允许二次确认后无封面发布，现有算法回退也允许无图文章；封面只作为推荐
  排序信号。
- 不按地区拆分头条，所有地区共用一个首页头条位。
- `published_at` 是来源发布时间，不作为人工资格的未来时间门禁；本次门禁针对真正控制网页公开时点的
  `published_to_web_at`。
- `withdrawn_at` 的历史残留不单独决定资格，以当前 `workflow_status` 为准。
- 公开普通信息流和详情页的历史查询语义不在本变更中改变；但人工选择、AI 推荐和算法化头条必须共用
  本节资格，避免人工选择失效后同一篇未来时间/空内容文章又被算法选回头条。
- 算法化头条仍保留近 72 小时、近 7 天、全部文章三级窗口、最多 48 篇合格候选及现有排序元组；这不是
  重做推荐算法，只是统一头条位的安全资格。

## 5. 人工操作

### 5.1 选择或替换

- 操作入口只展示通过资格校验的文章。
- 服务端必须再次校验文章资格，不能信任页面隐藏字段、Django Admin 展示值或旧页面状态。
- 选择请求携带页面读取到的选择版本号。事务锁定唯一头条控制行并再次比较版本：
  - 版本一致：原子写入新文章、操作者、选择时间并增加版本；
  - 版本不一致：返回明确冲突，保持当前选择不变。
- 已有有效人工头条时，页面必须明确展示将被替换的文章；从 AI 推荐接受时必须由用户点击明确的
  “替换当前头条”动作，不能由推荐生成过程代替确认。

### 5.2 取消

- 有权限人员可以显式取消人工头条。
- 取消后立即使用算法回退，不创建空白 hero，也不改变任何文章发布状态。
- 陈旧版本的取消请求不得清除其他人刚设置的新头条。

### 5.3 失效

- 被选文章撤稿、删除、改为非公开状态、清空有效标题/摘要/正文或把网页发布时间改到未来后，人工头条
  立即失效，并且同一资格会阻止算法回退再次选中它。
- 受支持的文章保存/删除路径在事务提交后协调选择状态并写一次
  `headline_invalidated` 审计；公开读取路径仍要重新校验，协调失败时也只回退算法结果，不展示无效文章、
  不返回 500。
- 失效不自动恢复：文章后来重新满足资格时，必须重新人工选择。

## 6. AI 推荐

### 6.1 推荐来源

当前版本不新增第二套外部 LLM/API 调用。推荐引擎在有限的最新公开候选集中复用已经持久化的自动化/AI
编辑信号：

- `decision_reason.signals.race_priority`；
- `score_total`；
- 是否有封面；
- `published_to_web_at`；
- 现有头条算法的稳定 tie-break。

引擎把使用的信号、候选范围、选中文章和 `engine_version` 保存为推荐证据，并根据命中信号生成可解释的
中文理由。页面文案使用“AI 编辑推荐/自动化信号推荐”，不得声称又调用了一次模型或给出未保存的推理。

### 6.2 推荐生命周期

- 后台人员在文章编辑台点击“刷新头条推荐”后才生成新的持久推荐；普通 GET 不写数据库。
- 新推荐原子地把旧 `active` 推荐标记为 `superseded`，再创建一个新的 `active` 推荐。
- 没有合格候选时不创建空推荐，页面显示明确说明，现有人工头条不变。
- 推荐文章失去资格时，推荐标记为 `invalidated`；它不能被接受。
- 接受推荐时，事务同时：
  1. 锁定头条控制行并比较预期版本；
  2. 锁定推荐记录并确认仍为 `active`、文章仍合格；
  3. 更新人工选择；
  4. 把推荐标记为 `accepted`；
  5. 写审计记录。
- 推荐生成本身永不修改人工选择；即使当前没有人工头条，也必须经过点击接受。

## 7. 权限与交互

- 读取公开首页不需要登录。
- 头条管理入口要求用户已登录、`is_staff=True`，且具有
  `stable.change_homepageheadlineselection`；superuser 按 Django 规则拥有权限。
- 无权限用户看不到操作按钮，直接 POST 返回 403。
- 不把选择模型注册成可自由编辑的 Django Admin 表单；所有写入经过共享服务校验、事务、版本检查和审计。
- 后台新增“首页头条”管理页，显示：
  - 当前有效人工头条或“当前使用算法回退”；
  - 当前 AI 推荐、理由、证据摘要和状态；
  - 最新合格文章列表；
  - 设置、替换、取消、刷新推荐和接受推荐入口；
  - 最近相关 `OperationLog`。
- 文章编辑台的 AI 辅助区展示同一当前推荐及理由，并提供刷新/前往确认入口。独立表单沿用编辑台现有
  quick-term 的非嵌套表单模式，不能误提交文章编辑表单。

## 8. 公开首页行为

- `public_news_feed` 先解析有效人工头条；存在时使用它作为 `headline_article`。
- 没有选择或选择失效时，调用共享服务中的算法选择；现有三级时间窗口、48 篇上限和排序元组不变，
  但候选先经过统一头条资格。
- 普通新闻流继续从当前页排除最终 `headline_article`，避免首屏重复。
- `_headline.html` 的对象契约不变，不新增来源、地区、语言或原文链接。
- 没有任何公开文章时保持现有空状态；头条区域不得 500 或产生空链接。

## 9. 审计

沿用 `OperationLog`，至少使用：

- `headline_set`
- `headline_replaced`
- `headline_cancelled`
- `headline_invalidated`
- `headline_recommendation_generated`
- `headline_recommendation_superseded`
- `headline_recommendation_accepted`
- `headline_recommendation_invalidated`

审计 detail 保存旧/新文章 ID、选择版本、推荐 ID、推荐引擎版本、失效原因和操作者；不保存模型 prompt、
密钥或正文全文。人工动作的 `admin` 必须是当前用户；状态失效协调可为空，但要记录触发文章 ID。

## 10. 验收标准

1. 有权限后台用户可把一篇合格文章设为唯一人工头条。
2. 新选择原子替换旧选择，陈旧版本请求得到冲突而不是覆盖新状态。
3. 未发布、已撤稿、未来网页发布时间或有效内容不完整的文章不能被设置或推荐。
4. 生效文章失去资格后，首页立即安全回退到现有算法。
5. 没有人工头条时，现有 72 小时/7 天/全部文章窗口、48 篇合格候选和排序元组不变；未来网页时间或
   空有效内容文章不会被算法选为头条。
6. 生成 AI 推荐不改变首页；推荐和人工选择可同时指向不同文章。
7. 只有人工明确接受推荐才切换头条；有效人工头条不能被推荐生成静默覆盖。
8. 无权限用户不能生成推荐、设置、替换或取消头条。
9. 设置、替换、取消、接受、失效和推荐生命周期均可从审计中追溯。
10. PostgreSQL 约束拒绝非 `homepage_primary` slot；并发操作后仍只有一个控制行和最多一个
    `active` 推荐。
11. 当前无首页缓存时，连续请求立即反映选择/取消/失效；本变更不新增会产生陈旧头条的缓存。
12. 公开首页仍隐藏新闻来源、地区、原文语言和原文链接。
13. 1440px 与 390px 首页头条正常显示、无横向溢出；后台管理页和编辑台操作在桌面/移动端可用。

## 11. 非目标

- 多头条轮播、推荐位矩阵或普通流置顶；
- 按地区分别设置头条；
- 个性化推荐；
- 定时开始/结束；
- AI 自动发布、自动接受或自动替换人工头条；
- 新增外部 AI 调用、提示词体系或模型配置；
- 修改新闻采集、正文提取、马名识别、赛事日历、QQ 推送或发布窗口；
- 顺手重构现有算法化头条/热门系统；
- 修改 `AGENTS.md` 或使用 旧规格流程 skill/CLI。
