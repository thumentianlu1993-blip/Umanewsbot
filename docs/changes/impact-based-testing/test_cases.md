# 计划的验证矩阵

本轮仅设计。实施时先用小型合成 Git 仓库/测试 suite 验证选择和状态传播，不为验证工具本身跑几千项。
每项需要真实失败证据，再实现通过；下表给出应能抓住的错误实现。

| 场景 | 预期 | 要抓住的错误 |
|---|---|---|
| 纯说明文档；策略 JSON 冒充文档 | 前者仅静态检查，后者按领域/高风险 | 按后缀一律免测 |
| 马匹模板小改、新闻服务小改 | 选相邻业务与核心冒烟；无全量、无无关发布合同 | `server/stable/**` 全量兜底 |
| 来源 parser 改动 | 必须纳入下游入库、规范化及公开判定 | 只跑同名 parser 测试 |
| 新增业务文件未登记 | 先报 unmapped，无数据库动作 | 默认为空/默认全量 |
| 重命名/删除；新增/修改/删除测试 | 旧新路径领域并集，新增测试选入，删除报告可见 | 丢失旧路径、删测试后零覆盖 |
| views/tasks 函数、装饰器、默认值、helper 修改 | 受审符号映射及其所有领域 | 仅比较函数体、忽略 helper |
| 大文件 import/常量变化、AST 不可解析 | 扩文件范围或报明确缺口 | body 不变就认定无影响 |
| 模型、迁移、settings、依赖和选测工具变化 | 高风险 full 及必要合同 | 一行改动一律低风险 |
| PR 删除映射/依赖边、修改 gate 工作流 | base 侧检查及新旧规则并集/高风险 | 候选能自证“无需测试” |
| 删掉base校验步骤、伪造同名成功job | 候选外核验workflow/blob/步骤和受信计划，拒绝merge | 只看job名字/结论 |
| 候选提供伪造审核名单或替换核验器 | 只接受协调者绑定的受信对象，拒绝候选目录import | 从artifact取自授权名单 |
| 固定 base/head 与合并树；head不变base前移 | STALE_BASE阻止merge，更新所属分支触发synchronize | 只看 PR head 旧绿灯 |
| 核验后main再次前移、尝试admin bypass | 服务端strict拒绝；工具不使用bypass | 合并前检查与合并间竞态 |
| Git 失败/冲突/非法 SHA/路径逃逸 | fail closed、非零退出 | Git 错误解释成空 diff |
| 本地 staged/unstaged/untracked 混合 | 都计入摘要和计划，结果标 local | 只看 git diff HEAD 丢 untracked |
| 精确类清单、继承/legacy 别名 | canonical ID 集合完整，重复人为 label 拒绝 | Django 提前去重掩盖清单错误 |
| 单批 200/201、单类过大、多领域超400 | 200通过，201需分组；过大类报缺口；扩大明确 | 截前200/任意拆共享类/自动全量 |
| 多片同名 test ID、漏片、漏 test、额外 ID | 聚合失败；合法多 profile 必须明确登记 | 只相加计数 |
| skip、expectedFailure、unexpectedSuccess | 仅明确配置和期限内的预期行为可接受；其余失败 | 一律忽略跳过或将失败标 xfail |
| teardown异常、子进程异常、超时、取消 | 总 gate 非成功，保存失败证据 | testsRun成功就写passed=true |
| PR新提交取消旧run | 仅旧隔离测试取消；新run完整执行 | 取消生产发布/真实抓取 |
| 矩阵隔离 | PG/临时目录独立；重复执行无相互污染 | 共用测试数据库/输出目录 |
| 继承生产配置/真实HTTP、独立Python/curl | network none下出站失败；127.0.0.1合成PG可用 | 只在父进程打补丁 |
| 用例起真实容器、访问宿主socket；本地Docker缺失 | 无daemon/能力/挂载而拒绝；本地不回退，交CI执行 | 用宿主网络绕过隔离 |
| research/P0旧触发器和共享合同 | 普通PR唯一执行，手动tests/needs/输入/续跑/不取消语义保留 | 新旧入口双跑或删前置检查 |
| 全量标准/发布/性能配置归属 | 收集总集合与各profile并集一致，专用PG真实执行 | PG全skip仍算全绿/重复合同 |
| 无变更定时检查、上次失败、周周期 | 按明确日/周规则执行，失败不得永久被跳过 | 只看SHA没变就跳过失败 |
| nightly发现选测漏项 | 修缺陷+映射+diff回放，领域扩测 | 删除失败/只加豁免 |
| 普通应用准备上线 | 缺发布证据时只补必要合同，无业务全量 | deploy前强制重跑stable |
| 日志/证据被篡改、过期或错run/attempt | 拒绝复用并显示具体原因 | 单读passed=true/只看标题 |

## 验收分阶段进行

1. 小型 fixture 获得选择/聚合/隔离 RED→GREEN，工作流表达式覆盖 docs/targeted/expanded/full/error/cancelled。
2. 只收集不执行：以近期真实 PR diff 回放四类常见小改动及模型/迁移/依赖高风险改动；检查理由与期望范围。
   收集也使用隔离环境；216 个静态文件数只作参考，真实 catalog 以 loader 去别名后的 canonical ID 为准。
3. 按选中计划分批跑真实相关测试，验证 PostgreSQL 语义、runner收尾及专用恢复合同；不机械跑全量。
4. 首次 full profile 校准在后续实施的独立明确验证环节运行固定 SHA，只跑一套候选，不再基线+候选双跑。
   本轮不执行；无此证据不得声称全量配置已验收。目录汇总与分片并集、特殊 profile、skip归属必须一致。
5. shadow 只比较旧/新“计划”，不双跑测试；覆盖成功后切换。用普通改动验证有相关检查且没有全量 job。
6. 连续 10 个代表性小改动记录实际时间与选集；检查 P95≤8分钟目标，未达到如实说明准备/执行瓶颈。
