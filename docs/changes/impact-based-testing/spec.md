# 按改动范围测试：方案草案

状态：仅设计，待用户审阅；尚未修改 CI、测试入口或代理规则。前置 PR #232 已于
2026-10-02 18:00:42 北京时间上线并通过只读验收，见[执行记录](../fix-known-test-failures/rollout.md)。

## 要解决的事情

让普通小迭代默认只跑相关回归和少量核心检查，不再自动带出几千项全量；需要检查全站的
改动仍保留全量能力。判断依据是影响范围，不是改了几行：数据库字段即使只改一行，影响也可能很大。

## 当前事实与逐项解释

| 问题 | 用浅显的话解释 | 方案 |
|---|---|---|
| PR 触发范围太粗 | 改马匹页的一句话，也会命中 `server/stable/**`，同时启动旧版和新版两套全量 | PR 先生成测试计划；普通改动只运行相关领域，取消默认基线全量 |
| 发布检查与业务回归绑在一起 | 页面改动也跟着跑真实备份、恢复和迁移检查；本次仅 49 项恢复合同就用了约 411 秒 | 只有部署、迁移、配置装载及恢复代码变化才在 PR 跑发布合同；真正上线前仍检查所需合同证据 |
| 没有可审查的“代码→测试”对应表 | 代理不知道哪些测试有关，于是为了保险全跑 | 建立显式对应表，同时写清关联领域；漏了映射先报错，不静默全量，也不当成无需测试 |
| 代理说明容易一路扩大 | TDD skill 列出了从最小测试到项目全量的顺序，但没有明确停止条件 | RED/GREEN 后运行影响计划；所需检查通过就停止，只有新增改动、失败或指定风险才扩大 |
| 同一份工作重复验证 | 旧版与新版各跑一次；代理、本地、CI、上线前还可能再次重复 | 本地聚焦行为验证、Linux CI 给交付证据，上线复用已验证代码的证据，做生产健康/业务验收；不自动再跑全量 |
| 测试日志过长 | 几千条测试名和同一堆栈反复进入对话，耗 token 却没提供新结论 | 默认只输出数量、用时、失败摘要和产物链接；完整日志保留在文件里，需要时再读取 |
| 缩小范围可能漏测 | 单改解析器，也可能影响下游入库；只按同名文件选测试不可靠 | 对应表记录跨模块依赖，核心冒烟兜底，定时全量发现遗漏，遗漏必须反补映射 |

证据：`.github/workflows/release_0078_contract.yml`、`scripts/test_release_0078_contract.sh`、
`.codex/skills/tdd/SKILL.md`、`docs/codex_workflow.md`。现在的 `known-failures` 入口只服务
50 项旧失败的修复清单，不能直接当作通用自动选测器。

2026-10-02 静态扫描发现 `server/stable` 中 216 个含测试函数的文件、5493 个 `test_` 函数定义；
`tests_legacy.py` 占 628 个。静态定义数不是实际执行数，继承、别名和装载规则会产生差异。
此前真实 stable 运行记录为 5682 项；本轮只执行了 501 项相关回归，没有重新运行全量来数数。

## 用户能够预期的行为

| 一次改动 | 默认验证 |
|---|---|
| 纯说明文档 | 引用、格式与工作流说明合同；不启动数据库、不跑业务全量 |
| 马匹模板/独立资料服务 | 对应页面、资料模块及其已登记下游测试，加小型核心冒烟 |
| 翻译/新闻处理 | 翻译与新闻发布相关回归，保留关联字段、失败重试和分发边界测试 |
| 赛果抓取、Celery 路由 | 来源解析、结果入库、幂等/重试、路由和公开判定相关回归 |
| 共享模型、迁移、全局 settings、公共依赖、测试选择基础设施 | 明确标成高风险，运行隔离的全量配置及相应发布合同 |
| 新文件、无法归类的动态关系 | 在执行测试前报出缺失映射；补映射和测试，或显式选择全量，不自动偷偷扩大 |

普通计划目标不超过 400 项，每批不超过 200 项；确实涉及多个领域时允许“扩展回归”，不能为了
达标截掉测试。扩展回归不自动变成全量。预计普通 PR 的 CI 用时目标为 P95 不超过 8 分钟，
这是验收目标，不是已测得的性能承诺；需结合依赖安装及真实 PostgreSQL 启动测量。

## 非目标

不删除测试换取速度，不通过新增 skip 掩盖失败，不修改业务、数据库结构或生产抓取范围。
不重构整个 Django 主干，不建立凭文件名猜依赖的复杂自动推断系统。
首版不建设跨提交测试结果缓存；现有下载依赖缓存可以继续使用。
本轮只交付方案，不启用定时任务、不跑全量、不再次发布生产。

## 验收标准

1. 文档、模板、独立业务服务的代表性小改动均不启动全量/基线全量/无关发布合同；不依赖 `[skip ci]`。
2. 高风险路径必定扩大到明确的全量配置；未知路径、空业务选集、漏批、错 SHA、异常跳过、清理失败均不能绿灯。
3. 能解释每个变更为什么选中每个领域，所有新增/修改测试及依赖关系被纳入；改映射不能移除旧规则要求的覆盖。
4. CI 与本地采用同一计划语义；区别仅在证据级别，开发者看到通过后不被默认要求再跑全量。
5. 全量只在声明的高风险变更、定时检查或显式手动请求运行；每次输出原因及范围。
6. 本轮不宣称未来永远不跑全量：对普通且可识别的局部改动避免全量，对真实跨全站风险保留全量。
