## E3：为什么前句不是马名，后句是？

**判断的是某段文字在这一次出现时指什么，而不是这个字符串是否曾被用作马名。**

- 已核片段：`今回がラストランとなる。`，意思是“这次将是最后一战”。`今回`是“这次”，`ラストラン`是完整普通词，`となる`是“将成为”。句子用“最后一战”描述本次出赛，并没有把`ラストラ`作为某匹马的名称。截去末尾`ン`会破坏词义和边界；网页恰好给前几个字加了马匹链接，也不能改变这句的语义。这里可以有一匹未点名的马作为报道对象，但不等于句内出现了马名。
- 合成对照：`競走馬ラストラが出走する。`，意思是“赛马ラストラ将参赛”。`競走馬`明确提供对象类别，`ラストラ`处在名称位置，后面的`が出走する`描述该对象参赛。因此，这个合成句中可将完整的`ラストラ`识别为horse提及。它不是对现实中存在同名马的证明，也不能据此绑定数据库马匹。
- 更直接的同词对照（合成）：`ラストランという名の競走馬が出走する。`，意思是“一匹名叫ラストラン的赛马将参赛”。此时连完整的`ラストラン`也被明确用作马名，应抽取整个名称。不能把“ラストラン永远不是马名”写成规则。

## 常见判断场景（已认可）

下列示例均为合成；名称、年龄、亲缘和比赛行为只用于解释语言判断，不是现实赛马事实。判断结论只针对指定提及，不代表整篇实体完整性已验证。

| 场景 | 示例 | 判断与依据 | 容易犯的错 |
| --- | --- | --- | --- |
| 1. 明确说明是马、明确命名 | `一匹名叫“晨光”的赛马即将复出。` | “晨光”是horse：类别和命名关系都明确 | 因为“晨光”也是普通词就排除 |
| 2. 普通词描述时间、状态或比赛性质 | `晨光中，马群开始训练。`；`今回がラストランとなる。` | 此处“晨光”描述光线，“ラストラン”描述最后一战，均不作horse | 在普通词中匹配到已知马名，就当马名抽取 |
| 3. 带马匹属性的介绍 | `晨光（牡3、田中厩舎）は調教を終えた。` | 此处“晨光”是horse；“牡3”（雄马、3岁）、所属马房及训练语境共同提供依据 | 仅凭括号、数字或片假名判定；把年龄、马房也并入马名 |
| 4. 骑乘关系明确区分马与人 | `骑师林某策骑晨光获胜。` | “晨光”是horse，“林某”是人；骑乘关系明确区分角色 | 看到“获胜”就把句中所有名字都当马名；骑师也能被报道为获胜者 |
| 5. 血统或繁育关系 | `赛马晨光的父亲是海风，母亲是月影。` | 三个名称均指马；后两者由明确的马匹亲缘关系确定，即便没有参赛动作 | 只抽当前参赛马；或对任何包含“父亲”的人物报道都套马匹分类 |
| 6. 前文已明确身份，后文省略类别 | `赛马晨光昨日抵达。晨光将在周日出赛。` | 两次“晨光”均是horse提及；第二次依据连续上下文指向同一匹马，分别保留原文证据 | 要求每次都写“赛马”才识别；或只保留首个提及 |
| 7. 同名但当前指人、机构或地点 | `晨光牧场宣布扩建。`；`晨光练马师表示满意。` | 前者“晨光牧场”指机构，后者在该句指人，均不能仅因名称重合而抽出horse“晨光” | 已知马名全篇替换；从完整机构名称中机械截出马名 |
| 8. 纪念赛名中包含马名字符串 | `晨光纪念赛将于周日举行。`；对照：`这项比赛为纪念赛马晨光而设。` | 前句整体是赛事名，单凭赛名不足以额外抽取horse；后句单独指称赛马，“晨光”可抽horse | 将赛名中的字符串一律拆成一个马名提及 |
| 9. 别名、简称与代词 | `赛马晨光被马房称为“小光”。小光今天休息。它将在周日出赛。` | 明确别名关系使两处“小光”可识别为马的称呼，须保留别名关系上下文；“它”是代词，不应伪造成原文中出现了“晨光” | 从缩写凭空猜马名；把代词替换成全名后当作原文引用。别名是否作为独立输出类型仍需与契约对齐 |
| 10. 标题短、缺少对象类别 | 仅有标题：`晨光归来` | 证据不足：可能指马，也可能是比喻或其他对象。结合正文确认；正文仍不能消歧时保留不确定 | 仅凭赛马网站、标题大小写、引号或一个“归来”就确定horse |
| 11. 网页链接、词库命中与语义冲突 | HTML为`<a>ラストラ</a>ン`，还原文本为`ラストラン` | 链接只可作辅助线索；在“这次将是最后一战”的语境中不抽horse子串 | 让HTML链接边界覆盖原文词义；认为词库命中就是语义证明 |

上述场景是模型判断提示与评估案例，不是逐词硬编码分类器。建议按以下顺序判断：先确认完整文本边界，再看该提及在句中指称的对象与角色，必要时读取邻近上下文。证据不足时保留不确定，不用字符串黑名单或默认取首次匹配代替判断。

识别出horse提及，只说明原文把这个名称用于一匹马；该马是否真实存在、是否与数据库某条记录同一身份、是否有可信中文名，是后续需要另行核实的问题。所有抽取仍须附原文上下文，不自行改写名称。
