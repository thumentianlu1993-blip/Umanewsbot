# 实体短单元与有界修复

用户已认可示例并批准实现、定向测试与独立复审。沿用当前独立分支；不新增付费调用、不变更生产或公开开关。人工门禁统一见根AGENTS.md。

context-v2实体阶段改为entity-units-v1输入协议：标题独立，正文以句末/换行边界聚合到约640字符的单元；无安全边界的长句保留完整，不硬切名称。每单元保留block_id、原文起止及160字符左右上下文，模型只标核心区起始的提及。短单元合为一次请求，每个单元显式返回coverage及entities。

服务端精确定位到单元窗口并映射回原块跨度；重名返回候选及原文上下文供修复，不默认取首次。仅结构与引用合格的行可暂存；未知类型、重叠、字段越界等行携问题反馈。只对有问题/未处理的单元请求一次修复，已验证行冻结，不可删除或重复。同批重叠行全部待修，不按返回先后选取；缺失回执反馈固定按输入单元顺序。修复附标题及相邻非请求单元的有界只读上下文（每项最多640字符），禁止输出这些上下文单元。修复仍失败进入review；结构总量超限直接待审。无迁移，使用entity_snapshot保存进度与首轮回执ID，实体修复不消耗译文repair_count。事件版本变化后重新判断仍有重大新事实时，显式清空实体阶段绑定，开始新一轮；旧attempt和费用账证保留，不重新发送上轮补丁。

发布前从首轮与修复的原始回执重新执行相同确定性算法，核对输入、首轮绑定、所有单元覆盖与冻结快照；不能只信任汇总snapshot。旧legacy路径保持，旧context-v2实体回执不冒充新协议。预算、unknown、请求数量和缓存机制沿用既有守卫。

代表性提示示例采用标题/正文分别提及、普通词与明确命名对照、骑乘角色、重复名上下文、原名不可规范化、字段限定。其余审阅稿保留为离线案例。每单元complete仅为模型回执，不证明语义无遗漏；不增加词库黑名单或自动身份绑定。
