# 数据集构建、划分与锁定

> 2026-11-01执行规模更新：用户指定先整理开发50、测试50、备用20。该批已形成v2待标注材料，原缺HTML的40篇已全部回原站核验可见正文，详见[交付记录](selection-120.md)；下文100/100保留为原设计规模，不是本批数量。实际测试材料尚不具备独立盲测gold资格，其余80篇沿用缓存HTML。

## 1. 三个不同的集合

推荐development=100真实文章、holdout=100真实文章、challenge约30短案例。pilot20包含在development内。

开发集100篇中，目标80篇按分层抽样选取，20篇用于既有错误和边界覆盖；历史错误不足时从抽样池补齐并记录组成。最终开发集每区20篇；若某地区错误过多，超额部分放开放回归附件，不挤占其他地区。锁定集全部按预先分层抽样选，不根据baseline是否失败选。

challenge包含真实片段或明确标为synthetic的对照、故障回执，不计入真实篇数或主通过率。既有3篇、20篇及其转载/变体均已曝光，最多进入development/开放回归。那些旧结果不自动获得人工gold资格。

## 2. 建立候选库存

优先盘点可合法复用的现有缓存，不新抓取。库存每项记录：sample_id、来源URL/站点、published_at与缓存时间（缺失记unknown）、语言、主体地区、文章类型、原始/clean SHA、字符数、标题/正文块、清洗完整性审查、许可/访问依据、曝光状态、duplicate_cluster、event_group、候选排除理由。

先固定库存、来源范围及时间窗口，再抽样。现阶段样本可用量未知，窗口和数量缺口是执行前待填项，不能写成已具备。建议用选定连续窗口的所有符合输入要求缓存，记录窗口内各类供给与排除比例；超过窗口的补样以扩展版本记录。

数据准入排除：来源无法核验/无复用依据、正文不完整、清洗结构无法恢复、标注尚未裁决。排除发生在看模型输出之前，保留清单与原因。难文、长文、未见名称、无实体新闻或原文本身模糊不能仅因模型可能失败而排除。

当前模型128行/输入长度限制不是“gold最多128实体”的理由。有效文章超过处理能力仍保留并标capacity_case；若明确另设产品输入范围，必须在冻结前声明适用范围与被排除比例。不能截掉文章后半段补足100篇。

## 3. 先分组，再划分

将以下关联组成不可跨集合的连通组（leakage_group_id）：

- 同URL不同版本、同原文SHA、转载及翻译转载。
- 高度近似正文或同模板仅换少量名称的变体。
- 同一具体赛事/马匹动态/机构决定事件及其直接更新、跟进稿。
- 同一真实样本派生出的删节、反例、合成改写、故障回执。

event_group需含对象、事件类别和发生时间/届次等依据，不能仅用“同一匹马”“天皇赏”或媒体域名，否则会把多年无关新闻串成一组。无法判断是否同事件先人工核对；从旧曝光样本可连通的整个组只能去开发/回归。

近重复检测在分组时使用规范化文本指纹、字符片段相似度等提名，人工确认；此处的规范化文本仅用于查重，不改变gold原文坐标。抽样种子和组列表固定，分组变化必须重算交叉泄漏。

锁定主集优先每组仅一篇，避免同一事件重复贡献分数。开发可保留同组多篇用于上下文测试，但须报告独立事件数。样本之间同一实体名称出现不视为必然泄漏，另按开发gold判断“已见/未见名称”子集，避免把正常新闻中的高频马名全部隔离。

## 4. 推荐划分算法

1. 从库存中识别已曝光组，标development_only；标签、回答、提示示例、模型结果、人工讨论任一被用于调优均算曝光。
2. 数据管理员按五个主体地区分层，锁定种子；不向调优者展示未曝光的候选内容。先从未曝光组抽锁定集每区20篇，再从剩余组补开发集每区20篇。
3. 每区内按库存中的文章类型和clean长度三分位尽量保持比例。样本不足时不强行满足所有交叉格；输出实际分布/缺口，不重复某一组补齐。
4. 在抽样前记录软覆盖目标：每个有足够供给的地区尽量覆盖至少两个来源；记录语言、预告/结果/马匹动态/机构规则等类型、长短文分布。不能等跑分后因为“太难”换样本。
5. 先抽样后盲标，标注导致确实无法进入gold时用预先排序的同层候补组替换，记录排除和replacement来源；已裁决为原文本身模糊的文章不替换。
6. 冻结split manifest与gold版本；自动检查URL、SHA、leakage_group、event_group及派生关系零交叉。记录每区数量、语言数量、独立事件数、原文模糊文章数和理论自动通过上限。

五地区各20篇是覆盖均衡设计；主100分不能称为全站自然流量正确率。线上有可信的独立流量分布后可另报加权分数，不事后重加权来提高主分。

## 5. 锁定集谁能看、何时使用

角色是工作责任，不要求新增账号体系：

| 角色 | 开发集 | 锁定原文/gold | 模型输出及逐例评分 |
| --- | --- | --- | --- |
| 调优者/提示词优化器 | 全部可读 | 冻结前后均不用于调优 | 最终验收揭盲后才看 |
| 数据管理员与人工标注/裁决者 | 可读 | 可读；不参与该轮调优 | 标注时不看被测输出 |
| 隔离模型执行器 | 仅manifest指定input | 执行时只读原文，不挂载gold | 只输出回执 |
| 离线评分器 | 只读冻结回执 | 可读gold；无模型网络权限 | 写结果，不改prompt |

在同一共享工作区放一个叫holdout的文件夹，不构成真正隔离。执行建议：锁定材料置于调优进程未挂载的独立受控目录，由用户/数据管理员保管；执行器只得到input副本，评分器才得到gold。调优会话不要参与锁定标注，也不要通过工具浏览锁定内容。没有隔离条件时诚实标为“内部保留集，独立性未证明”，不冒称盲测。

原则上先在开发集完成所有改动，再同时冻结baseline和一个最终候选，用同一锁定集做一次比较活动；这能在最终报告中得到baseline60、candidate85，而不提前把锁定集反馈用于调优。

只看聚合分数也会反馈测试信息。不得不断试候选直到过85。最终比较失败后，可揭盲分析并将这一版本归档为已曝光回归集；下一轮独立验收需要新未曝光组，不能靠重命名文件恢复独立性。揭盲前已登记的重复运行属于同一次活动，不得在结果间修改模型/prompt。

## 6. 版本、变更与泄漏处置

manifest记录dataset_version、annotation_version、split_version、inventory_sha、gold_sha、input_sha、seed、freeze_time、角色访问记录、曝光状态和替换记录。数据目录不提交受限新闻全文；仓库只放规范、合成示例和不含敏感数据的摘要/哈希。

发现真实gold错误：保留原始报告，按不看候选优劣的规则裁决，生成新版本；对baseline和candidate都重算同样的原始回执，注明属于修正版评分，不仅改单个模型分数。若改动影响模型输入或规则指令，则需要新评估，不能只离线重算冒充新行为。已泄漏版本的修正不会恢复独立性。

预训练数据污染无法凭本地划分完全排除。报告只声称“未用于本轮应用调优”，尽量使用较新的未曝光真实缓存，不声称模型从未见过原文。
