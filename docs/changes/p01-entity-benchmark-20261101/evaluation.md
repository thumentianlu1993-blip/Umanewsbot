# 评分、实验与调优流程

## 1. 冻结评估对象

比较的是“固定DeepSeek配置＋prompt＋输入组织＋输出适配＋程序校验/修复”的系统版本，而不是孤立的模型名称。记录代码SHA、prompt SHA、输入/gold/split SHA、术语/示例库快照、模型请求名与返回名、API形式、thinking/temperature等实际支持参数、输出上限、超时、修复次数、价格快照及预算。供应商未返回精确revision时注明别名漂移未知，不伪造固定模型版本。

基线使用本次已提交的entity-units-v2业务候选及其冻结配置；历史60/100仅为用户举例。未来实际baseline必须在新gold上重新测，不能把3篇或旧结构通过率折算为100分。

两条输出轨道：first_attempt和final（包含最多一次预登记修复）。成本包括全部首轮、失败、修复、思考token及未决预约。未声明的手工清洗、重试、字段删除或从多次结果挑最好一份不得加入正式分数。

## 2. 精确实体匹配

评分输入为正式校验得到的canonical occurrences，排除common_word；输出协议失败、定位未完成或整体review时，本篇的正式可用输出集合视为空。保留部分accepted/原始回执供诊断，但不混入正式可用结果。

Gold的每个mention包含canonical span/type和调用前冻结的acceptable_variants。预测与gold建立匹配边，当block_id、start、end、text、type全部与canonical或某个变体一致才有边。做确定性最大基数一对一匹配：

- TP=匹配数；FP=未匹配预测；FN=未匹配gold正例。
- 同一gold不能被两个预测重复计分；同名不同位置分别计数。
- 纯输出排序不影响评分。允许变体提升的是“预声明边界可接受率”，同时另报canonical严格分数，不能隐藏边界变化。
- 错类型算一个FP＋一个FN，另记type_error；错边界/位置同理。诊断标签不改变上述计数。
- 非实体清单不是唯一负例范围。任何未匹配专名预测均为FP；普通词误抽另单列。
- gold ambiguous_span不当作确定类型正例；预测为某专名没有可匹配gold，因此为FP。送review仅能证明未自动放行；是否真正识别原文歧义须另核验证据，不是自动成稿通过。

例如gold有两个不同位置的Alpha，预测只给一个：TP1、FN1；不得按去重后的“Alpha命中”报100%。如果同一位置同时输出两个允许变体，不能都得分；若正式协议先因重叠拒绝整篇，则按协议失败处理，原始行重复只进诊断。

## 3. 主指标与辅助指标

**整篇完全通过**：正式结果ready_to_translate（或业务等价可用状态）、全部协议/跨度检查通过、TP等于本篇gold正例数、FP=0、FN=0、无gold要求review的原文不确定。无实体文章在协议有效且无专名预测时可通过。API失败/预算未执行/截断等一律不移出冻结分母。

主分数 = 完全通过文章数 / manifest全部文章数。开发100与锁定100分别算；挑战集单独算。批次中途停下时仅报告“已观察通过k/N，活动未完成”，未执行不视为模型错误，但最终完成目标未达，不报k/已执行来替代主指标。

辅助指标：

| 指标 | 公式或口径 |
| --- | --- |
| 实体micro精确率 | ΣTP / (ΣTP+ΣFP)，分母0记N/A |
| 实体micro召回率 | ΣTP / (ΣTP+ΣFN)，分母0记N/A |
| micro F1 | 2ΣTP/(2ΣTP+ΣFP+ΣFN)，分母0记N/A |
| 协议成功率 | 有完整合法规范输出的篇数/N；同时列JSON、schema、定位、候选决策失败 |
| 修复恢复率 | 修复后完全通过数/实际进入修复的篇数；另列需要修复但未执行数 |
| 安全拦截率 | gold要求review且系统未自动放行数/gold要求review数；可能包含协议故障，不声称识别到了歧义 |
| 有依据的不确定识别率 | 结果明确指出与gold模糊位置一致的原文不确定证据数/gold要求review数；仅schema/API失败不计。协议不提供可核验证据时记N/A |
| 不必要转人工率 | gold可判明但结果review数/gold可判明篇数 |
| 成本 | 总已结算估计＋unknown预约上界；每尝试篇/完全通过篇，后者分母0时N/A |
| 时延 | 供应商耗时与全流程耗时分列，P50/P95及失败数，不只统计成功请求 |

协议失败的正式输出为空，会产生全部正例FN，且精确率可能偏高或N/A；因此禁止单报精确率，不把“什么都没输出”当准确。另可报告“仅协议成功篇的语义P/R”，必须注明条件分母，不与全量混称。

按地区、原文语言、长度、实体密度、标题/正文、类型、已见/未见名称、文章类别给出样本数和分数；小样本不下总体结论。独立事件数及人工标注分歧也进报告。

## 4. 错误报告

每篇可有多种error_tag：json/schema、quote_not_found、ambiguous_position、wrong_unit、duplicate、type_error、boundary_error、missing、common_word_false_positive、uncertainty_policy、capacity、timeout、provider_unknown、annotation_dispute。

需要饼图/独占计数时，按预先固定顺序取primary_reason：未执行/供应商→协议/截断→定位/修复→语义；语义先类型/误抽再遗漏。完整多标签仍保留，不能把40篇多问题累加成40个互斥案例。

每次比较输出baseline→candidate转移表：共同通过、修好、退化、共同失败。净提升=修好−退化。对退化逐篇检查，不能只复测旧失败样本。

## 5. 开发集上的优化循环

1. 完成gold、评估器合成反例测试与冻结baseline；先用pilot20控制成本，然后跑开发100。
2. 分析失败原因，选择影响最多且有明确机制的一个假设。不预设“改prompt一定最佳”。
3. 同一轮最多准备少量候选，例如3版；每版记录唯一主要变量、预期受益、潜在退化、实验预算。
4. 在固定开发筛选子集和相关challenge筛选；进入决赛的候选必须重跑完整开发100，包括之前通过的样本。子集得分不得当100分。
5. 净收益、误抽/遗漏及成本均可接受，才冻结一个候选用于锁定比较；不把更多repair次数与只改prompt的收益混为一谈。

候选顺序建议：标注规则澄清→少量成对示例→初轮/修复提示拆分→结构化输出与协议简化→分段/上下文→术语候选→有界复核/推理模式。每项是实验，不是保证有效。术语表只能提供有来源候选，不将词典命中直接当实体；few-shot/检索库仅来自开发与预先冻结的外部知识，不包含锁定gold或其派生数据。

模型可以建议prompt版本，但只能读取开发错误。评分由确定性程序对人工gold执行，不能让被测模型自己给最终分数。增加复核、检索或多次采样都须把调用和token成本计入同一系统方案。

## 6. 锁定验收与85/100的含义

默认节约成本方案：baseline与最终候选各对锁定100篇运行1轮，运行顺序预先按固定种子交错以减少时间漂移；每篇最多首轮＋一次修复，即最多400次调用，实际可能较少。不得在中途查看逐例分数后修改候选。预算依实际输入和模型配置计算，不使用旧20美元余额当新活动授权。

若希望声称稳定达到85，可在活动前选择各3轮：每轮仍是100篇，最多1200次调用；要求候选三轮均>=85/100，并报告均值、范围及三轮都通过的篇数。不能把300次当300个独立新闻，不能对每篇挑三轮最佳结果。此稳定性实验是可选方案，不默认执行。

一次85/100只证明这个冻结集合这一轮的结果。报告Wilson 95%区间；样本事件相关时使用按leakage_group的配对bootstrap或至少披露相关性，不把单纯二项区间当线上保证。配对新旧比较优先报告净提升和转换表；仅在样本/组数允许时给出配对不确定性估计，不强称统计显著。

推荐的开发候选选择条件是开发完全通过率提高、关键误抽不增加、成本未超预设上限；最终85目标不是放宽gold、扩大允许变体、删除难例或无限重试的理由。误抽/遗漏容忍度若用于上线，应在单独发布方案明确，本基准不代替生产验收。

## 7. 参考与适用边界

本方案借鉴任务专用评估、留出数据、专家标注和持续回归原则：[OpenAI官方评估指南](https://developers.openai.com/api/docs/guides/evaluation-best-practices)。100/100规模、类型规则、85分和分阶段实验均为本项目设计提案，不是该文档给出的通用阈值。
