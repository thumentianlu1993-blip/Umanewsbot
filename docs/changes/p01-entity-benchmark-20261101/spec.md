# P01 新闻实体标注与评估方案 v0.1

日期：2026-11-01。状态：设计提案，尚未构建真实gold、实现评估器或执行模型实验。人工确认仅引用[根AGENTS.md](../../../AGENTS.md)。本次用户要求是设计，不把样本数、85分目标或后续付费执行写成已完成事实。

## 1. 目的与当前证据

建立可重复回答“哪类错误减少、哪些原先正确的文章退化、成本增加多少”的评估闭环，替代围绕少量文章反复追加提示词。

当前代码`0c6ff935`实现entity-units-v2；最新实测3篇4次调用仍为0/3通过，既有输出协议失败，也有语义误抽和遗漏。133项离线测试证明程序合同，不证明模型识别质量。用户举例的60/100是目标讨论中的假设，不是本项目已测baseline。

## 2. 范围

第一版评估完整新闻标题和正文中每一次命名实体的发现、类型、边界、原文位置及可供下游使用的结果。类型为horse、person、race、organization、place。普通词和证据不足属于标注判断，不额外发明现实实体。

不在第一版评分中混入：现实身份消歧、术语库写入、中文译名、文章价值/事件去重、译文质量、发布成功。可保存article_local_entity_key帮助检查，但不要求查出真实马匹ID。遇到命名实体但不知现实身份，只要原文支持类型，仍应抽取原名。

输入以冻结clean为准；同时保留raw来源和清洗版本，标注前审核正文完整性。实体评估不掩盖清洗缺陷，数据准入失败单列；未来从HTML到成稿的端到端评估使用另一分母。

## 3. 推荐规模与划分

| 集合 | 目标数量 | 用途 | 可否用于提示示例/错误分析 |
| --- | ---: | --- | --- |
| 开发集 development | 100篇真实新闻 | 调优、错误分析、候选比较 | 可以 |
| 锁定测试集 holdout | 100篇真实新闻 | 冻结baseline与最终候选的一次独立比较 | 调优期间不可以 |
| 挑战回归集 challenge | 首批约30个短案例 | 普通词/专名对照、重复位置、协议故障 | 可以；不计入100篇主分数 |
| 标注试点 pilot | 开发集内20篇，不额外加数量 | 校准规范与标注一致性 | 可以 |

开发/锁定各覆盖日、港、英、法、美20篇，形成“五地区均衡基准”，不是线上自然流量的估计。地区按新闻主体，语言按原文，两者独立记录。不为凑法区而假设原文一定是法文。不足时如实报告，不能用合成文本或额外重复事件补数。

若首轮资源只有100篇：可先做每区15篇开发＋5篇保留，即75/25。25篇测试每篇占4个百分点，结果写21/25等实际分母，不能宣称85/100。已被反复调试的100篇应视为开发集，另取未曝光样本做锁定集。

200篇是拟定完整目标，不代表本地已有200篇合格输入。第一步盘点现有缓存和曝光记录，再决定可达规模；本次不采集新网页。

## 4. 首要评分与目标

主指标为“整篇可用实体结果完全通过率”：固定测试分母100篇，协议有效、证据定位有效、无误抽、无遗漏、类型正确、边界符合预声明规则，并能自动进入下阶段，才记1分。一次受控修复后通过与首轮通过分开报告。转人工、拒答、超时、截断、未完成均不算自动通过。

85/100为本方案的候选调优目标，不是生产发布标准，也不保证能达到。只有对未用于调优的锁定100篇、按预登记配置与规则得到85篇通过，才可说“本次锁定集85/100”。必须同时报告样本组成、重复波动、费用、基线差异与局限。抽取及翻译发布的验收不可互相替代。
