# 实体标注规范 v0.1

本规范是拟建benchmark的标注口径。历史实验保留旧评分，不据此回改旧结果；正式标注前用20篇开发试点校准并冻结v1。任何会改变业务输出的规则调整须在实施设计中显式处理，不能仅通过改gold实现。

## 1. 标注单位与原文证据

- 一篇样本包含完整标题及有序正文块；标题必标，不用摘要替代正文。
- 单位是一次提及（mention），不是去重后的名称清单。标题一次、正文三次，共四个mention；同名不同对象不自动合并。
- 每条记录block_id、start、end、text、type及逐字context。start/end为当前块Unicode code point偏移，0起始、左闭右开，兼容Python字符串切片，不是UTF-8字节或JavaScript UTF-16长度。
- 必须满足block_text[start:end] == text；空格、大小写、组合字符、标点、全半角均保留，不在标注后再NFKC、去空格或繁简转换。UI如用JS须显式转换索引。
- context有自己的context_start/context_end，应覆盖mention，逐字来自同一块。跨度唯一确定提及；不要求短context本身全篇唯一。重复语境不能默认选第一次。
- 分句/单元仅是模型输入组织。gold绑定完整clean块，不绑定640字分段算法，否则调分段就会改“答案”。

## 2. 类型和覆盖范围

| 类型 | 必标内容 | 不据此抽取 |
| --- | --- | --- |
| horse | 原文明确指向赛马的名称，包括父母、历史参赛马、退役马及标题名称 | 毛色、年龄、泛称“该马”，仅因字典存在就把普通词当马 |
| person | 骑师、练马师、马主、发言人等具名人物；原文支持的简称/姓氏 | “骑师”“指挥官”“他”等仅有角色或代词 |
| race | 具体命名赛事及原文可判明的赛事简称 | G1、JRAG1、分级赛、最后一战等等级/类别/描述 |
| organization | 具名机构、协会、媒体、牧场、公司等 | 未命名的董事会、委员会、厩舎、两家母公司等泛称 |
| place | 具名国家、城市、地区、赛场、训练中心等地理/场所名称 | 普通“坂路”“草地”“B跑道”等内部设施描述，除非文本明确作为具名场所 |

新闻正文与引语中的以上提及均覆盖，不只抽“重要马名”。数字、金额、日期、比赛名次不独立标实体，留给事实评估。品牌/奖项等确实为专名但无法归入五类的情况记type_gap送裁决，不猜类别；未解决则该文章进入待定库存，披露数量，不能为当前模型通过而删去这类问题。

同一字符串按每次上下文判断。synthetic例：“名为最后一战的赛马”中的最后一战为horse；“这将是最后一战”是非实体。示例不是现实马匹身份声明。

## 3. 边界规则

1. 默认最小完整名称：去除外侧引号、括号、介绍性职称、年份/届次/等级，保留属于名称本身的字符。
2. 具名对象的内部通用成分必须保留：France Galop Committee可作为完整机构名；不能同时再把内部France Galop作为另一个重叠mention。晨光牧场取完整organization，不从中切出horse晨光。
3. 名称与职称/等级紧邻时，优先核心名；确有同一指称的合理边界变体，可在调用前写入acceptable_variants，例如橋口/橋口調教師、天皇賞・秋/天皇賞・秋・G1。不能把任意子串或任意扩展都算对。
4. 变体必须同一块、同一次提及、同一类型，附明确理由；按类型规则一致裁决，不针对某个模型输出事后增加。一个gold mention只允许匹配一个预测，两个变体同时输出仍算重复或协议重叠。
5. 名称与泛称的区分依原文：独立Board of Directors作为泛称/回指不标命名机构；具名机构完整标题包含它时，可标完整名称。认识它指向哪个机构，不等于原文出现了该机构名。
6. 地名的独立出现全部标：栗東トレセン整体为place；另一次括号中的栗東独立为place，不因训练中心已经抽过就省略。
7. 原文异写不规范化：秋の天皇賞作为该位置的原文，不能输出天皇賞・秋替换其text。别名对齐和中文译名不在本任务处理。
8. 连续原文跨度为基础，不拼接跨词/跨块的不连续名称。发生真实嵌套歧义时先裁决外层指称；不能用两个重叠gold与现有非重叠保护链路冲突。无法裁决记待定，不静默降级。

标注员看完整文章确定上下文，但不得用新网络知识来补出原文没有的类型或身份。若需外部证据才能断定，记录needs_external_identity；实体身份任务后续另评。

## 4. 非实体与不确定

正例要全量标。非实体不穷举所有普通字词，只标有混淆价值的hard_negative，包括普通词形似马名、等级、角色、泛称组织等；每条保留跨度、原文和原因。

输出common_word或不输出非实体均可；程序仍须验证所有输出行合法。hard_negative本身不计TP，不能靠大量正确标普通词提高实体分数。未标负例处的额外专名也照样计FP，不把负例清单当黑名单。

区分两种不确定：

- **标注分歧**：两位标注者意见不同，应裁决后进入gold；未裁决的标签不是“原文真的模糊”。
- **原文本身不足**：例如只给“晨光归来”且全文没有类型依据，gold登记ambiguous_span及expected_action=review，不编造horse标签。已明确的其他实体仍照常标注。

有原文不确定的文章可以按抽样进入锁定集，不因其难而移走；主“自动完全通过”指标中转人工仍为0。另报告安全拦截率与有依据的不确定识别率，不能把schema错误导致的转人工算作识别到了歧义。若这类文章超过15/100，则85自动通过存在理论上限，应在冻结时披露，不通过删难例满足目标。

## 5. 标注工作流

1. 数据管理员先核对来源、输入完整性、曝光记录与事件组。
2. 20篇开发试点由两位具备对应语言/赛马理解的人工标注者独立标注；首轮不展示模型答案。比较正例跨度/类型和非实体判断，形成争议清单。
3. 裁决者依据原文与统一规则决定；保留两个原始版本、裁决理由、标注员/复核员及时间。修订规则后重标受影响的试点。
4. 正式开发集可使用模型预标，但标为model_assisted并由人全文复核；另随机抽20%独立盲标，并复核全部争议。与试点重叠的文章不重复计量。
5. 锁定集建议全部双人独立盲标并裁决；不展示被测baseline/候选输出。标注员不把内容或答案传给调优者。
6. Gold入库必须有真实人工身份和review状态；代理编写的示例、模型自评、程序跨度检查均不能填成human_verified。暂无合适人工时可以完成prelabel，但必须报告gold尚未就绪。

一致性报告包括双向严格span+type F1、含允许变体F1、类型混淆及分歧率。建议试点严格F1>=0.90、所有分歧已裁决后扩量；这是标注质量建议，不是模型分数或用户确认门禁。未达时先修改规范，不通过宽泛允许变体凑一致性。

## 6. 标注质检

检查源SHA与clean SHA、块顺序、所有跨度、context包含关系、唯一mention_id、重复/重叠、正负标签冲突、变体是否同一次指称、未知类型、未裁决状态。全文覆盖由人工确认，不能只凭JSON字段齐全证明“没有漏标”。可选重要性标记仅供错误优先级，不影响主评分的全量实体要求。
