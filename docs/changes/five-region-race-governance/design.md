# 实施方案

## 统一公开读取规则

新增轻量公开赛事范围模块，集中定义五地区、公开赛事对象判断、赛事 QuerySet 过滤，以及马匹赛事记录的地区过滤。只在前台读取层使用，后台和采集 writer 不复用此过滤。

所有公开赛事 SQL 在切片、分页、计数和年份聚合前过滤；对象列表和详情 registry 的 legacy 重定向前同样检查。详情内的系列历届冠军、分场父/子入口及 canonical_product_event 使用同一公开条件；历届冠军在计算 covered_years 前过滤，以免隐藏记录压掉允许地区的 fallback。保留现有 published、canonical duplicate、分场与 read-gate 条件。地区参数解析和赛事页地区选项使用五地区集合，新闻/马匹既有地区注册不缩减。

年份缓存与 sitemap 计数缓存升级键版本，使切换后不会读到旧地区产生的年份或分片数量；正常失效机制沿用。拒绝地区详情不会先重定向到可泄露目标的公开路径。

生涯记录：event 与 result.event 均存在时必须指向同一赛事，否则该行不公开；只有 event 时用其地区，只有 result 时用 result.event 地区，两者均为空才使用 race_region。未知地区不展示。先过滤再分页，主胜鞍使用相同过滤；公开链接仍要求赛事通过公开对象判断。

## 历史盘点及修复

生产只读快照使用 repeatable read/read only 和 statement_timeout，导出压缩传输，不持续锁表。初次盘点获得五地区历史 9,570 场、93,657 行赛果及 30,293 个年度目录项；其他地区公开赛事 712 场。该统计不等同于完整率，目录占位和名单字段仍须分层核验。

先审查 8 场已完赛但无赛果的草稿、来源字段空值模式和目录未物化项。依据具体 source_refs、缓存及既有解析器确定修复项；如仅映射错误，优先离线重放。来源缺失不构造替代结果。

最终数据写入只接受冻结 manifest 的既有事件/目标、强身份、已知字段差异和 CAS；保留人工锁及生效中的写入者规则。数据包在隔离 PostgreSQL 演练 dry-run/apply/replay/恢复；只读核验后随精确发布包交付。具体数据项和规模由盘点证据确定，不预先授权不明确的整库回填。

## 冻结修复清单

具体盘点与剩余项见 [audit.md](audit.md)。旧 JRA 骑手包仅填原缓存同身份的空姓名；日本 11 场新取得官方详情使用既有 source_refs SHA 绑定前态，只补清单列明的空字段，并对两条遗漏的非完赛/取消行绑定完整旧行 ID 集合。新增行的官方名次为空；原件只记“中止”时使用 did_not_finish，不能细化为拉停等原因。

8 场空表包按日期、地区、赛事身份及旧目标状态做 CAS：七场取消不公开，一场法国完整赛果公开。三个包均拒绝人工锁、非 historical writer 和现有 enrollment。每包事务执行、OperationLog 记录、条件恢复，不改模型或迁移。新增行被后续 HorseRaceRecord/HorseP0Source 引用时恢复拒绝删除；其他已知字段或来源漂移同样阻断。
