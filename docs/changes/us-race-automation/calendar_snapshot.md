## 修复边界与拟实施方式

- 年度目录使用只读 HTML 快照及绑定清单，记录年份、原始 URL、真实采集时间和原件 SHA256；显式配置清单路径及 SHA。支持任意年份，不只硬编码 2026。
- 在现有美国来源入口读取对应 TOBA 快照，保持既有解析器、赛事 key、冲突和身份校验。未启用快照时保留既有调用行为；启用后缺文件、摘要不符、缺年份或时间无效均明确失败，不回退访问被拒绝的目录。其他来源继续使用原有共享预算和网络入口。
- 人工原件先在本地解析、核对年份/结构并生成清单；保存与生产激活分开，具体生产动作仍按根 `AGENTS.md`。不新增管理界面、数据库迁移或第三方来源。
- 远期待赛资料使用 Sporting Life 已有的当前赛卡目录，再按目标日期、场地、赛事筛选；不自动跟随任意重定向，也不扩大域名或路径范围。
- 旧目录的空 `Field` 不代表零匹，也不能从解析行数反推完整性。拟仅在目录缺少独立人数时，使用 Sporting Life `WEIGHEDIN` 来源明确的 `ride_count`，并继续与 DRF 逐马、名次、退赛名单核对；缺少此类独立证据时仍拒绝发布。目录已有正数与来源不符时继续拒绝，不能静默覆盖冲突。
- 不绕过 Cloudflare，不访问 Equibase，不伪造采集时间。现有历史数据不重导，生产继续保持 `cba39875`，新候选另按根 `AGENTS.md` 交付。

## 方案审核补充

- 快照仅在默认 `fetch_source_page` 的美国 TOBA 精确年度 URL 分支读取；先执行 route URL、当前有效期、来源和既有开关校验。命中返回原始时间的 `SourceBytes`，不进入共享网络租约、网络预算或失败缓存。显式档案 fetcher 保持独立，缺页不能由配置快照补齐。
- 当前目录筛选为空只代表尚未核实。没有可用候选时，只有单场来源明确 `not_published` 才生成同名检查结果；其余返回 `coverage_unverified`，写入检查原因且不发布候选。其它来源的合格候选仍可使用，来源错误和日期未知不得伪装已确认无资料。
- 快照清单与原件分别绑定 SHA、年份、规范 URL 和有效采集时间；配置缺失或损坏直接失败，不网络兜底。测试覆盖许可/开关失效、显式档案隔离、来源明确 pending、跨时区日期，以及既有人数冲突和删马/改名次/漏退赛。

人工下载保留原始HTML后，运行离线命令（不访问数据库或网络）：

```sh
python server/manage.py prepare_us_calendar_snapshot --input /path/to/toba.html --output /path/to/new-snapshot --year 2026 --captured-at 2026-11-11T19:45:10.803577+00:00
```

年份和真实采集时间由原件提供，命令验证目录结构、年份和字节，生成新目录的 `index.json` 及内容摘要命名原件。输出目录必须不存在，避免覆盖已绑定快照。运行时以只读挂载提供文件，同时配置 `RACE_DATA_SYNC_US_CALENDAR_SNAPSHOT_FILE` 和 `RACE_DATA_SYNC_US_CALENDAR_SNAPSHOT_SHA256`；两者绑定清单及其引用原件，清单可列多个互不重复年份。快照缺页、摘要错误或年份无效时不会访问线上目录兜底。替换文件需生成新目录和新SHA；旧目录保留供配置回退。

目录的采集时间不会被读取时间覆盖，未填写人数依旧表示未知。Sporting Life声明人数仅在明确终态、完整逐马/名次/退赛交叉核对通过时使用，来源摘要写入名单证据。
