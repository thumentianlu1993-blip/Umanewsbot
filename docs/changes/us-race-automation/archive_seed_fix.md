# 冻结赛果回放与历史名单身份收据修复

## 发布结果与根因

PR #301 已合并为 `2e47b49a`。经用户批准发布候选 `c2881c9e` 时，完整原件解析通过，赛果写入在历史名单赛事附近报 `result_identity_conflict`。库内提交探测确认整包没有提交，恢复退出 0；四应用回到 `332fc540`、schema0084 保留，251 条基线、健康页和两类发布锁释放复核通过。美国本包数据与自动更新仍未上线。

冻结回放凭证此前绑定整个解析字典。但 `fetch_bound_observation` 会在来源身份尚未建立时，依据数据库已有的合格名单候选添加 `identity_seed_receipt`；建立来源绑定后，再次解析不再添加该字段。来源原件与赛果没有变化，数据库派生的附加字段消失却触发摘要不匹配；外层只保留通用身份冲突原因，掩盖了具体差异。

此前整包演练装入了写入/恢复表、109 条旧地区登记和美国身份背景，但漏装只读依赖 `RaceEventDataCandidate`。生产目标实际有 160 条候选，其中 19 条待处理名单分布在 event491、492、494、495；第一场为 event491。不能用此前的完整事务演练声称已覆盖这些背景输入。

## 修复边界

- 新摘要函数保留全部来源解析字段，仅排除数据库派生的 `identity_seed_receipt`。该收据仍由既有身份解析器核验，不从来源 JSON 获得授权。
- 原件 SHA、名单及其他解析字段变化仍使凭证失效；真实采集时刻、未来时间、当前策略、来源范围、赛事身份和最终写入检查不变。
- 失败结果保留通用 reason，同时增加具体身份原因；精确发布错误包含赛事 ID，便于定位。
- 原 manifest、153 个目标、111 场 1071 行、101 个来源时刻及 109 条换绑不变。无新增迁移，不增加抓取范围或消息发送。

## 验证边界

新增端到端回归先重现 `result_identity_conflict`，修复后覆盖旧名单存在、来源绑定建立、二次解析、重复执行和精确恢复，候选记录保持不变。已有二次解析篡改、48 小时原件、未来时刻、过期策略及默认实时陈旧观测规则继续测试。本机 154 项通过。

已补查目标赛事的候选、参与者身份、修订、结果观测、发布授权等读取背景：160 条候选记录，其余 14 类检查表无记录。新演练装入全部候选及原身份背景，另外核对候选在写入、重复执行和恢复后不变。固定候选 PostgreSQL、真实背景复现、完整原 manifest 和远端 CI 的结果以最终交付收据为准，本文不预先宣称通过或上线。
