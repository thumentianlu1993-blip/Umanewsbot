# 赛事区修复测试用例

实施依据：已批准 PLAN SHA256 `3bfc69404b1228ad1a3b2c42338c87fbc7bb2c7479204a54635eff46e528b323`。本文件先于应用修改建立；每项映射到自动测试或明确的发布验证，不访问生产数据库、Redis 或真实第三方。固定日期避免夹具随时间过期。

| 编号 | 场景 | 必须满足 |
|---|---|---|
| R01 | 当天列表缺终态 | 不注入 complete/official，暂定证据保留 |
| R02 | 同日精确详情明确终态 | 单次最多一次回退，走既有正式发布门禁 |
| R03 | 详情 404/超时/限额/无终态 | 暂定不丢、不误确认，下次仍可查询 |
| R04 | 次日详情缺状态 | 不再默认 official；结果完整性与权限仍校验 |
| R05 | 已正式／重复响应／缺选手 | 不降级、不重复发布、不绕过名单门禁 |
| D01 | D−4 本地 00:00，时间为空 | 开始检查；D−5 不触发高频链路 |
| D02 | D−4～D−2／D−1／D 当天 | 3h／1h／10min；赛时与赛卡同档 |
| D03 | 跨时区、跨日换档、T+5 | 下次不越过档位边界；过期停止赛前检查 |
| D04 | 改期、取消、未定延期 | 旧基线不可写，按新日期计算或停止 |
| D05 | 同对象重复投递、worker 崩溃 | 单有效 lease；到期可接续，旧 token 零写 |
| D06 | 两来源并发写调度元数据 | 合并当前 source 子树、不覆盖另一来源 |
| D07 | 同桶、缓存、批次／预算不足 | 共享响应，未执行保持 due，原因可审计 |
| D08 | 已有身份未成功纳管 | 资格盘点仍执行，不因 already_valid 丢失 |
| D09 | 429、Retry-After、公布时间 | 不以跨日加速绕过退避，公开检查时间真实 |
| J01 | 官方未编号／编号／报名名单 | 阶段与时间准确，空编号不伪造 |
| J02 | 错比赛／错日期／错域名／部分表 | 拒绝写入，不覆盖有效候选 |
| J03 | 重复内容／旧响应／空页／阶段倒退 | 幂等、保留新鲜完整候选 |
| J04 | JRA 名单展示 | canonical runner／participant／revision 零增量 |
| J05 | 普通 PENDING、FAILED、IGNORED | 不因候选存在就公开，仅校验白名单可见 |
| J06 | TRA 只有 enrollment 尚无完整赛卡 | 已校验 JRA 名单不空窗 |
| J07 | TRA 使用不同马匹 ID 首次成功赛卡 | 一套 canonical 选手，事务内切换且停止 JRA |
| J08 | 切换后门禁失效、取消、改期、T+5 | 不退回旧 JRA 候选或过期名单 |
| J09 | BASIC 与 owner／人工锁／原值冲突 | 仅 UNMANAGED 补空或同来源值；接管后零写 |
| J10 | 通用 apply 服务、后台 POST、批量入口 | 标记 RUNNERS/BASIC 均拒绝；普通候选保持 |
| J11 | 默认关闭、关闭后积压／在途、重开 | 关闭态零网络零写，不复活过期候选 |
| J12 | HTML、URL、原始证据 | 仅安全字段输出；外链限定官方且不跟随越界重定向 |
| U01 | 历史 scheduled 无时间／有时间 | 赛期已过资料待补，不再赛前 |
| U02 | 即将开赛、运行、延期、取消 | 筛选和显示一致，过期不混入 |
| U03 | 已完赛但结果未公开／旧 confirmed 行 | 正式公开门禁决定筛选，不以一行结果绕过 |
| U04 | 北京与当地时间、夏令时、仅日期 | 明确时区、当地日期分组不变 |
| U05 | 出马表缺失／闸位 0 | 本站暂未收录／—，不推断上游未公布 |
| U06 | 日历／详情查询数量 | bounded query，无逐赛事查询新增 |
| A01 | 只读 audit | 缺赛时／名单、过期、暂定、匹配与超期检查有界输出 |
| A02 | 829 精确别名及历史 inventory | 不模糊合并；恢复包绑定目标基线／来源证据／SHA |
| P01 | PostgreSQL 并发 claim／候选与纳管 | 行锁和 token 保护，无重复 canonical／过期写入 |
| P02 | 设置、env、Compose、迁移 | 默认关闭一致、无迁移漂移、关闭 JRA 不关闭 TRA |

## 通过标准

新增回归先观察业务断言 RED，再实现 GREEN。受影响模块、Django check、迁移检查及 PostgreSQL 专项通过；全量 CI 与相同环境基线比较，新增失败为零。已有失败不得删除或弱化掩盖。独立代码 reviewer 对冻结候选 APPROVED，复审保持同一 reviewer。

## 发布时单独验证

真实接口正式性、JRA 页面阶段、实际请求预算及自然 D−4 调度效果不能由合成测试证明。生产数据修复按重新冻结的名单执行，79 是原排查快照；本阶段只准备可审阅修复包和发布包，不写生产。不满足外部正式性合同的结果仍暂定，不能用时间推断确认。
