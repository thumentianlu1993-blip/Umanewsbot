## 1 测试环境与证据

自动测试使用脱敏固定 HTML/JSON、mock 模型/来源响应、隔离 PostgreSQL 和测试队列。不得连接真实生产数据库、Redis、任务队列或第三方服务。Celery、并发、事务和迁移场景不能仅用 SQLite 或同步 mock 宣称通过。用户路径须浏览器实际操作；真实付费、生产写入和发布的边界统一按根 [AGENTS.md](../../../AGENTS.md)。

行为变化先取得能捕捉原错误的 RED，再实现和复验。低影响纯文案/链接等使用针对性检查，不机械添加镜像实现的单测。保留旧版固定 SHA 的基线失败集合；新增失败必须闭合，与本次路径相关的旧失败也不能直接豁免。

每条证据包含：用例 ID、输入版本/哈希、候选 SHA、环境、目标范围、预期与实际结果、时间、失败原因、对应修复/复验。代码、隔离副本、自然运行和公开页面分别记，不相互代替。生产样例时间使用北京时间，原始来源时间保留其时区。

## 3 测量和分母

信息错误率 = 出现至少一项关键错误的审核场次 / 实际完成关键资料审核的场次。空缺不纳入“正确场次”，需同时报告所有目标数、可审核数和资料覆盖率。

卡顿率 = 至少错过一次阶段或公开更新期限的场次 / 窗口内所有应推进场次。包含未登记、来源空缺和任务未执行；外部原因单列，但不默认移除。相同场多次卡点主指标只计一场，附阶段次数和持续时间。

离线和自然运行分开计算，不能相加成更好看的比率。固定验收集至少 300 场时，2/300 <1%，3/300 不通过；卡顿 8/300 <3%，9/300 不通过。重大身份、虚构确定资料等错误即使总比率低也阻断上线。

当来源只有“上次未见/首次发现”区间时，公开时延也输出上下界。上界超过目标就不能记作已证明满足时限；必须补更密观察或明确未验证。不把本地入库时刻伪装成来源发布时间。

自动完成率只在满足输入条件的任务中度量，但必须另列所有未满足输入条件的目标和原因，避免把失败从漏斗删除。人工耗时基于同样六项任务，不以总工作量下降或少发内容推断交互改善。

完整候选 O06 计划 10/23 16:00 开始，全量 O08 计划 10/28 16:00 开始，共同最终截止为 10/30 16:00，分别达到 168 和 48 小时。使用真实启用时间、固定候选/配置、对象范围和有效区间判断，不按计划时刻推定通过。

A 线负责 R16 的可重算逐场账本及末段增量：12:00 为预报，16:00 冻结最终输入，16:30 前输出完整质量报告。报告包含 `window_start`、`window_end`、`snapshot_id`、`input_sha256`、`policy_version`、`candidate_sha`、目标/应推进/可审核/缺失数、错误与超时场次、来源时延及未验证项。R 独立核对增量、共同截止及哈希；协调者准备 V06/V07 汇总，不将 R16 预报当最终通过。V06 17:00 前交付，V07 18:00 前完成终审，报告主体提前准备。
