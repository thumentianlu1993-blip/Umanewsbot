## 2 每个实际包必须填入的内容

- 精确 PR/commit、构建 tree、镜像摘要，以及适用环境/地区/来源/对象名单。
- schema 增量及顺序、索引和唯一约束、旧应用兼容性。当前规划可能新增任务/证据/阶段账本字段或表，但尚未分配迁移号；复用既有表优先，不能预先承诺“无迁移”。
- 配置差异：模型适配和预算、新闻质量/选稿/周覆盖、赛事统一决策/轮询/成熟度、马匹发布、关系重建、后台续跑、QQ 禁发、前瞻及独立探针。实际名称由 F01 和各实现任务锁定。
- Web/worker/beat/探针需要重建或重启的清单，任务路由、并发/速率及共享队列影响。
- 固定输入的数据动作：近年档案、现成名采纳、旧公开结果、重复赛事、正文重处理、存量关系；分别附对象数、SHA、预期增量、冲突和恢复点。
- 实网来源和付费模型用量范围、已有权限有效期和预算；不将账号存在当作已允许无限调用。
- 验证样例和自动停用条件，回退代码/配置/数据方案；已公开内容及人工修正的保存方式。

实际执行与批准规则引用根 AGENTS.md。本文的时间表不是这些尚未产生的包已经获得生产授权。

## 3 兼容发布顺序

1. 对齐固定候选和当日运行版本；核对共享 worktree、release lock、活跃数据任务及暂停批次。保留其他线程内容，长任务依赖固定 SHA/镜像。
2. 备份并在隔离环境验证恢复；检查 O02 的已知唯一约束缺陷确实闭合。确认镜像与 schema 都具备明确恢复面。
3. 应用向后兼容的增量 schema/索引，避免整表长事务；大数据转换使用独立可重跑批次。索引创建和约束验证策略由数据规模决定并在副本测时。
4. 部署能兼容旧数据的新代码，新增自动化默认关闭或影子；热身、健康、资源与关键页面通过后，再按实际包启用限定范围。
5. 来源/证据/身份链先就绪，再启用确定资料读写和期限调度；可靠结构化更新保持快速路径；长模型研究使用有界资源，不能堵塞赛事控制队列。
6. 名称/马匹/关系候选先验证再公开；数据修复按类型独立输入包，事务内不抓取网络、不调用模型，提交后发送可重试的内部变更事件。
7. 启用前瞻/赛后稿之前，复验名单版本、取消/开赛状态和事实证据；仅重点赛事，公开格式与引用展示合同一致。
8. QQ 停用同时涵盖新触发、旧重试、手动入口、beat 和专属依赖；保留历史记录。共享邮件等非 QQ 能力不得误删。
9. 按地区和模块核验数据及公开页，检查真实队列下一动作，不以 HTTP 200/flags/任务 SUCCESS 代替完成。

## 4 生产数据与恢复边界

近期资料、历史名检索和存量新闻关系的目标集在 H01/F06 冻结，动态新增另记。批次采用固定对象与源内容版本，重跑不重复建马、计赛次、发文章或复活已否决关系。并发人工编辑/新赛果到达时验证版本；冲突不靠最后写入强行覆盖。

每批核对：原目标数 = 公开完成 + 明确无资料/无现名 + 身份/事实冲突 + 运行失败。后面三项不能计为公开完成。恢复只回退本批引入的错误且保护之后的合法更正；有复杂交叉引用时优先暂停并前向修复，不能无条件用旧整库覆盖在线新数据。

旧历史采集暂停状态、冻结 `race_live` 队列及无关资源均保持原边界，除非具体包明确包含变更。来源条款续期与过期日期在 O01/F03 核对；不能因为排期需要而自动延长。

## 5 回滚与中止信号

自动检查包括：新增重大身份/事实错误、数据唯一约束破坏、公开跨版本混合、重复副作用、关键期限持续违约、队列/内存资源失控、未经范围内的请求或 QQ 发送、无法恢复。出现问题停止受影响模块扩大范围，保留运行证据和原失败指标。

建议回退顺序：停止新增触发和对应任务领取 → 等待/隔离在途对象 → 关闭受影响公开新路径或回到兼容读模型 → 回退配置/代码 → 对固定坏批次执行经过验证的恢复/前向修正 → 验证旧路径、新数据兼容和自然更新。恢复已验证内容时保留新 schema 和审计，通常不做不可逆 down migration。

模型不可用时让结构化快路径继续；语义不确定内容有界待处理。前瞻过期不能在恢复后补发为新稿。QQ 在本版回滚时仍应保持停用意图，具体兼容旧代码的阻断配置需随包验证，不能因应用回退意外恢复发送。

O07 在副本演练实际候选，并记录实测恢复耗时和数据恢复点。10/28 全量后若关键修复/回退重置观察条件，V06 重新计算有效稳定窗口，明确 10/30 DDL 是否仍能满足。
