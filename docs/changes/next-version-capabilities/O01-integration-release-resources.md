## 集成、生产和 schema 顺序

本地 integration lock 已采用持有进程的 `fcntl` 排他锁，覆盖短时集成/推送；台账记录 owner、线程、操作、SHA、资源、开始时间与 PID，退出释放。长测试绑定归档/固定镜像，不占锁等待模型审核。

生产当前入口为 `deploy/deploy_0079.sh` 与 `deploy/release_0079.py`，现状 schema0079；不能用旧0078入口、普通 compose up 或直接 restore_db 代替精确发布流程。既有 deployment_lock.sh 使用 token hash、PID、action、开始时间和 Compose 信息，顶层 wrapper 在正常退出与受捕获信号时释放；它不能单独证明根 AGENTS.md 所要求的完整 owner/线程/SHA/资源域及持续存活。生产包准备时须把进程生命周期锁和审计绑定补齐或提供已核等效实现，并保留已有恢复 intent 的 fail-closed 语义，不按时间删除残留锁。本文件未更改锁实现或生产运行。

首批 F01/U01/F02 与 Q01/Q02 已审切片没有迁移；H01/B005 当前是只读工具及测试接通。后续账本、身份/关系等 schema 尚未分配编号，由 A 汇总实际 models 差异并以届时 main 的叶子分配。发布顺序沿 [rollout](rollout.md)：完整恢复可用 → 向后兼容增量 schema → 默认关闭/影子的新代码 → 来源和身份证据链 → 固定范围写入与公开。不得提前承诺所有后续包无迁移。
