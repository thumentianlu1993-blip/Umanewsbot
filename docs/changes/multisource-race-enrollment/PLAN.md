## 1. 当前问题与方案结果

详见 [根因](ROOT_CAUSE.md)与[证据](EVIDENCE.json)。104 没有来源身份、Enrollment、LifecycleControl 和赛果；TRA 的日本 free 出马表为空；已有 JRA 13 匹赛前候选及正确赛时没有完成接管。census 开赛即排除、身份发现 T+5 停止，覆盖告警又只检查已登记赛事。

目标结果：JRA 或其他已准入来源命中 104 后即可建立一份赛事登记；到时推进状态，完整正式赛果进入既有 revision/publication 链。TRA 后来命中时只挂接到同一个 event，不再生成登记、重复名单或重复公开赛果。其他地区走同一个机制，不为日本写一套绕过通用准入的特例。

## 2. 锁定的产品语义

1. **来源发现互不阻塞。** 一个来源空响应、超时或未开放，不阻止同地区其他已准入来源的发现。来源按政策及预算公平轮转，不等待 TRA 先失败才允许其他来源发现。
2. **登记与资料能力分离。** 可信来源身份唯一命中现有公开赛事即可登记；日期／身份来源、仅赛果来源也可建立覆盖记录，不再强制同一个来源同时有赛时、出马表、赛果。只有具备对应能力与合法证据的 binding 才可驱动该资料写入；登记成功不代表赛时已知或完整赛果已确认。
3. **一个 event、一份登记、一个数据同步 owner。** 多源绑定附着于同一登记。各资料能力的首个合法来源粘滞；同轮多个可用来源按 policy 固定顺序决定，后到来源不因为排序更高就抢写。缺失能力可由另一来源补充，连续网络故障或访问拒绝可触发有界备用来源授权；失效来源的替换需通过合同、身份和 generation 校验，并留下变更凭证。
4. **身份去重先于写入。** 名称不作唯一键；可信 ID/跨源链接、比赛发生实例、受审赛事届次为自动匹配依据。名称拼写、简繁、跨语种和冠名变化用于候选召回与核验。模糊相似、自动翻译、音译或 LLM 判断不能独立触发合并。
5. **赛后可补入、缺口可见。** 未来 30 天及过去 7 天的公开赛事进入覆盖盘点；过期未完成项转为持久 incident，不静默消失。已完成的结果更正观察保留现有规则，不借本次重写历史。
6. **状态与结果确认分离。** 可信分钟赛时支持 T→running、T+30→finished；完整来源终态可提前结束。没有分钟时间时不猜时间、不按日期硬改 finished。结果确认必须有完整参赛集合、明确终态及对应来源确认合同。
7. **同场赛后仍可读最后有效出马表。** 停止赛前请求不等于删除有效名单；赛后保留只读名单与最后更新时间，实时赔率按原新鲜度隐藏，正式名单／结果接管后不重复展示。

2026-09-05 旧方案的“整场仅完整来源竞争纳管、其他来源不能独立补能力”会使部分资料来源无法纳管；本方案依据本次用户明确多源要求拟改为上述能力分离。旧流程在 v1 登记上保持运行；新规则经实现和精确发布后才生效，不能改文档就宣称生产已切换。保留字段来源优先级函数，但它不能绕过 binding 选源和粘滞规则自动抢占。

## 3. 本轮不做

- 不自动创建全世界新 RaceEvent；范围为当前启用地区的既有公开 calendar canonical event。外部未匹配比赛保存候选，另有日历导入流程。
- 不自动合并／删除已有 RaceEvent、改 URL 或新建 ProductCanonicalLink；发现已有两个 event 疑似同场时冻结绑定并进入审核。
- 不扩展马匹全球实体匹配、历史全量回填、新闻采集或 QQ 分发，不消费旧 race_live 队列。
- 不把来源网页存在当作生产适配器、自动化许可、访问稳定性或全区域覆盖证明。生产新增来源／网络额度按 AGENTS.md 精确发布包执行。

## 4. 复杂度与完成标准

保留 Django/Celery/现有队列与预算器，不新增平台。需要跨现有身份、登记、claim、provider、生命周期、结果与公开读取修改：只改 discovery 会留下 provider_not_implemented，故超过 8 文件合理。拟增 2 张小表和 2 个聚焦服务（身份解析、来源适配器协议），复用既有审计／候选／incident，不新增第三套登记或任务队列。

完成必须逐地区给出至少一个非 TRA 已验证登记来源，以及两种来源到达顺序的去重用例。某地区访问受阻或证据缺失时标记 coverage_gap，该地区不能宣布闭环；核心上线或日本修复不等于七地区全部完成。全量测试允许已核验基线失败，但新增失败必须为 0；具体冻结指标见 test_cases.md。
