# 术语扫描性能基线修复

当前主线实现扫描 100 篇文章、2 万个别名的既有用例，在 Windows/SQLite 隔离环境实际耗时
15.59 秒，未满足原定 10 秒上限；同一用例也在此前 Linux CI 失败。
本机 cProfile 诊断显示，400 次字段解析反复筛选、排序整个别名索引，累计约 800 万次排序键计算。
诊断本身有计时开销，24.63 秒的 profile 结果只用于定位，不能与未加 profile 的验收耗时直接比较。

最小修复将原有的“文本中不存在则跳过”条件移到语言筛选和排序之前。
仍使用相同的 NFKC/casefold 文本、语言与启用条件、长度优先稳定顺序及正则匹配；
不增加缓存、依赖或索引框架，不改变身份、证据、替换、提交或发布规则。

本地修复后，原 `stable.test_public_term_consistency` 全模块 41 项在 3.573 秒内通过，
其中包括原 10 秒门槛、查询数上限及恒定查询量断言，以及冲突、位置偏移、原文保留和事务回滚测试。
没有修改测试、放宽断言或跳过用例。该耗时是整个模块的测试执行时间，不含数据库准备。
原始 RED、诊断分别保存在本机 `runtime/diagnose-term-performance/`，GREEN 在
`runtime/fix-term-scan-performance/local-tests.log`。

交付记录须补齐固定候选的 Linux/PostgreSQL 16 全量对照及独立只读审核。
不执行历史新闻修复、生产 dry-run 或生产内容写入；人工交付边界统一见根 `AGENTS.md`。
