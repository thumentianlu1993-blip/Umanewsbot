# 第4项执行器验证边界（2026-10-31）

本轮新增P02独立执行器，旧0078/0079的摘要与恢复入口保持原样。当前实现仍不是生产发布包；后续交付统一按根[AGENTS.md](../../../AGENTS.md)。

## 已实现

- 宿主锁兼容既有发布锁，子进程仍在执行时保持锁存活；数据库单连接持有独立会话锁。
- 初始意图先于停服，绑定候选提交、镜像、数据库、配置与唯一恢复目录。只接受精确0079起点，逐事务执行0080、0081、0083、0084、0085、0086，记录每步意图与完成回执。
- 七个schema状态由隔离PG16实测并冻结，检查所有app recorder与public catalog；备份、角色权限、配置、静态/媒体及旧镜像分别验证。
- 首次DDL前核对每表行内容摘要、业务序列和权限；备份后修改同样行数的数据也拒绝。Django recorder序列允许事务回滚空号，但下一值不得重复已有记录。
- ACL保留NULL与显式空权限区别；成员关系包含grantor、继承和SET能力。隔离恢复保留源集群OID 10初始化管理员身份，角色备份仅精确跳过该角色已存在的CREATE语句，ALTER与GRANT原样执行，不归一化业务授权。
- contained证书文件链接以私有普通文件备份；目录链接、越界链接与复制期间变化拒绝。材料放在checkout之外，仅允许绑定本intent的精确恢复marker出现在Git未跟踪清单。
- 静态收集和只读探针关闭writer、使用内存broker；正常恢复检查实际镜像、环境、命令和服务集合。intent后失败，包括收尾回执失败，均尝试逐个停止writer；清理失败显式报错，保留材料。
