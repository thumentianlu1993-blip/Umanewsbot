## 已确定的修复路线

采用“保留原物理数据库 → 停写切点完整dump → 独立副本按受审规则修复 → 新dump向第二空库严格恢复 → 校验 → 第5步受控切换”的路线。原因是源端索引与heap已有读取不一致证据，不能把副本缺约束的ALTER动作照搬到生产；原始dump也不是单独可用的完整回滚点。

本包的切点定义为 `rehearsal_cut_id`，只用于第4步演练。恢复源库写入后，所有基于这个切点的副本都成为历史副本，**禁止直接作为第5步切库目标**。第5步必须另取 `release_cut_id`，在新切点后持续停止全部writer，重新完成修复、严格恢复、校验及切换。当前方案不包含增量追平；若未来采用增量同步，需要另行设计、完整性验证和范围确认，不能只允许一个未量化RPO来绕过。

本轮修复规则和隔离工具已经验证新闻39条、术语373条重复主行及证据5条/窗口48条碰撞处理。其固定计划只绑定旧切点副本。新切点必须重新生成全量重复分母、FK/软引用及before-image清单；任何规则未覆盖状态保持拒绝，不扩大原生产apply范围。第4步可修复新隔离副本，不能因此写生产源库。

## 空间前置：先完成，后申请停写窗口

用户已明确禁止购买额外存储，原扩容建议取消。生产仍仅有100GiB系统盘。本轮按已授权清理范围删除停用OneBot超过7天的468个日志及701个无标签、无引用、已确认归属的旧镜像，释放8,168,353,792字节；清理后复核可用18,602,373,120字节。未删除数据库、Redis卷、登录资料、备份或发布目录；七服务身份和restart未变，五项公网探针200。固定清理manifest SHA为 `a02a95fd936b2b824675effe6d6e64bb882a1ffe17ad671c223a42703a44aa97`，一次性执行已完成，不可重复执行。

新候选将全行JSON排序改为固定32字节逐行SHA256排序，算法标识 `sorted-sha256-row-json-v2` 进入校验摘要；旧算法收据不得复用。独立空库流式严格恢复与来源库的129表、128序列、目录和权限核对通过，共13,392,635行。读取过程中采样临时文件最高279,625,728字节，采样值不是严格峰值；本机验证另设置每进程1GiB临时文件限额、4MiB work_mem、关闭并行排序。生产执行器尚未绑定这些限制，不能宣称生产已有同等硬约束。

保留不同数据库身份的A/B两个独立副本，不采用删除A后将B作为自身恢复证明的方案。两个历史恢复PG卷实际合计12,307,394,560字节，仅用于容量估算；dump优先流式传输并存于已有本地空间，避免在生产保留重复临时dump。剩余空间仍需覆盖WAL、临时排序、失败现场和安全余量。当前可用量只说明存在进一步验证的空间，不证明生产准入：最终manifest必须绑定新切点体积、并发进程数、磁盘硬阈值及超限退出/原服务恢复措施，并完成实际峰值测量。不能削减备份或完整性校验来凑容量。

不购买或扩容磁盘，不继续清理有标签的回滚镜像、历史备份或其他任务资源。若实测不满足空间预算，继续调整有界执行方式；未经验证不进入生产双副本操作。

## 可审的采集窗口范围

目标主机为既有Umanews生产主机，Compose项目`umanewsbot`；旧应用revision `df2f376a6718f39c3f31694f6b320bdda6e161dd`，运行image `sha256:3fcf9090af794f98fffa0f33f110e02126b491fd0caab5df6b9dd1be69bc20f9`。开始前必须重新核身份；旧服务、配置、证书、Redis和数据库身份/存储路径都进入私有不可变manifest。空间先决条件未满足时不进入此窗口。

拟定停写上限30分钟，含恢复原服务的预留；它是中止预算，不是已承诺RTO。现有DB/Redis不重建、不迁移、不清队列，不修改数据库行，不改变功能开关的最终原值。不合并代码或启用P02。

1. 单一release coordinator取得自动释放共享锁，固定owner、聊天、operation、候选SHA和资源域。核对所有本地/外部writer及其他任务；若仍有活跃生产采集或不明writer，不自行强杀。需要跨聊天暂停/恢复协调时，应将明确收件聊天和消息范围纳入授权。
2. 记录原服务运行/停止状态、镜像、有效配置、Beat调度与所有相关开关。停止新Beat投递，安全排空在途任务、暂停后台/新闻/术语写入口；外部writer完成批次后暂停。保留Redis全部消息，核对无活跃写事务及未知写入口。无法在预算内排空则恢复原状态，不开始dump。
3. 在同一关闭态生成保留owner/ACL的完整DB备份、角色和成员关系、私有运行配置、证书/文件布局、真实镜像身份以及数据库所有媒体引用的OSS版本清单。镜像内容可复用同digest已核实归档；实时指针和版本清单必须取本切点，不能以旧在线清单补签。
4. 归档源端先完整落盘、fsync、SHA/大小/TOC校验。capture最长20分钟，余下10分钟预留检查与恢复；失败保留部分产物并判失败。TOC通过不等于完整恢复通过。
5. 采集结束在原镜像、原数据库、原配置恢复此前运行的服务，不启动原本停止的服务；恢复顺序为只读健康检查、原worker、原Beat/入口。验证七服务/公网健康/实际配置/队列状态；只恢复本任务暂停的外部作业。若原服务恢复失败，继续持锁处置并通知，不能因为预算耗尽就强行宣称恢复或放弃现场。
6. 释放本任务锁；所有完整恢复、去重和媒体字节验证移到隔离副本，避免把远程大文件下载时间计入本次演练采集的生产停写。恢复源库writer时永久将本次副本用途标记为rehearsal-only，不授予切库资格。OSS按已冻结版本下载不依赖后续latest，拟覆盖约9323对象/0.97GB，实际范围按新切点清单固定；不增加新闻/赛事第三方抓取。

批准之前，必须把执行脚本、存储目标、输入身份、镜像、配置、预算和恢复命令固化到manifest及SHA，并完成独立review；本草案不是该最终manifest。若存储条件、协调范围或writer清单尚不明确，先继续只读准备，不要求用户批准不可审的动作。

## 生产形状验证与第4步完成条件

在获准资源上，用相同CPU/内存限制及原生amd64、独立数据库/Redis/网络完成新切点修复→严格往返恢复→六步迁移→关闭态读探针→故障恢复。生产应用始终继续使用原库；隔离环境无真实外部凭据、无端口公开，禁止向生产DB/Redis发测试。

需采样数据库/临时文件/WAL/镜像/备份的峰值空间、内存、锁等待和每阶段耗时，不能沿用本机累计BlockIO。完整恢复媒体版本字节，校验全部引用；既有生产RDB已禁网恢复9728键及race_live=7543，但不含其后AOF增量；窗口仍需冻结并验证完整Redis持久化集合及队列身份，不能以旧RDB或三条合成消息替代共同切点保留证明。停写期间取得的持久文件和数据库必须有共同cut ID；角色/config/OSS切点证据仍缺任一项则不签production_shape。

第4步完成需同时具备：固定候选CI及独立review、当前完整恢复材料、去重修复和恢复路径、生产形状性能/RTO实测、可审核的第5步发布包。当前隔离证据只满足其中已列明部分。
