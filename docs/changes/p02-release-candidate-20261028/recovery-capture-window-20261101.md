# 第4项下一次恢复材料采集窗口

这是基于[11月1日只读证据](production-readiness-20261101.md)准备的资源协调及采集顺序。15:12已按用户授权完成一次协调暂停，后续负载未过预算、未进入备份；见[窗口结果](recovery-window-result-20261101.md)。不包含生产数据去重、索引修复、停服、迁移、切库或发布。人工门禁仅引用根[AGENTS.md](../../../AGENTS.md)。

## 先协调共享资源

用户已明确授权并已向“P04 马匹信息”发送以下范围的协调消息：

> 请在当前在途请求、已批准批次与回执全部收尾、台账闭合后安全暂停连续采集，保留队列、固定版本、原授权与证据；不要强杀在途请求或清理未知状态。确认本任务持有的共享锁已正常释放，并报告是否有未解决请求。为P02只读恢复材料采集留出窗口；窗口结束后，在原有范围与有效条件不变时恢复原速采集。任何状态不明先保留暂停并说明。

P02不自行终止P04进程或代其释放锁。是否恢复须结合窗口结束及P04原有条件核验，不能跳过其未知请求/版本漂移检查。跨会话协调消息需要用户明确授权。

## 窗口内先核状态，再决定是否采集

1. 核实实际commit/image、DB身份/schema、锁、在途操作与资源。身份或配置漂移时重新绑定证据，不沿用本轮观察值。
2. 连续观察3次、间隔20秒：拟采用的保守启动条件为1分钟负载不超过CPU核数、可用内存至少2GiB、SwapFree至少1GiB、磁盘余量足以同时保留原库与本次备份。数值是本次拟定技术预算，不是已测得的生产RTO。
3. 若仍高负载，继续有界只读定位网页读取和流量，不启用整库备份，也不自动限流、封禁、调参或停止服务。共享锁释放与CPU余量分别判断，不能认为暂停采集必然解决负载。
4. 启动前冻结采集脚本及输入身份、源端私有产物目录、输出位置、预期最大空间/时长和自动取消条件。备份仅对源数据库读取；不要使用会去掉owner/ACL的通用备份选项冒充完整权限恢复材料。共享资源锁按根AGENTS管理，不抢占其他存活任务。

## 采集与隔离验证范围

- 数据库：用匹配PG16客户端生成保留owner/ACL的完整custom-format归档，单并发，有限锁等待和语句/总时长预算；本机磁盘/资源先检查。优先源端完成私有归档后再传输，避免慢网络长时间拖住快照；超预算仅取消本次备份并保留失败证据。`nice`不能保证降低源端数据库后端的CPU占用，不以此代替资源检查。
- 配套材料：在同一采集窗口重新取角色/成员关系、运行配置、证书与必要持久目录，固定实际旧镜像并验证归档载入。原始凭据只进入私有备份，隔离应用使用禁网和去除外部凭据的派生配置。
- 媒体：从新数据库副本枚举全部引用，记录OSS的具体对象版本、大小与摘要并验证恢复。Bucket开启版本控制或少量样本成功均不等于全量引用齐备。
- 新副本：先保留原始副本，重新核实字节重复分母、状态及全部引用，拒绝未覆盖的新状态。对索引差异采用经EXPLAIN确认的完整表扫描来确定对象。既有隔离工具绑定旧备份，不能只替换摘要或旧映射来放行新范围；适配新材料须保留绑定、独立review与拒绝测试。
- 在新副本验证修复，再生成新的完整备份恢复到空库，核对全部表内容、序列、角色/权限、catalog和关键业务。最终才继续生产形状的迁移、服务与恢复演练。

在线数据库快照不保证数据库、配置和OSS天然处于同一个全局切点。此窗口最多补齐新鲜演练材料；正式停写切点与可接受RTO仍需精确生产包和实测。本轮没有可执行生产修复manifest，不能把以上采集顺序当作生产apply授权。
