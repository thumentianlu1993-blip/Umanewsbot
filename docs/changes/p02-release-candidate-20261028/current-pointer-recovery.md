# 第4步：当前生产配置目录指针的恢复兼容

## 真实触发与范围

2026-11-05只读盘点发现，`upcoming_racecard_urls/current` 是指向同一挂载根内 `generations/<sha>` 的相对目录链接，目标目录及其文件均已归档。现有 `config_inventory` 拒绝所有目录链接，因此真实生产形状的发布会在停服前被拒绝。该拒绝记录保留；不通过跳过该挂载、删除链接或修改生产配置放行。

本修复只让配置恢复包保留这种已存在的内部目录指针。静态/媒体归档默认继续拒绝链接；配置根不能是链接。绝对目录链接、越界、悬空、循环、特殊文件仍拒绝。文件证书链接沿用已有物化语义。生产资源、数据修复范围与开关不变；人工门禁仍只引用根AGENTS.md。

## 实现约束

- 配置清单记录内部目录链接的相对目标，遍历实际目录但不跟随别名重复遍历。解析后必须位于同一源挂载根内，且目标为真实可达目录。
- `materialize_config` 先复制目录/普通文件，再恢复相对目录链接；复制前后源清单与目标清单必须一致。将 `current` 物化为普通目录会破坏后续原子替换指针，因此不采用这种做法。
- 归档新增显式、仅用于配置备份的内部目录链接支持；默认接口保持拒绝。清单同时绑定普通文件摘要与链接目标。归档验证检查全量成员唯一性、链接目标与清单一致、无越界/悬空/循环及链接路径下的伪造成员。
- `DockerRuntime.backup_and_restore` 只在配置归档调用开启该能力。关闭态漂移检查、无覆盖发布、权限私有化与生产形状证明均保持。

## 验证

先复现真实形状的最小反例：`generations/<sha>/manifest.json` 与 `current -> generations/<sha>`。验证物化、归档、隔离解包后链接仍可读且可由新指针原子替换；普通资产接口仍拒绝。负例覆盖绝对/越界/悬空/循环、归档链接篡改、链接下成员注入和重复成员。通过后由原独立审核上下文复审，并在最终固定候选重新完成所需CI与对应演练。

## 实测与审核

最小真实形状先得到 `P02 unsupported configuration member` 的RED；修复后配置指针复制、tar往返及原子替换通过。实现进一步限制目录目标为规范相对路径、不得包含`..`或经过其他链接。配置目标已存在时拒绝，防止沿预置链接写出。相关执行器/影响合同37项通过，原审核上下文独立验证合法归档及11种拒绝场景后PASS，无P0–P2。
