## 问题陈述

Horse Racing Nation（HRN）详情页的真实正文位于 `.article-body`。当前
`HorseRacingNationAdapter` 只声明 `article, main`；当页面没有语义 `<article>` 时，解析器会选择
整个 `<main>`。因此顶部 ticker、登录入口、标题/作者区、右侧 Related Pages 和 Top Stories 等网页框架
被当作原文正文保存，随后进入翻译、改写、审核与公开展示。

公开文章 `9623` 和同源文章 `9519` 已只读复现同型污染，证明这不是单篇文章特例。

## 范围

1. 为 HRN 详情页声明来源级可信正文容器，禁止以 `main` 或其他页面级节点作为 HRN 正文兜底。
2. 在可信容器缺失或清理后为空时保持 fail-closed，并保留现有可审计解析状态。
3. 使用真实 HRN 页面结构的最小 fixture 覆盖问题页面，并使用正常文章反例证明正文开头、结尾、段落、
   小标题、引用、列表和表格文本不会被过度裁剪。
4. 在国际抓取进入 upsert 前拒绝选择器失败、清理后为空或无正文的详情，确保失败页面不创建/更新文章、
   不触发术语发现或翻译，并写入 CrawlJob/来源可见错误证据。
5. 为历史 HRN 文章提供只读、分批、可复跑的候选识别方式；输出文章 ID、解析状态、命中选择器、
   原始 HTML/正文前后哈希、长度和候选原因，不直接改生产数据。
6. 扩展现有 `repair_article_content_boundaries`，使历史写入必须绑定精确批准 manifest/file SHA，并在同一事务
   锁定全部目标行、逐篇复核输入哈希后才进行任何写入；规定未来经单独审核/授权的重处理顺序与失败边界。
8. 在实现确认后同步仓库工作流契约检查器及其 mutation test，使八阶段字符串可被机器验证；当前方案阶段只记录
   已确认的旧字符串不匹配，不修改脚本或自动化测试。

## 非目标

- 不在公开模板或 CSS 中隐藏脏段落。
- 不按“当前、热门、登录、免费注册”等中文结果建立单词黑名单。
- 不为文章 `9623` 写 ID、URL、标题或正文特判。
- 不修改翻译提示词来要求模型猜测哪些文字是导航。
- 不重构全部国际新闻适配器，也不在缺乏真实证据时替换其他来源选择器。
- 不新增模型字段、数据库迁移、依赖、Celery 队列、环境变量或前端页面。
- 本阶段不编写/修改自动化测试，不修改应用代码，不重处理历史文章，不部署或发布。

## 功能要求

### R1：HRN 必须只从可信正文容器提取

- 当页面包含 HRN `.article-body` 时，只允许该节点及其正文子节点生成 `body_ja_raw`。
- 页面级 ticker、登录区、breadcrumb、标题/作者元数据、分享区、相关推荐和热门故事不得进入原文正文。
- 选择器元数据必须记录实际命中的 `.article-body`。

### R2：选择器漂移必须 fail-closed

- 当 HRN 页面不含可信正文容器时，正文为空且状态为 `selector_not_found`（或等价明确失败）。
- 不得回退到 `main`、`body` 或全页文本。
- 国际抓取必须在调用 `upsert_article_from_draft()` 前检查解析状态和正文；失败详情不得创建或更新
  `NewsArticle/NewsSnapshot`，不得触发术语发现、翻译、改写或公开链路。
- 失败详情应计入现有 detail failure/CrawlJob/来源摘要；同轮其他文章继续处理。

### R3：合法正文结构必须保留

- 保留正文第一段和最后一段。
- 保留段落、小标题、引用、列表项和表格单元格的文本及原有顺序。
- 通用清理规则只能继续删除可信容器内部明确的结构化噪声、独立 URL 或 CTA；不得以宽泛词语删正文。

### R4：历史影响识别必须只读且可审计

- 只扫描明确指定的来源、ID 范围和批量上限，按文章 ID 稳定排序。
- 缺少 `original_content_html`、选择器失败、清理后为空和正文发生变化必须分别记账。
- 候选结果必须含输入选择条件、文章状态、人工字段状态、原始 HTML SHA-256、旧/新原文正文 SHA-256、
  当前有效公开正文 SHA-256、解析状态、选择器和长度差；输出不得修改数据库、触发网络、翻译、改写、发布或 QQ。
- 批次输出保存后计算文件 SHA-256，作为人工审核与未来重处理的输入证据；输出不得包含凭据或无关完整 HTML。
- 部署前已存在的全部 HRN 文章均属于历史审核 scope，不得只选择 `before_body_sha != after_body_sha` 的行；
  changed/unchanged、当前有效正文层和哈希只是分类证据，防止重复抓取先更新原文层后漏掉仍然污染的旧中文稿。

### R5：历史重处理必须分门禁执行

- 历史候选识别与历史重处理是两个阶段；识别结果不自动批准重处理。
- 未来重处理必须使用明确文章 ID 的批准 manifest，先备份与 dry-run；commit 必须同时提供精确 manifest
  文件 SHA-256。批准 artifact 必须使用 schema v2，并逐篇绑定文章集合、`updated_at`、原始 HTML、旧原文正文，
  以及 commit 将持久化的 `title_ja`、`body_ja_raw`、`body_ja_normalized` 和解析元数据输出哈希。
- 解析元数据哈希只覆盖实际持久化的 `body_parse_status/body_selector/body_cleaning`，使用 UTF-8
  `json.dumps(..., ensure_ascii=False, sort_keys=True, separators=(",", ":"))` 的 canonical JSON 计算 SHA-256。
- commit 在单一事务锁定全部目标行后重新解析并复核上述全部输入/输出。legacy schema v1、缺少 v2 字段或任一
  parser 输出漂移时整批零写入、零 OperationLog。
- 原文正文重解析、中文翻译刷新、既有改写稿处置和公开正文验收必须分别记账。
- 若文章存在人工编辑正文，默认转人工决策，不自动覆盖。
- 若有效公开正文来自 `rewrite_body_zh`，只更新翻译字段不足以完成修复；必须按审核决定重跑改写或显式清除/
  替换旧机器改写稿，并验证 `effective_body` 已切换到干净内容。
- 重处理不得重新发布文章、改变 `published_to_web_at`、创建重复文章或新增 QQ delivery。

### R6：工作流必须包含实现确认断点

- 方案审核通过后，在用户明确G1 范围确认前，禁止写测试、改应用代码/配置/迁移、启动实现 subagent 或重处理历史数据。

## 失败边界

- 可信选择器未命中：该篇失败，不使用宽泛兜底，不影响同轮其他文章继续处理。
- 可信容器命中但正文为空：该篇失败，不恢复清理前文本。
- 解析失败详情在 upsert 前被拒绝；不得创建空正文文章，也不得以新 HTML/metadata 覆盖既有文章或触发翻译。
- 正常反例出现首尾缺失、结构项丢失或顺序变化：测试失败，禁止实现进入 review。
- 历史识别缺少 HTML：记录 `missing_original_html`，不得联网补抓后静默替代历史证据。
- 历史识别或重处理出现文章集合、输入哈希、标题/raw/normalized 正文或 canonical parse metadata 任一输出哈希
  漂移：事务内整批停止并零写入，不接受新状态为原批准基线。
- 翻译或改写失败：保持修复前公开稿与发布状态，留下失败证据，不重复推送。
- 生产部署后新抓取仍出现页面框架：暂停 HRN 来源或其自动发布资格并按代码回滚路径恢复。

## 验收标准

1. 文章 `9623` 对应 HRN 页面结构中的 ticker、工具、登录和推荐文字不进入提取结果。
2. 上述网页框架不会进入新采集文章的 `body_ja_raw/body_ja_normalized`，因而不会进入翻译、改写或公开正文。
3. 真实正文第一段、最后一段和合法段落、小标题、引用、列表、表格文本均保留且顺序正确。
4. 至少一个正常 HRN 文章反例完整通过，不因通用噪声规则过度裁剪。
5. 缺少 `.article-body` 的 HRN 页面明确失败，不回退 `main/body`。
6. 选择器失败或清理后为空的国际详情不创建/更新文章，不触发术语发现或翻译，并留下 CrawlJob 可见证据。
7. 修复解释并覆盖 HRN 来源结构，不依赖文章 ID、中文译文或已知词黑名单。
8. 所有部署前已存在 HRN 文章可用只读分批方式生成带哈希的审核 scope；未来 commit 只有在 schema v2 精确批准
   manifest/file SHA 和逐篇输入及全部持久化 parser 输出哈希均匹配时才允许整批写入。本任务当前版本不修改生产数据。
9. 聚焦测试、受影响国际适配器回归、Django check、必要静态检查和独立 code review 全部通过后，
    门禁的 mutation；既有 workflow test inventory 保持 `26/26`。
