## 一、统一北京时间展示与列表语义

- 一份公开时间转换结果供归一化展示、详情、日历及首页赛事组件使用：有效`race_datetime`优先；缺失时，本轮兼容已有的Asia/Shanghai完整日期+赛时组合，其他缺UTC记录不在展示层猜测转换。来源字段冲突、DST重复/不存在时刻或非法时区不猜测。
- 截图赛事改为`2026-09-19 04:14（北京时间）`；基础资料日期为`2026-09-19`，时间为`04:14`，标题/时间字段明确北京时间。去掉当地时间与IANA时区名。今天/明天、日期分组及首页“下一场/本周”使用同一北京日期。
- 数据库查询使用同一公开时间表达式：已验证UTC瞬时转Asia/Shanghai日期/时间，兼容当前37条Asia/Shanghai完整日期/时间组合，直接按明确+08偏移计算。不为未来未知样式搭通用时区推断器；其他缺UTC组合先保持未定并记数据缺口。不要凭举办地区推断时区，未知/DST有歧义的记录保持未定；不要把查出的一页先局部重排。
- 默认窗口、全部/重点筛选、年份/搜索、向前/向后游标、日期分组必须同步切换。显式年份筛选按公开北京日期；实施复审补充：北京日期未定时，仅以既有届次year保留年份检索入口，仍进入待定分组末尾，不用届次猜测日期；已知北京日期不回退届次。URL及`year/edition_year`仍保留赛事届次/身份，不因跨年改路由。
- 精确时间按UTC瞬时升序（等价北京时间升序），同瞬时按ID稳定排序。旧游标升级版本并安全回到首页，不解释为新排序位置。
- 没有具体开赛时间时绝不补00:00。若北京日期仍可确定（例如已确认+08时区的日期），保留该日期并放当日已知赛时之后；不能确定北京日期的，显示“北京时间待定”，进入可分页的待定分组。原始举办地日期仍保留后台，避免假装已经换算。
- 公共时间值在SQL筛选、排序、游标与Python展示之间必须用同一合同测试比对；本轮不新增持久时间字段或批量修改历史源数据。

### 3.3 动态字段与失败语义

- 退赛保留原马号和马匹行，明确“退赛”；不删除行、不重排马号，也不因来源暂时少一行就推断退赛。源稳定runner ID优先；无ID时仅接受本场马号+规范化马名唯一对应，有歧义拒绝更新。
- 退赛状态不能被较旧、缺状态的名单覆写回已登记。恢复出赛必须有更新且明确的来源证据；部分页面、无终止标签、错误赛事、超时都不成为“完整最新卡”。
- 赔率与热门排名不再硬编码空白。保存原值、格式、类型、来源时间/抓取时间；明确区分即时、晨间ML、预测赔率，不混为实时价。暂无赔率为“—”，不伪造0；没有热门排名不自行从赔率反算。
- 官方退赛与已有卡的赔率若来自不同来源，只能按现有字段来源仲裁与精确身份映射受控更新，并分别保留时间/类型；不能把不同来源的整行无证据拼接。实现优先选有完整动态字段的同源卡，减少合并复杂度。
- 赔率独立记录观测时间：来源给出有效更新时间时以该时间判鲜；来源没有时间时，仅在本次实际取得并成功验证该赔率字段的情况下使用抓取时间。身份/整卡/名单检查成功不能推进旧赔率的时钟；来源时间未推进或本次缺赔率也不能使旧价重新有效。ML/预测仍保留类型，不因重新抓取变为实时价。
- 失败不覆盖最后有效名单；公开显示更新延迟。动态赔率独立观测时间超过该赛前层级周期+一次10min调度容差时置空，旧值只留后台；退赛证据保留，不回退为已登记。名单与赔率的新鲜度分别计算。
- 查询时不触发外部抓取，网页访问不消耗来源额度。

### 3.4 最小停用入口
