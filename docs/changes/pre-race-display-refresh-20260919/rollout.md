# 发布边界与恢复约束

用户已明确授权上线，实际发布包与验收记录见release.md。本文件保留容量、停止面与覆盖约束。

- 无模型或数据库迁移；部署应用代码涉及web、普通worker、赛务worker和Beat的固定镜像一致性。
- 新配置`RACE_DATA_SYNC_PRE_RACE_REFRESH_ENABLED=false`为默认值，首次开新绑定来源刷新须列入发布包。JRA沿用既有开关。
- 491沿用原Sporting Life来源；生产NYRA403，取消人工绑定变更。上线时已过赛前窗口，不强行恢复；赛后资料另列范围。
- 772已纳管链必须验证不争用；其余未纳管来源中没有可用HTTP来源的明确留为缺口，不能只看身份任务成功。
- 保持3h/1h/10min。验收至少一个未纳管预览和一个已纳管路径各两次自然到期，核对attempt、来源、候选/checkpoint与双域名实际字段；未观察长周期则明确记录未证明。
- 停用：相应刷新开关置false，重载/停止旧配置worker和Beat，确认旧在途任务退出；过期或已取消lease不得再提交。只读保留最后有效卡并受原公开门禁、正式接管与赔率过期规则约束。仅编辑env不能证明已停止。
- 遵循既有0078前向恢复合同；不普通切旧镜像/整库回滚，不改变历史828/830/924或旧LIVE队列。

## 启用前的请求与容量核算

代码按真实来源（nyra/sporting_life/zeturf/racing_post/nar）与赛事地区计入既有共享快照额度；JRA继续既有jra_pre_race_v1/japan_jra桶。请求频率不变；实际发布已将每来源/地区日请求上限192调整为512，日字节上限保持1GiB。

按全天持续处于该档位估算的单场上限：D−4～D−2为8次/天，D−1为24次/天，D0为144次/天。精确开赛后的停止和共享页面缓存可以减少实际请求，但启用时不能以尚未证明的节省代替容量。

| 同一来源/地区当日D0场数 | 名单请求上限 | 启用检查 |
| --- | ---: | --- |
| 1 | 144 | 还须加同桶其他同步流量及重试余量 |
| 2 | 288 | 若实际额度仍为192，则不足；例如RP美国两场、ZEturf法国两场须按当日清单核实 |
| 3 | 432 | JRA三场还须计发现索引请求；不能只看单卡成功 |

发布前重新读取当时 `RACE_DATA_RAW_DAILY_PROVIDER_REGION_REQUESTS`、`RACE_DATA_RAW_DAILY_PROVIDER_REGION_BYTES`、原始快照磁盘剩余量及现有消耗；以冻结目标清单按桶汇总，明确所需调整值并纳入G2包。单响应有2MiB上限，但预算须按真实快照计量口径和样本体积计算，不能仅放开请求数。若不够且未批准调整，保持新增刷新开关关闭；页面展示修复仍可独立发布。此项是已有容量检查，不新增预算管理系统。
