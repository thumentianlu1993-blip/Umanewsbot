# 专有术语候选发现功能验收记录

## 验收范围

本轮验收覆盖专有术语候选发现、后台候选审核、正式术语确认和操作留痕。

## 自动化功能测试

测试代码位于 `server/stable/tests.py`，覆盖：

1. 四类实体发现：马名、比赛名、骑手名、马主名。
2. 日文标准化、正式术语主词与别名去重、停用术语去重、跨类型冲突。
3. 原文精确校验、置信度过滤、上下文数量限制、幂等证据聚合。
4. 任务成功、失败、关闭跳过和抓取主链路隔离。
5. 工作人员鉴权、未登录跳转和非工作人员拒绝访问。
6. 候选列表关键词、状态、类型、来源、置信度和日期筛选。
7. 单篇文章重新发现。
8. 接受、修改后接受、重复正式术语拦截。
9. 合并到候选、合并到正式术语、明确确认后添加别名、证据保留。
10. 拒绝、忽略、批量拒绝/忽略和非待审核状态保护。
11. 操作日志、正式术语别名搜索和页面成功提示。

执行结果：

```bash
DB_ENGINE=sqlite CELERY_TASK_ALWAYS_EAGER=true ../.venv/bin/python manage.py test stable
```

共 69 项测试，全部通过。

## 本地隔离验收环境

Docker 服务在本机未运行，因此使用本地虚拟环境、独立 SQLite 数据库和 Django 开发服务器部署验收环境，不接触开发数据库或生产数据。

关键配置：

```bash
DB_ENGINE=sqlite
SQLITE_DB_PATH=/tmp/umanews-term-acceptance.sqlite3
TERM_DISCOVERY_ENABLED=true
CELERY_TASK_ALWAYS_EAGER=true
AUTO_TRANSLATE_ON_INGEST=false
```

页面地址：`http://127.0.0.1:8011/admin/`

## 浏览器验收结果

通过浏览器实际完成以下操作：

1. 管理员登录并进入术语候选池。
2. 按关键词和来源筛选候选。
3. 从文章详情页重新触发单篇术语发现。
4. 修改日文原词、中文译词、别名和优先级后接受候选。
5. 将候选合并到正式术语，并明确确认添加日文别名。
6. 拒绝候选。
7. 忽略候选。
8. 批量忽略待审核候选。
9. 检查待审核徽标随状态变化归零。
10. 检查操作日志包含发现、接受、合并、拒绝和忽略记录。
11. 按合并后的日文别名搜索正式术语。

数据库最终状态与页面一致：

- 修改后接受的候选进入正式术语库。
- 合并候选保留来源证据，正式术语新增明确确认的日文别名。
- 拒绝与忽略候选保留证据。
- 单篇重新发现生成成功任务日志。

## 验收中发现并修复的问题

1. 忽略或拒绝成功提示曾显示为“候选已已忽略/拒绝”，已改为“候选状态已更新为‘已忽略/已拒绝’”，并增加回归测试。
2. 正式术语页面在 SQLite 环境下无法按 JSON 日文/中文别名可靠搜索，已改为数据库兼容的别名搜索实现，并增加回归测试。
