# 赛马新闻信息流后台（第一阶段）PRD

## 1. 文档目的

本文档用于指导 Codex 实现“中文赛马新闻信息流 APP”的**第一阶段后台系统**。

第一阶段目标不是做全功能媒体中台，而是**先跑通最小闭环**：

**新闻来源接入 → 定时抓取 → 原文抽取 → 自动翻译 → 人工编辑 → 人工审核 → 发布到网页端**

本阶段后台只有**一个管理员角色**，即系统唯一使用者。抓取、编辑、审核、发布全部由同一管理员完成。

---

## 2. 产品背景

用户希望搭建一个中文赛马新闻网站/网页端信息流产品，从日本/海外赛马网站抓取新闻，经自动翻译后，由管理员手动筛选、校对、编辑，再发布到网页端。

后台的核心价值：

1. 汇总多来源赛马新闻
2. 提高翻译和内容整理效率
3. 保证发布前可人工校对
4. 形成稳定、可追踪的内容生产流程

---

## 3. 第一阶段目标

### 3.1 目标

第一阶段必须完成以下能力：

1. 管理员登录后台
2. 配置新闻来源
3. 定时抓取来源内容
4. 自动抽取标题、正文、发布时间、原文链接、图片
5. 将抓取到的新闻保存为后台候选内容
6. 支持管理员查看原文和自动翻译结果
7. 支持管理员编辑标题、摘要、正文、封面、标签
8. 支持管理员执行“审核通过/驳回”
9. 支持管理员发布到网页端信息流
10. 支持查看文章状态与基础操作日志

### 3.2 非目标（第一阶段不做）

以下能力明确不进入第一阶段：

1. 多管理员/多角色权限体系
2. 复杂审批流
3. 多渠道分发（如公众号、X、Telegram）
4. 自动选题排序算法
5. 复杂专题页系统
6. 高级知识图谱
7. 复杂去重聚合算法
8. 高级 SEO 管理
9. 自动推荐系统
10. 评论、社区互动
11. APP 端原生后台

---

## 4. 用户角色

### 4.1 角色定义

系统仅有一个角色：**管理员**

管理员拥有以下全部权限：

- 登录后台
- 配置来源
- 发起抓取/查看抓取结果
- 查看原文与翻译结果
- 编辑文章
- 审核文章
- 发布文章
- 撤回文章
- 查看日志
- 修改系统配置

### 4.2 默认约束

- 系统初始化时创建唯一管理员账号
- 暂不支持注册
- 暂不支持多账号协作
- 暂不支持 RBAC

---

## 5. 产品范围

第一阶段后台包含以下 7 个核心模块：

1. 管理员登录
2. 工作台首页
3. 新闻来源管理
4. 抓取任务与候选新闻池
5. 翻译与编辑台
6. 审核与发布管理
7. 已发布内容管理

---

## 6. 核心业务流程

### 6.1 主流程

```text
管理员登录
→ 配置新闻来源
→ 系统按计划抓取新闻
→ 系统抽取原文信息并入库
→ 系统自动生成中文翻译初稿
→ 管理员在候选池中挑选内容
→ 管理员进入编辑页修改标题/摘要/正文
→ 管理员手动审核
→ 发布到网页端
→ 文章进入已发布列表
```

### 6.2 文章状态流转

```text
抓取成功
→ 待翻译
→ 待编辑
→ 待审核
→ 已发布
```

补充状态：

- 抓取失败
- 翻译失败
- 已驳回
- 已撤回
- 已归档

说明：

- 第一阶段不做“初审/终审”双流程，统一由管理员单人完成
- 管理员在编辑完成后，点击“审核通过并发布”即可完成最终上线

## 7. 功能需求详述

# 7.1 管理员登录

## 功能目标

管理员可以安全登录后台，并维持登录态。

## 功能点

1. 登录页
2. 用户名/邮箱 + 密码登录
3. 登录失败提示
4. 登录态持久化
5. 退出登录
6. 修改密码

## 规则

- 初始管理员账号由系统配置生成
- 密码需要加密存储
- 未登录用户访问后台页面时自动跳转登录页

## 页面字段

登录页字段：
- 用户名或邮箱
- 密码
- 登录按钮
- 错误提示区域

## 验收标准

- 正确账号密码可进入后台首页
- 错误密码给出提示，不泄露具体信息
- 退出后需重新登录

---

# 7.2 工作台首页
## 功能目标

后台首页用于帮助管理员快速掌握今天的内容处理情况。

## 展示内容

1. 今日抓取成功数
2. 抓取失败数
3. 待编辑文章数
4. 待审核文章数
5. 已发布文章数
6. 最近抓取来源状态
7. 最近发布文章列表
8. 快捷操作入口

## 快捷操作

- 新建来源
- 立即抓取一次
- 查看候选新闻池
- 查看待发布文章
- 查看已发布文章

## 验收标准

- 登录后默认进入工作台首页
- 关键统计数据能实时展示
- 快捷入口可正常跳转

---

# 7.3 新闻来源管理

## 功能目标

管理员可以维护新闻抓取来源。

## 来源字段

每个来源必须包含以下字段：

- 来源名称
- 来源网站主页 URL
- 来源抓取入口 URL（可与主页相同）
- 来源类型（RSS / 列表页 HTML / 文章页模板）
- 来源语言（日文 / 英文 / 中文）
- 是否启用
- 抓取频率（分钟）
- 来源备注

可选字段：

- 来源 logo
- 来源优先级
- 默认栏目标签

## 操作

- 新增来源
- 编辑来源
- 启用/停用来源
- 删除来源
- 立即测试抓取
- 查看最后抓取时间
- 查看最后抓取状态

## 规则

- 停用来源后不再参与定时抓取
- 删除来源仅允许删除没有关联记录的来源，或改为软删除
- 建议采用软删除，避免数据孤儿

## 列表页字段

- 来源名称
- 来源语言
- 抓取入口 URL
- 启用状态
- 抓取频率
- 最后抓取时间
- 最后抓取状态
- 操作按钮

## 验收标准

- 管理员可以完整新增一个来源
- 能手动测试抓取
- 来源启用后能进入定时任务

---

# 7.4 抓取任务与候选新闻池

## 功能目标

系统自动从来源抓取新闻，并将抽取后的内容存入候选新闻池。

## 抓取内容字段

每篇抓取到的原始新闻至少包含：

- 来源 ID
- 原文标题
- 原文正文（纯文本）
- 原文 HTML（可选但建议保存）
- 原文 URL
- 来源站点名
- 发布时间（如果可识别）
- 作者（如果可识别）
- 原始图片 URL（可选）
- 抓取时间
- 抓取状态

## 抓取方式（第一阶段建议）

优先支持两种方式：

1. RSS 抓取
2. HTML 列表页 + 文章页正文抽取

第一阶段不要求复杂反爬，不要求代理池，不要求高级解析策略。

## 候选新闻池功能

管理员可查看所有抓取到的新闻候选。

列表需支持：

- 按来源筛选
- 按抓取状态筛选
- 按文章状态筛选
- 按日期筛选
- 关键词搜索
- 查看详情
- 手动触发重新翻译
- 标记为忽略
- 进入编辑

## 候选新闻池列表字段

- 原文标题
- 来源名称
- 发布时间
- 抓取时间
- 当前状态
- 是否已翻译
- 是否已发布
- 操作按钮

## 详情页需展示

- 原文标题
- 原文链接
- 来源
- 发布时间
- 原文正文
- 原始图片
- 自动翻译结果
- 当前状态
- 创建时间/更新时间

## 去重要求（第一阶段简化版）

做最基础去重即可：

- 相同原文 URL 不重复入库
- 相同来源 + 相同标题视为重复，默认不重复创建

## 验收标准

- 系统可按计划自动抓取启用来源
- 抓取后的文章出现在候选池中
- 重复 URL 不重复生成候选内容

---

# 7.5 自动翻译

## 功能目标

系统对抓取到的原文自动生成中文翻译初稿，供管理员后续编辑。

## 输入

- 原文标题
- 原文正文
- 来源语言

## 输出

- 中文标题初稿
- 中文正文初稿

## 规则

- 翻译任务可在抓取后自动触发
- 若翻译失败，文章状态标记为“翻译失败”
- 管理员可手动重新触发翻译

## UI 展示

在候选详情页/编辑页中需双栏展示：

左侧：原文
右侧：中文翻译

## 术语要求（第一阶段简化版）

第一阶段不做完整术语库系统，但要支持一个最小化“术语映射配置”：

例如：
- グランアレグリア → 放声欢呼
- イクイノックス → 春秋分
- キタサンブラック → 北部玄驹

实现建议：

- 提供一个 JSON 配置文件或后台简单配置项
- 翻译后进行术语替换

## 验收标准

- 抓取成功后可自动获得中文翻译初稿
- 管理员可重新触发翻译
- 页面可同时查看原文与译文

---

# 7.6 编辑台

## 功能目标

管理员对候选新闻进行人工修订和发布前整理。

## 编辑内容字段

管理员可编辑以下字段：

- 中文标题
- 中文摘要
- 中文正文
- 封面图
- 标签
- 来源说明
- 原文链接
- 发布状态

## 页面布局建议

编辑页分三栏或上下结构：

### 方案 A（推荐）

- 左侧：原文标题 + 原文正文
- 中间：自动翻译结果
- 右侧：可编辑发布内容

如果实现复杂，可改为上下布局：

- 上部原文
- 中部翻译稿
- 下部发布稿编辑器

## 编辑功能

- 修改标题
- 修改摘要
- 修改正文
- 插入/替换封面图
- 手动添加标签
- 自动保存草稿
- 手动保存草稿
- 预览发布效果
- 驳回
- 审核通过并发布

## 正文字段最低要求

编辑器第一阶段建议支持：

- 段落
- 换行
- 加粗
- 引用
- 插图
- 超链接

第一阶段可使用 Markdown 编辑器或简单富文本编辑器。

## 标签建议

第一阶段标签手动输入即可，不做复杂实体系统。

建议支持以下常见标签：

- 赛事
- 马匹
- 骑手
- 调教师
- 海外远征
- 伤病
- 退役
- 配种
- 赛前情报
- 赛后复盘

## 验收标准

- 管理员可在编辑台修改并保存文章
- 可查看原文和翻译稿
- 可进入预览页查看最终展示效果

# 7.7 审核与发布
## 功能目标

管理员确认内容无误后，将文章发布到网页端。

## 状态定义
- 待编辑
- 待审核
- 已发布
- 已驳回
- 已撤回

## 操作

- 保存为草稿
- 提交审核（实质上是切换到待审核）
- 驳回
- 审核通过并发布
- 立即发布
- 撤回已发布文章

## 发布字段

发布时需保存：

- 发布标题
- 发布摘要
- 发布正文
- 封面图
- 标签
- 发布时间
- 发布人（固定为管理员）
- 原文来源说明
- 原文链接

## 发布规则

- 已发布文章在网页前台可见
- 撤回文章后在前台不可见
- 已发布文章允许后续再次编辑并更新

## 验收标准

- 管理员可将文章从待审核改为已发布
- 发布后网页端可看到该文章
- 撤回后网页端不再显示

## 12. 默认技术实现建议

以下是给 Codex 的默认技术建议，如未特别说明，按此实现：

### 12.1 技术栈

- 前后端框架：**Next.js 14+（App Router）**
- 语言：**TypeScript**
- 数据库：**PostgreSQL**

## 附录 A：第一阶段补充规范（根据后续讨论更新）

本附录用于补充第一阶段 PRD 中关于图片工作流与编辑器交互的要求。如与正文中较早版本的描述冲突，以本附录为准。

### A.1 图片资源本地化与简化媒体库

#### 目标
为解决外链图片防盗链、失效、加载不稳定等问题，第一阶段应支持对允许使用的原图进行本地化存储，并在编辑器中高效使用。

#### 第一阶段必须支持的能力
1. 从原文中识别候选图片
2. 管理员手动触发“本地化并插入”
3. 后端下载图片并上传到本地存储或对象存储（OSS/S3）
4. 返回站内可访问的 `internal_url`
5. 在编辑器中将图片插入正文
6. 在编辑器中支持一键“设为封面”
7. 支持管理员手动上传替换封面图
8. 记录图片原始来源 URL

#### 范围限制
- 第一阶段**不支持自动去水印**
- 第一阶段**不支持手动框选去除来源标识**
- 仅支持正常比例裁切，用于正文或封面展示（如 4:3、16:9、原图）
- 图片本地化失败时，不应阻塞文章编辑与发布

#### 建议流程
```text
管理员在编辑页点击“本地化并插入”
→ 后端下载原图
→ 上传至本地目录或 OSS/S3
→ 返回 internal_url
→ 弹出图片处理小窗
→ 管理员可选择比例裁切（4:3 / 16:9 / 原图）
→ 完成后插入正文或设置为封面
```

#### 建议接口
- `POST /api/media/localize`：传入原图 URL，返回本地化后的图片信息
- `POST /api/media/upload`：管理员手动上传图片
- `PUT /api/media/:id/crop`：保存裁切参数
- `POST /api/media/:id/set-cover`：设为封面

#### 建议数据结构
建议新增 `media_assets` 表，字段至少包含：
- id
- raw_article_id
- original_image_url
- internal_image_url
- storage_provider
- status
- is_cover
- created_at
- updated_at

同时建议在文章表中增加：
- `cover_media_asset_id`

### A.2 三栏式超级编辑器（第一阶段优先方案）

第一阶段编辑页优先采用三栏布局，以提高“原文对照 + 编辑 + 辅助信息”效率。

#### 布局说明
- 左栏：来源参照区
- 中栏：中文编辑区
- 右栏：辅助工具区

#### 左栏（来源参照区）
展示内容：
- 原文标题
- 来源名称
- 发布时间
- 原文链接
- 原文正文
- 原文图片列表
- 每张图片的“本地化并插入”按钮

#### 中栏（中文编辑区）
展示与编辑内容：
- 中文标题输入框
- 中文摘要输入框
- 正文编辑器
- 封面图预览
- 预览按钮
- 保存草稿按钮
- 审核并发布按钮

#### 右栏（辅助工具区）
第一阶段至少展示：
- AI 翻译参考入口或完整译文区域
- 建议标签（可为空）
- 已识别实体（可先静态展示）
- 术语纠偏按钮（重新应用术语映射）

#### 降级策略
如果三栏布局在第一阶段实现复杂度过高，可退化为“双栏布局（原文 + 编辑）”，但必须保留：
- 原文可见
- 翻译参考可见
- 图片本地化入口可见
- 正文编辑器可见

### A.3 UI 视觉规范

为保持后台的统一视觉，第一阶段建议采用以下风格：
- 主色调：Deep Turf Green `#1A3A32`
- 动作色：Winner Gold `#C5A059`
- 背景色：Slate Gray `#F8FAFC`
- 字体优先：Inter、PingFang SC

说明：第一阶段不要求像素级还原设计稿，但应尽量遵守上述色彩与层级关系。

### A.4 交互补充要求

1. 打开编辑页时，术语映射应已应用到翻译稿中，例如：
   - グランアレグリア → 放声欢呼
   - イクイノックス → 春秋分
2. 标题为空时禁止发布
3. 封面图为空时，发布前必须提示管理员确认
4. 刷新页面后不应丢失登录态
5. 在 iPad Pro 尺寸下应能顺滑编辑，不得出现核心按钮不可点击、编辑器无法输入、布局严重溢出等问题
6. 点击图片后的浮动工具栏建议包含：裁剪、替换、设为封面
7. 左栏原文和中栏编辑区的滚动同步为增强项，第一阶段可选实现

### A.5 候选新闻池交互补充

候选新闻池第一阶段建议采用卡片化列表或高信息密度表格，至少展示：
- 来源图标/来源名称
- 原文标题
- 抓取时间
- 翻译状态
- 当前状态
- 操作按钮（忽略 / 编辑）

增强项：
- 鼠标悬停标题时，显示原文前 200 字快速预览
- 抓取失败项悬停显示错误信息

### A.6 给 Codex 的补充约束

1. 图片本地化功能属于第一阶段正式范围
2. 去水印不属于产品范围，不得实现“自动去水印”或“手动框选去水印”
3. 术语映射替换必须发生在编辑页渲染前，而不是仅在保存或发布时替换
4. 编辑页要优先保证可用性，而不是追求复杂动画或过度视觉效果
5. 如三栏编辑器实现成本过高，可先实现稳定的双栏版本，再预留右栏扩展位
