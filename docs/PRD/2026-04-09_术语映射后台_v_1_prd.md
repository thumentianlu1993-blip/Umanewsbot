# 术语映射后台 V1 PRD

## 1. 文档目的

本文档用于指导 Codex 实现“术语映射关系配置后台”的独立可用版本，用于替代当前难以使用的 Django Admin 页面。

目标是提供一个**简单、稳定、适合单管理员高频使用**的术语管理界面，支持：

- 单条新增/编辑
- 批量导入
- 快速搜索与筛选
- 启用/停用
- 别名维护
- 优先级调整
- 基础校验

本期只做术语后台本身，不重构翻译主链路。

---

## 2. 背景与问题

当前系统已有术语映射能力，术语数据通过 Django Admin 维护。

存在的问题：

1. 页面可用性差，不适合高频编辑
2. 列表信息密度低，查找效率差
3. 不方便做批量导入
4. 别名、优先级、启停状态维护体验差
5. 缺少面向实际翻译场景的字段组织方式
6. 不适合后续持续扩充赛马专名库

该后台需要成为管理员日常使用的“术语工作台”，而不是数据库表的可视化入口。

## 3. 目标

### 3.1 核心目标
构建一个面向单管理员的、简单易用的术语映射后台。

### 3.2 本期必须实现的目标
1. 用独立页面替代 Django Admin 维护术语
2. 支持术语列表查看、搜索、筛选
3. 支持单条新增/编辑术语
4. 支持批量导入术语
5. 支持启用/停用术语
6. 支持维护日文原词、中文译词、别名、类型、优先级、备注

## 7. 数据模型设计

本期继续沿用现有 `TermEntry` 主模型，如当前字段不足，可做最小增强。

### 7.1 主字段
建议保留或确认以下字段：

- `id`
- `term_type`：术语类型
- `source_ja`：标准日文原词
- `target_zh`：标准中文译词
- `aliases_ja`：日文别名列表
- `aliases_zh`：中文别名列表
- `notes`：备注
- `is_active`：是否启用
- `priority`：优先级
- `updated_at`
- `created_at`

### 7.2 字段说明

#### `term_type`
建议枚举值：
- `horse`：马名
- `race`：赛事名
- `jockey`：骑手名
- `trainer`：调教师名
- `owner`：马主名
- `farm`：牧场名
- `racecourse`：赛场名
- `org`：机构名
- `fixed_phrase`：固定术语
- `other`：其他

#### `aliases_ja`
用于存储该术语的日文别名，可为 JSON 数组或单独关联表。

建议第一期为简化实现，允许使用 JSON 数组，例如：
```json
["イクイノ", "Equinox"]
```

#### `aliases_zh`
用于存储中文别称或其他常见翻译。

#### `priority`
用于冲突时排序，数字越大优先级越高。

## 8. 核心功能设计

# 8.1 术语列表页

## 目标
让管理员能快速找到、筛选和管理术语。

## 列表页必须具备的能力
1. 查看术语列表
2. 关键词搜索
3. 按术语类型筛选
4. 按启用状态筛选
5. 按更新时间排序
6. 快速启用/停用
7. 进入编辑页
8. 新建术语入口
9. 批量导入入口

## 列表展示字段
每行至少展示：
- 日文原词
- 中文译词
- 类型
- 日文别名数量
- 中文别名数量
- 优先级
- 状态（启用/停用）
- 最近更新时间
- 操作按钮

## 搜索要求
支持对以下字段搜索：
- `source_ja`
- `target_zh`
- `aliases_ja`
- `aliases_zh`
- `notes`

## 筛选要求
支持：
- 按类型筛选
- 按启用状态筛选
- 按是否有别名筛选（可选增强）

## 操作按钮
每行建议包含：
- 编辑
- 启用/停用
- 复制一条

## 批量操作（第一期可选但建议做）
- 批量启用
- 批量停用

## 验收标准
- 管理员可在列表页快速检索术语
- 启用/停用操作无需进入详情页
- 列表页支持分页

---

# 8.2 单条新建 / 编辑页

## 目标
让管理员高效维护单个术语。

## 页面字段
必须包含：
- 术语类型
- 日文原词
- 中文译词
- 日文别名
- 中文别名
- 优先级
- 是否启用
- 备注

## 输入形式建议

### 日文原词
单行输入框

### 中文译词
单行输入框

### 日文别名
建议使用“多值输入”组件：
- 回车新增一个别名
- 支持删除单个别名
- 支持粘贴多行自动拆分

### 中文别名
同上

### 优先级
数字输入框

### 是否启用
开关组件

### 备注
多行文本框

## 编辑体验要求
1. 新建和编辑使用同一套表单
2. 保存后给出成功提示
3. 支持“保存并继续编辑”
4. 支持“保存并新建下一条”
5. 编辑页返回列表时，保留列表页筛选条件（如实现成本可接受）

## 校验规则
1. `source_ja` 不能为空
2. `target_zh` 不能为空
3. `term_type` 不能为空
4. 同一 `term_type + source_ja` 不允许重复创建
5. 若重复，给出明确提示，并引导进入已有术语编辑页

## 验收标准
- 管理员可创建新术语
- 管理员可编辑现有术语
- 别名输入体验优于 Django Admin 原始输入框

---

# 8.3 批量导入页

## 目标
让管理员快速导入一批术语，避免逐条手录。

## 导入方式
本期至少支持以下两种方式之一：

### 方案 A（推荐）
CSV / Excel 文件上传

### 方案 B
多行文本粘贴导入

建议两者都支持；如果时间有限，优先做 CSV 上传。

## 支持字段
批量导入最少支持：
- `term_type`
- `source_ja`
- `target_zh`
- `aliases_ja`
- `aliases_zh`
- `priority`
- `is_active`
- `notes`

## 格式建议
### CSV 表头示例
```csv
term_type,source_ja,target_zh,aliases_ja,aliases_zh,priority,is_active,notes
horse,グランアレグリア,放声欢呼,"Gran Alegria|グラン","放声欢呼|大欢声",100,true,
```

说明：
- 多个别名可用 `|` 分隔
- 导入前页面应展示模板下载入口

## 导入流程
```text
管理员上传 CSV
→ 系统预解析
→ 返回预览结果
→ 显示新增/更新/错误数量
→ 管理员确认导入
→ 系统写入数据库
→ 显示导入结果
```

## 导入策略
必须支持两种模式：
1. **新增模式**：已有重复项时报错
2. **覆盖更新模式**：已有重复项时更新已有数据

建议默认使用：
- 新增模式

## 错误处理
导入预览时应能识别：
- 必填字段缺失
- 类型不合法
- 优先级不是数字
- 重复项
- 布尔值格式错误

## 导入结果反馈页
导入完成后至少展示：
- 总条数
- 成功条数
- 失败条数
- 跳过条数
- 错误详情（按行展示）

## 验收标准
- 管理员可以上传模板格式正确的 CSV 批量导入术语
- 系统能在导入前给出预览与校验
- 系统能明确告知失败原因

---

# 8.4 快速操作体验优化

## 目标
减少管理员日常维护成本。

## 建议功能
1. 从列表页快速复制一条术语作为新建模板
2. 列表页快速启用/停用
3. 编辑页支持“保存并继续新增”
4. 搜索框支持回车搜索
5. 列表页默认按 `updated_at desc` 排序

这些能力虽然小，但对单管理员高频维护非常重要。

---

# 8.5 后端能力要求

## 核心接口
建议至少提供以下接口：

### 列表查询
- `GET /api/terms`
  - 支持分页
  - 支持关键词搜索
  - 支持类型筛选
  - 支持状态筛选

### 详情查询
- `GET /api/terms/:id`

### 新建术语
- `POST /api/terms`

### 更新术语
- `PUT /api/terms/:id`

### 启用/停用
- `POST /api/terms/:id/toggle-active`

### 批量导入预检
- `POST /api/terms/import/preview`

### 批量导入确认
- `POST /api/terms/import/commit`

## 后端校验要求
1. 校验 `term_type + source_ja` 唯一性
2. 校验必填字段
3. 校验枚举值合法性
4. 校验优先级为整数
5. 别名字段写入前需标准化为数组

## 9. UI 与交互规范

### 9.1 整体风格
沿用现有后台系统风格，不单独设计新视觉系统。

建议遵守：
- 与现有后台页面统一
- 简洁、信息密度适中
- 重点突出输入效率与查找效率

### 9.2 列表页布局建议
采用“上方筛选 + 下方表格”的经典管理页布局。

#### 顶部区域
- 页面标题：术语映射
- 搜索框
- 类型筛选
- 状态筛选
- 新建按钮
- 批量导入按钮

#### 表格区域
每行展示关键字段，操作按钮保持简洁。

### 9.3 编辑页布局建议
采用单页表单布局，信息从上到下依次为：
- 基本信息
- 别名信息
- 状态与优先级
- 备注
- 底部操作按钮

### 9.4 交互要求
1. 保存成功后提示 Toast
2. 校验失败时，错误提示贴近具体字段
3. 导入预检失败时，不允许直接提交
4. 列表切换筛选条件时即时刷新
5. 别名输入必须比纯文本输入框更易用

## 11. 技术实现建议

### 11.1 基本原则
1. 不重构现有后台框架
2. 不依赖 Django Admin 作为主操作界面
3. 使用现有项目技术栈与布局体系实现
4. 保证实现简单、可维护

### 11.2 前端实现建议
如果当前后台已是 Django 模板 + 适量 JS：
- 继续沿用
- 对别名输入组件可使用轻量 JS 组件或手写标签输入交互

如果当前后台已有独立前端页面体系：
- 在现有体系中新增术语模块页面

### 11.3 批量导入实现建议
优先支持 CSV。
解析逻辑应放在后端，不放在前端。

## 13. 给 Codex 的执行说明

1. 本期目标是替代 Django Admin 的术语维护页面，不要扩展到翻译主链路重构。
2. 优先保证“简单易用”，不要过度设计复杂交互。
3. 批量导入必须可用，因为这是本期核心价值之一。
4. 单条编辑与批量导入都要覆盖。
5. 术语页面应成为管理员日常维护术语的主要入口。

---

## 14. 一句话总结

本期要做的不是“术语表管理功能”，而是一个真正能让单管理员高效维护赛马术语映射的**小型术语工作台**：

**能查、能改、能批量导、能快速维护。**
