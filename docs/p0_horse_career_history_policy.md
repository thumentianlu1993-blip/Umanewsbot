# P0 马完整生涯履历策略

## 文档状态

- 决策日期：2026-07-16
- 状态：用户已确认，交由“继续P0马信息补全专项”落实能力修复
- 当前执行边界：先修数据模型、完整性口径、展示和测试，不立即批量抓取或写入历史履历
- 关联文档：`docs/historical_race_data_coverage_policy.md`

本文只规定 P0 马匹的完整生涯履历。它与“哪些赛事需要进入正式赛事总账并建设赛事详情页”是两个独立维度。

## 核心结论

P0 马的生涯履历必须按马匹本身抓取，不能从正式赛事总账或已收录重点赛事反推。

- P0 马实际参加过的新马赛、未胜利赛、普通条件赛、让磅赛、表列赛、G2/G3 和 G1 都应出现在马匹生涯履历中。
- 一场比赛是否进入 `RaceEvent` 正式赛事产品层，不决定它是否进入 `HorseRaceRecord`。
- 正式赛事总账中已有该场比赛时，履历记录应关联 `RaceEvent` / `RaceEventResult`。
- 普通比赛没有独立赛事详情页时，仍应保留一条不关联 `RaceEvent` 的 `HorseRaceRecord`，展示比赛快照字段和来源。
- 英国、法国、美国历史 G2/G3 即使按赛事覆盖策略属于非阻塞缺口，也不能因此从 P0 马完整生涯中消失。
- P0 马的完整生涯可以只保存该马自己的逐场事实，不要求为每场普通比赛同步抓取全体参赛马和完整赛果。

因此，产品允许以下状态同时成立：

1. 某场普通比赛没有公开赛事详情页。
2. 该场比赛仍出现在所有相关 P0 马的完整生涯履历中。

## 数据分层

### `RaceEvent*`

`RaceEvent`、`RaceEventRunner` 和 `RaceEventResult` 是赛事产品层，服务赛事日历、赛事详情、完整出马表和全场赛果。

### `HorseRaceRecord`

`HorseRaceRecord` 是马匹参赛事实层，负责表达一匹马实际参加过的每一场比赛，包括未获胜、未上名、未完赛、取消资格等结果。

当前模型已经允许 `event` 和 `result` 为空，因此能够承载未进入正式赛事总账的普通比赛。后续实现不得为了生成马匹履历而强行创建低质量或无法确认身份的 `RaceEvent`。

### 关联原则

- 有确定 `RaceEvent` 身份：建立关联，不重复创建另一条普通履历。
- 没有 `RaceEvent`：保存独立 `HorseRaceRecord`。
- 后续正式总账补到该场比赛：在身份确认后回填关联，并保持原始来源证据。
- 仅名称相似但日期、场地或赛事身份不充分：保留未关联记录并进入审核，不自动合并。

## 地区来源矩阵

### 日本

1. JBIS 马匹 `record/` 页作为完整生涯主来源，可提供生涯出赛总数及逐场日期、场地、比赛、名次、跑道、距离、马号、骑师、负磅、时间和奖金等字段。
2. netkeiba 马匹战绩作为补充来源和现有导入链路。
3. JRA/NAR 官方单场赛果用于争议字段、异常结果和比赛身份核验。
4. 海外远征记录须使用举办地区来源补充，并与日本来源中的海外记录去重。

参考入口：

- <https://www.jbis.or.jp/horse/0001311583/record/>

### 中国香港

1. HKJC Horse Information 和马匹往绩作为香港本地生涯主来源。
2. 退役马资料页不完整时，按马匹烙号、名称和 HKJC 历史赛果页重建本地逐场履历。
3. 来港前及海外远征记录使用原举办地区来源补充。

参考入口：

- <https://racing.hkjc.com/en-us/local/information/selecthorse>
- <https://common.hkjc.com/utility/faq/english/racing/horse-info>

### 英国

1. Sporting Life 马匹 `Full Form` 作为低成本批量提取主来源。
2. Racing Post Horse Profile 作为历史补充和交叉验证来源。
3. BHA、官方单场结果或赛马场资料用于纪律结果、改判和身份争议核验。
4. 只抽取客观比赛事实，不复制专有评级、评论、预测或版权内容。

参考入口：

- <https://www.sportinglife.com/racing/profiles/horse/1154799>
- <https://help.racingpost.com/hc/en-us/articles/207998329-Horse-Profiles>

### 法国

1. Geny 马匹 `Carriere` 页面作为实际批量提取主来源，可提供生涯出赛总数和逐场履历。
2. France Galop 马匹资料、官方结果公报用于权威校验。
3. Racing Post、PMU 和 Canalturf 用于缺页、旧记录和跨境记录补充。
4. 平地与障碍记录不得因比赛类型不同而遗漏。

参考入口：

- <https://www.geny.com/fr/cheval/2879346-maine/course/1656862>
- <https://www.france-galop.com/fr>

### 美国

1. Equibase Horse Profile 的 `Results` 作为美国和加拿大逐场履历主来源，生涯统计总数作为完整性校验值。
2. Horse Racing Nation 作为可访问性补充来源。
3. 赛马场官网、America's Best Racing 等用于缺页和争议场次核验。
4. Maiden、Allowance、Claiming 与 Stakes 均属于 P0 马生涯事实，不能只保留分级赛。

参考入口：

- <https://www.equibase.com/profiles/Results.cfm?rbt=TB&refno=1452255&registry=T&type=Horse>

## 最低逐场字段

每条已确认实际出赛记录至少应保存：

- 马匹稳定身份 `horse_profile_id`。
- 比赛日期；来源只给年份时必须标记日期精度，不能虚构月日。
- 原始比赛名和规范化展示名。
- 场地、地区和可用的场次号或来源赛事 ID。
- 距离原文及可规范化的距离值；必须保留原始单位，不能把英里、化朗和米混为同一数值。
- 跑道或赛事类型，例如草地、泥地、全天候、跨栏和障碍追逐。
- 最终名次或正式异常状态。
- 骑师、马号、闸位、负磅、完成时间和奖金等来源可得字段。
- `source_name`、`source_url`、外部马匹 ID、外部赛事 ID、抓取时间及原始证据引用。

当前模型没有独立列的扩展字段可以先保存在 `source_refs` / `raw_payload`，但公开需要稳定查询、排序或审核的字段应在专项设计中评估是否结构化。

## 结果状态语义

不得把所有非数字名次折叠成 `unknown`。完整履历至少要区分：

- `won`
- `placed`
- `finished`
- `did_not_finish`
- `disqualified`
- `scratched`
- `withdrawn`
- `unknown`

`scratched` / `withdrawn` 表示报名或出马后未实际参赛，不得计入生涯实际出赛总数。来源只提供报名记录而无法确认是否出赛时，保持待确认。

## 身份匹配与去重

履历去重不能只使用比赛名称。优先使用：

1. 同来源外部马匹 ID 和外部赛事 ID。
2. 马匹稳定身份、实际日期、场地、场次号。
3. 马匹稳定身份、实际日期、场地、距离、比赛名规范化结果。

跨来源马匹身份不能仅凭同名合并。至少结合出生年份、性别、父母、地区、练马师或其他稳定特征；证据不足时保留冲突候选。

海外远征经常同时出现在母国马匹页和举办地区来源中。合并后应保留多个来源引用，但只能生成一条参赛事实。

## 完整性验收

P0 马生涯完整度必须与血统完整度、资料字段完整度分开记录，不能继续使用当前仅表示二代血统状态的 `HorseProfileCompleteness` 代替。

一匹 P0 马只有满足以下条件，才能标记为“生涯履历完整”：

1. 已确认可靠来源所列的生涯实际出赛总数。
2. 系统有效实际出赛记录数与来源总数一致。
3. 从首次出赛到最后一次出赛没有无法解释的时间或赛季缺口。
4. 每条记录都有日期、比赛、场地、结果状态和来源证据；历史资料确实缺字段时有显式缺口状态。
5. 海外远征已按举办地区来源核对。
6. 退赛、取消、改判、取消资格和未完赛没有被错误计数或丢失。
7. 重复来源记录已经合并，且来源引用仍可追溯。

建议独立记录以下指标：

- `official_or_source_start_count`
- `collected_start_count`
- `linked_race_event_count`
- `unlinked_race_record_count`
- `overseas_start_count`
- `gap_count`
- `career_history_status`
- `last_verified_at`

不能用“已抓到若干重点胜利”“已经关联若干赛事”或“马匹基础资料完整”代替完整生涯验收。

## 前台展示要求

- 马匹详情页应能浏览全部生涯履历，默认按日期倒序或提供正序/倒序切换。
- 不得继续用固定截取最近 20 条作为“完整履历”。可使用分页或加载更多控制页面体积。
- 已关联公开 `RaceEvent` 的记录可以进入赛事详情页。
- 未关联赛事仍显示日期、比赛名、场地、距离和结果，但不生成无效链接。
- 页面应区分实际出赛与退赛/取消出赛。
- 主胜鞍应从完整履历派生，而不是反过来作为履历来源。

## 本阶段需要修复的能力

“继续P0马信息补全专项”应在不启动历史履历批量抓取的前提下完成或重新核对：

1. 将生涯履历完整度从血统完整度中拆分，定义状态、计数和缺口原因。
2. 确保 `HorseRaceRecord` 能保存未关联 `RaceEvent` 的普通比赛，并能在后续确认赛事身份后安全关联。
3. 修正前台固定最多展示 20 条的问题，支持完整履历分页或等价交互。
4. 处理实际出赛、退赛、取消、未完赛和取消资格的计数语义。
5. 定义跨来源、跨地区和海外远征的身份匹配、去重与来源保留规则。
6. 为普通比赛无赛事详情、后续回填关联、同名马、重复来源、跨单位距离和异常结果补齐测试。
7. dry-run artifact 必须报告来源生涯总数、采集数、去重数、缺口数和逐马完整状态。
8. 保持公开数据只读本地数据库；不得在用户访问马匹页时实时请求第三方。

## 当前明确不做

- 不在本阶段批量访问 JBIS、HKJC、Sporting Life、Racing Post、Geny、France Galop、Equibase 或 Horse Racing Nation。
- 不在本阶段向生产库批量写入历史 `HorseRaceRecord`。
- 不因为要展示一条普通履历而批量创建普通比赛的 `RaceEvent` 详情页。
- 不改变 `docs/historical_race_data_coverage_policy.md` 已确认的赛事 G1/G2/G3 覆盖门禁。
- 不把当前文档列出的公开来源视为已取得商业数据许可；实际自动化前仍需核对访问条款、限速和公开展示边界。

后续真正启动履历抓取时，应先按五地区各抽取少量 P0 马做 dry-run 验收，再分批执行，并继续使用可审核 artifact、来源证据、身份冲突表和显式 commit 门禁。
