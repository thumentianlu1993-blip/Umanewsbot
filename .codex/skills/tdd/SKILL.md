# Umanews 测试先行（repository fallback）

这是项目内的 TDD 兜底 skill，不是 Codex 内置 skill。优先使用当前环境提供的 Codex 原生测试先行能力；没有合适的通用原生 skill 时使用本 skill。

## 不可跳过的入口条件

在任何功能代码开发前，必须已有一份完整的 `test_cases.md`，并由方案审核确认至少覆盖：

- 核心正常路径与验收标准
- 边界值、空值、非法输入和权限边界
- 下游失败、超时、部分成功和恢复路径
- Django 模型约束、查询与迁移行为（若涉及）
- Celery 重复投递、重试、幂等、锁/lease、并发和 worker 崩溃恢复（若涉及）
- 性能边界、批次和回归范围
- 部署/回滚相关兼容行为（若涉及）

`test_cases.md` 不完整时，停止实现并先补足测试设计。不得边写生产代码边追补核心测试范围。

## RED 证据

1. 先把一个明确行为转化为最小、可重复的自动化测试。
2. 在修改对应生产代码前运行它，记录真实失败命令、退出状态和能证明缺失行为的失败摘要。
3. 测试必须因为目标行为尚未实现而失败；导入错误、环境损坏、测试数据错误或无关失败不算 RED。
4. 若现有实现意外通过，说明测试没有证明变化：增强断言、补边界或重新确认方案，不得伪报 RED。
5. 每个测试需在 `test_cases.md` 或返回证据中说明它应捕获的具体 mutation，例如删除幂等判断、移除唯一约束、错误扩大批次或跳过状态转换。

## RED-GREEN-REFACTOR 循环

每次只推进一个可审查行为：

1. `RED`：新增/调整测试并确认目标失败。
2. `GREEN`：做满足该行为的最小实现，运行同一测试确认通过。
3. `REFACTOR`：在测试保持绿色时消除重复、改善命名和边界，不扩大范围。
4. 运行最近相关测试集，确认没有把失败转移到相邻行为。
5. 再进入下一个行为。

不要先完成整批实现再一次性补测试，也不要把“测试文件已存在”当作测试先行证据。

## Django/Celery 隔离规则

- 失败时先运行最小的 test class/test method；确认局部行为后再扩大到 app suite 和全量回归。
- 自动化测试不得访问真实外部网络、生产数据库、生产 Redis、真实队列或第三方服务。
- 使用 mock/fake、受控 fixture、测试数据库和 eager/隔离 worker；同时保留能验证任务边界而不是只验证 mock 调用次数的断言。
- 时间、随机数、重试延迟、锁 owner、task id 和外部响应必须可控。
- 涉及事务、`on_commit`、并发、`select_for_update` 或 lease 时，选择能真实覆盖相应数据库语义的测试层，并明确 SQLite 与 PostgreSQL 的能力差异。
- 网络适配器测试只验证构造、解析、错误映射和重试策略；生产连通性另走受控验证，不属于 TDD 自动化测试。

## 验证层次

按风险逐级扩大，不得用后一层的“可能会通过”替代前一层证据：

1. 最小行为测试
2. 相关 test class/module
3. 相关 Django app 或 Celery 集成测试
4. 项目全量回归
5. 必要时的本地 PostgreSQL/Docker 生产形状验证

本地验证、预发布验证和生产真相必须分别报告。

## 文档和纯配置豁免

只有不改变任何运行时行为的纯文档或纯配置整理可以不制造自动化 RED。豁免必须显式记录：

- 为什么没有可执行行为变化
- 使用了什么静态检查、解析、render、config check 或人工验收
- 哪些风险仍未由自动化测试覆盖

只要配置涉及 feature flag、队列/路由、权限、依赖版本或装载、容器行为、部署顺序、
数据读写/迁移或任何其他运行时行为，就不属于豁免；文件名是“文档”或“配置”不能单独
成为豁免依据。

## Subagent 交付要求

承担实现分支的 subagent 返回结果时必须附上：

- 对应 `test_cases.md` 条目
- RED 命令、退出状态和失败摘要
- GREEN 命令、退出状态和通过摘要
- 相关测试集与 full regression 的命令、结果；未运行时说明原因和剩余风险
- 测试可捕获的 mutation
- 本分支修改文件清单

缺少 RED/GREEN 证据时，父任务不得把该实现视为完成。本 skill 只服务 Codex 原生执行流程，
不得引入另一套规格工作流或人工确认门禁；确认边界统一引用根 `AGENTS.md`。
